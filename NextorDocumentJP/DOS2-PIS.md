## 1. はじめに
本書は、MSX-DOS 2がMSX 2コンピュータ上のトランジェントプログラムに提供する環境について説明します。MSX-DOS 2用に新しいプログラムを作成する際、あるいは既存のCP/MやMSX-DOS 1のプログラムを、MSX-DOS 2の高度な機能に対応するように移植・修正する際のガイドとして利用されることを想定しています。

MSX-DOS 2は、標準的なCP/MやMSX-DOS 1の環境に対して多くの拡張を行っていますが、既存プログラムとの高い互換性も維持しています。主な特徴は以下の通りです。

* MS-DOSスタイルのツリー構造ディレクトリ
* ファイルハンドル
* 環境文字列（環境変数）
* 適切なエラーハンドリング

多数の拡張DOSコールが追加されており、これらはアドレス `5`（CP/Mにおける「BDOS」呼び出し位置）のDOSエントリージャンプを経由してアクセスされます。個々のファンクション（機能）の詳細な説明については、『MSX-DOS 2 ファンクション仕様書』を参照してください。

なお、本書では「MSX-DOS」という用語を、特に指定がない限り、原則として「MSX-DOS 2」を指すものとして使用します。

## 2. トランジェントプログラム環境
本章では、MSX-DOS下でトランジェントプログラムが実行される環境（プログラムの起動、終了、メモリの使用状況など）について説明します。

### 2.1 MSX-DOSからの起動（エントリー）
トランジェントプログラムは、TPA（Transient Program Area：トランジェントプログラム領域）の開始アドレスである `0100h` にロードされ、MSX-DOSによって `CALL` されます。このとき、スタックポインタ（SP）は TPA の末尾に設定されています。この位置をそのままスタックとして利用すれば、TPAのRAMを最大限に活用できます。もしこれが望ましくない場合は、トランジェントプログラム自身が TPA 内に独自のスタックを設定する必要があります。

トランジェントプログラムが起動された時点でのZ-80レジスタの値は不定です。アドレス `0` から始まる最初の 256バイトのRAM（ゼロページ）には、セクション2.3で説明する各種パラメータやコードが設定されています。

トランジェントプログラム起動時は割込みが許可（DI状態ではなくEI状態）されています。通常は許可したままにしてください。MSX-DOSのファンクションコールは、プログラム側で割込みを禁止していても、原則として処理中に割込みを再許可します。

### 2.2 MSX-DOSへの復帰（リターン）
トランジェントプログラムは、以下の4つの方法のいずれかで終了することができます。

1. 起動時のスタックポインタを維持した状態で `RET` する。
2. アドレス `0000h` へジャンプ（`JP 0000h`）する。
3. MSX-DOSの「プログラム終了（Program Terminate）」ファンクションを呼び出す。
4. MSX-DOSの「エラーコード付き終了（Terminate with Error Code）」ファンクションを呼び出す。

最初の2つの方法は、MSX-DOS側から見れば同一であり、CP/MおよびMSX-DOS 1と互換性があります。3番目の方法もCP/MおよびMSX-DOS 1と互換性があり、これは「エラーコード付き終了」をエラーコード `0` で呼び出すのと同等です。

新設された「エラーコード付き終了」ファンクションを使用すると、プログラムからMSX-DOSへエラーコードを返すことができます。なお、前述の3つの終了方法では、常にエラーコード `0`（エラーなし）が返されます。新規に作成するプログラムや、移植されたCP/Mプログラムでは、エラーコードが `0` であっても、この新しい「エラーコード付き終了」ファンクションを使用することが推奨されます。

プログラムの制御外で発生する様々なイベントによっても、プログラムが終了することがあります。例えば、キーボードから「Ctrl-C」や「CTRL-STOP」が入力された場合や、ユーザーがディスクのエラーメッセージ「Abort/Retry/Ignore?」に対して「Abort（中止）」を選択した場合、あるいは標準I/Oチャンネルでエラーが発生した場合などです。これらのケースでは、適切なエラーコードがMSX-DOSに返されます。

トランジェントプログラムは「アボートルーチン（強制終了処理ルーチン）」を定義することができます。「プログラム終了」や「エラーコード付き終了」ファンクションによる終了時、または上記のようなアボートエラーによる異常終了が発生した際、このルーチンが呼び出されて適切な後処理を行います。このアボートルーチンの定義方法や用途については、『MSX-DOS ファンクション仕様書』に記載されています。

### 2.3 ゼロページの使われ方
起動時、トランジェントプログラムのために、RAMの最初の 256バイト（ゼロページ）に様々なパラメータ領域が設定されます。この領域のレイアウトは以下の通りで、MSXのスロット切り替え呼び出しに使用される領域を除き、MSX-DOS 1およびCP/Mと互換性があります。

```text
        +-------+-----+------+------+------+------+------+------+
  0000h |    Reboot entry    |  Reserved   |   MSX-DOS entry    |
        +------+------+------+------+------+------+------+------+
  0008h |  RST 08h not used  |  RDSLT routine entry point       |
        +------+------+------+------+------+------+------+------+
  0010h |  RST 10h not used  |  WRSLT routine entry point       |
        +------+------+------+------+------+------+------+------+
  0018h |  RST 18h not used  |  CALSLT routine entry point      |
        +------+------+------+------+------+------+------+------+
  0020h |  RST 20h not use   |  ENASLT routine entry point      |
        +------+------+------+------+------+------+------+------+
  0028h |  RST 28h not used  |             not used             |
        +------+------+------+------+------+------+------+------+
  0030h | CALLF routine entry point |      not used             |
        +------+------+------+------+------+------+------+------+
  0038h |  Interrupt vector  |                                  |
        +------+------+------+                                  +
  0040h |                                                       |
        +                                                       +
  0048h |        Used by secondary slot switching code          |
        +                                                       +
  0050h |                                                       |
        +                           +------+------+------+------+
  0058h |                           |                           |
        +------+------+------+------+                           +
  0060h |        Unopened CP/M FCB for first parameter          |
        +                           +------+------+------+------+
  0068h |                           |                           |
        +------+------+------+------+                           +
  0070h |        Unopened CP/M FCB for second parameter         |
        +                           +------+------+------+------+
  0078h |                           |   Space for end of FCB    |
        +------+------+------+------+------+------+------+------+
  0080h |                                                       |
    .   .                                                       .
    .   .      Default Disk transfer address.  Initialized to   .
    .   .      original command line parameters.                .
    .   .                                                       .
  00F8h |                                                       |
        +------+------+------+------+------+------+------+------+
```

アドレス `0000h` には、トランジェントプログラムを終了させるために使用できるジャンプ命令（`JP`）があります。このジャンプ先のアドレスは、BIOSジャンプベクタ（セクション2.4参照）の場所を特定するためにも使用できます。CP/Mとの互換性を保つため、このジャンプ先アドレスの下位バイトは常に `03h` になります。

アドレス `0003h` と `0004h` の2バイトの予約領域は、CP/Mでは IOBYTE とカレントドライブ/ユーザー番号にあたる領域です。MSX-DOSはCP/Mとの互換性のためにカレントドライブのバイトを最新に保ちますが、新しいプログラムではこの領域を直接参照せず、代わりにMSX-DOSの「カレントドライブの取得」ファンクションコールを使用することを推奨します。ユーザー番号と IOBYTE はサポートされていません。MSX-DOSではI/O再指向（リダイレクション）がCP/Mとは異なる方法で行われ、ユーザー番号という概念も存在しないためです。

アドレス `0005h` には、MSX-DOSの常駐部へのジャンプ命令があり、これを利用してMSX-DOSコールを行います。また、このジャンプ命令のアドレス自体が、プログラムが使用可能な TPA の上限（Top of TPA）を定義しています。TPAのサイズは、MSX本体に装着されているカートリッジの種類やその数によって異なりますが、一般的にはおよそ 53KB です。このジャンプ先アドレスの下位バイトは、CP/M互換性のために常に `06h` となり、その直前の6バイトにはCP/Mのバージョン番号とシリアル番号が含まれます。

Z80の各リスタート（RST）割り込み位置（`0008h`〜`0028h`）には、ユーザー用にそれぞれ4バイトが確保されており、ジャンプ命令を記述するのに十分なスペースがあります。ただし、リスタート位置の間のバイトは、MSXのスロット切り替えルーチンのエントリーポイントとして使用されています。

`0038h` から `005Bh` までの領域は、MSXの割り込み処理およびセカンダリスロット切り替えコードに使用されるため、絶対に書き換えてはなりません。多くのCP/Mデバッガ（ZSIDやDDTなど）はブレークポイントのエントリーとしてアドレス `38h`（`RST 38h`）を使用しますが、これらのデバッガを使用する場合は別のリスタート（`RST 28h` を推奨）を使用するように修正する必要があります。

アドレス `005Ch` と `006Ch` に設定される2つのFCB（ファイルコントロールブロック）は、最初の2つのコマンドライン引数をファイル名として解釈して作成された、未オープンの有効なFCBです。両方のファイル名を使用する場合は、最初のFCBをオープンした際に2番目の領域が上書きされてしまうため、あらかじめ2番目のFCBの内容をメモリ上の別の場所にコピーしておく必要があります。FCBのフォーマットについてはセクション3.6を参照してください。

起動時のコマンド名を除いたコマンドライン全体は、デフォルトのDTA（Disk Transfer Area：ディスク転送領域）であるアドレス `0080h` に、先頭に長さバイト、末尾にヌル文字（`00h`）を付加した形で格納されます（長さバイトおよびヌル文字は、長さのカウントには含まれません）。この文字列は、環境変数 `UPPER` が `ON` である場合は大文字に変換され、CP/Mとの互換性を確保するために、入力された先頭のスペースも含めて格納されます。

MSX-DOS用の新しいプログラムでは、CP/M形式のFCBを使用すべきではありません。ディレクトリへのアクセスやパス名の処理が容易に行える、より使いやすい新しいMSX-DOSコールが用意されているためです（詳細はセクション3を参照）。

コマンドライン引数にアクセスする、より優れた方法も用意されています。環境文字列 `PARAMETERS` には、大文字変換されていないオリジナルのコマンドラインが格納されます。また、環境文字列 `PROGRAM` を使用することで、プログラムがロードされたドライブ、ディレクトリ、ファイル名を取得することができます。これらの環境文字列全般の詳細については、セクション3.5を参照してください。

### 2.4 BIOSジャンプテーブル
アドレス `0000h` にあるジャンプ命令は、常に下位バイトが `03h` であるアドレスへジャンプします。そのアドレスには別のジャンプ命令があり、これは17個のエントリーを持つジャンプテーブルの2番目のエントリーです。これは、CP/M 2.2 のBIOSジャンプテーブルと完全に一致しています。

このテーブルの最初の8つのエントリーは、リブート（再起動）およびキャラクターI/O用です。これらのルーチンはCP/Mと同じ仕様で実装されています。残りのジャンプ先は、CP/Mにおける低レベルのディスク関連ファンクションですが、MSX-DOSではファイルシステムが根本的に異なるため、これらに対応する処理はありません。これらのルーチンは、メインレジスタの値を破壊し、可能な場合はエラーを返して、何も行わずにそのままリターンします。

MSX-DOSはBIOSコールの実行中、内部スタックに切り替えるため、ユーザーのスタック領域は少階層（8バイト程度）しか消費しません。

なお、このジャンプテーブルは常に256バイトのページ境界に配置されますが、アドレス `0006h` で定義される TPA の上限からの距離は、CP/M 2.2 とまったく同じ距離にはなっていません。行儀の良いCP/Mプログラムであれば問題ありませんが、一部のプログラムはCP/M 2.2におけるBDOSのサイズに依存して作られているとの噂があり、そのようなプログラムは修正が必要になります。

BIOSジャンプベクタのエントリーは以下の通りです。

```asm
   xx00h - JMP WBOOT   ;ウォームブート
   xx03h - JMP WBOOT   ;ウォームブート
   xx06h - JMP CONST   ;コンソールステータス
   xx09h - JMP CONIN   ;コンソール入力
   xx0Ch - JMP CONOUT  ;コンソール出力
   xx0Fh - JMP LIST    ;リスト（プリンタ）出力
   xx12h - JMP PUNCH   ;パンチ（補助）出力
   xx15h - JMP READER  ;リーダー（補助）入力

   xx18h - JMP RETURN  ;CP/MにおけるHOME
   xx1Bh - JMP RETURN  ;CP/Mにおけるディスク選択
   xx1Eh - JMP RETURN  ;CP/Mにおけるトラック設定
   xx21h - JMP RETURN  ;CP/Mにおけるセクター設定
   xx24h - JMP RETURN  ;CP/MにおけるDMAアドレス設定
   xx27h - JMP RETURN  ;CP/Mにおけるセクター読み込み
   xx2Ah - JMP RETURN  ;CP/Mにおけるセクター書き込み
   xx2Dh - JMP LSTST   ;リストステータス
   xx30h - JMP RETURN  ;CP/Mにおけるセクタートランスレート
```

### 2.5 RAMページング
トランジェントプログラムがロードされると、マッパーRAMスロットが全4ページ（ページ0〜3）で有効になり、基本64KBを構成する4つのRAMセグメントがページインされます。また、ページ0にはMSXのBIOS ROM互換のスロット処理エントリーポイントが用意され、ページ3には各種マッパーサポートルーチン（仕様はセクション5参照）が用意されます。

プログラムは実行中、任意のスロット切り替えやページングを行うことができ、終了時にスロットの選択状態やRAMページングの状態を元に戻す必要はありません（これらは `COMMAND2.COM` が自動的に処理します）。ただし、プログラムがページ0を書き換える場合は、割り込み処理やスロットエントリーポイントに対して通常通りの注意を払う必要があります。また、**ページ3は絶対に書き換えてはなりません**（いかなる処理でも変更は禁止されています）。

MSX-DOSのファンクションコール（またはMSX-DOS BIOSコール）を呼び出す際、ページ0、1、2はどのスロットに切り替えていても構いません。その状態は呼び出し後も保存されます。パラメータは選択されているどのスロットからでも渡すことができますが、環境文字列やディスク転送領域（DTA）はマッパーRAMスロット内（TPA内）に存在している必要があります。

ファンクションコールを行う際、ページ0、1、2には任意のRAMセグメントを選択しておくことができ、スタックも任意のページに配置できます。現在のページング状態は、エラー発生時も含め、すべてのファンクションコールにおいて保存されます。ディスク転送は、ファンクションコールが呼び出された時点でページインされているRAMセグメントに対して直接行われます（これがオリジナルのTPAセグメントでなくても構いません）。

トランジェントプログラムが TPA 以上のRAMを使用したい場合は、マッパーサポートルーチン（セクション5参照）を使用して追加のRAMを取得できます。プログラムは、オリジナルのTPA 4セグメント以外のRAMを使用する前に、必ずマッパールーチンを呼び出して新しいセグメントを「確保（アロケート）」する必要があります。これにより、（RAMディスクなどによって）既に使用されているセグメントを誤ってプログラムが使用してしまう競合を防ぐことができます。確保したセグメントは、通常「ユーザーセグメント」として割り当てるべきです。ユーザーセグメントは、プログラム終了時に自動的に解放されます。「システムセグメント」は、トランジェントプログラム終了後もそのセグメントを保持し続ける必要がある場合にのみ確保してください。

追加のセグメントを確保した後は、プログラムはそれらをページインし、マッパーサポートルーチンを使用してアクセスすることができます。通常、必要に応じて元の TPA セグメントを再びページインできるように、元のTPAセグメント番号をプログラム側で記憶しておく必要があります。元のセグメント番号は通常 `0`、`1`、`2`、`3` ですが、トランジェントプログラムはこれを前提とせず、ページングを変更する前に必ずマッパールーチンの `GET_Pn` を使用して現在のセグメント番号を確認してください。

## 3. MSX-DOSコール

### 3.1 呼び出し規約
MSX-DOSのファンクションコールは、レジスタ `C` にファンクションコードを入れ、その他のメインレジスタに必要なパラメータを設定して、`CALL 5` 命令を実行することで行います。処理が実行され、ファンクションに応じた結果が各レジスタに返されます。

通常、すべてのメインレジスタ（`AF`、`BC`、`DE`、`HL`）の値はMSX-DOSの呼び出しによって書き換えられるか、結果が返されます。裏レジスタセット（`AF'`、`BC'`、`DE'`、`HL'`）は常に保存されます。インデックスレジスタ（`IX`、`IY`）は、結果を返す一部の例外的なケースを除き、すべて保存されます。

MSX-DOSは呼び出し時に内部のシステムスタックに切り替えるため、トランジェントプログラムのスタック領域は少階層（8バイト程度）しか必要としません。

互換性を保つため、CP/Mに相当する機能を持つすべてのファンクションは、`A=L` および `B=H` の状態でリターンします。多くの場合、`A` にはエラーフラグが返され、成功時は `00h`、失敗時は `01h` または `FFh` になります。

MSX-DOS 2で新設されたすべてのファンクション（ファンクションコード `40h` 以上）は、レジスタ `A` にエラーコードを返し、その他の結果を各メインレジスタに返します。エラーコード `0` は「エラーなし」を意味し、ゼロ以外の値はエラーが発生したことを示します。その具体的な内容は値によって判断できます。エラーコードとメッセージの一覧はセクション6に記載されています。エラーコードに対応するASCII形式の解説文字列を取得できる「エラーコード解説（Explain Error Code）」ファンクションも提供されています。

個々のファンクションの仕様は『MSX-DOS 2 ファンクション仕様書』に詳しく記載されています。

### 3.2 デバイスとキャラクターI/O
MSX-DOSのファンクションでファイル名（filename）を指定する箇所では、代わりにデバイス名（device name）を指定することもできます。これらのデバイスはキャラクターベースのI/Oに使用され、プログラム側で相手がディスクファイルなのかキャラクターデバイスなのかを意識することなく、全く同じ方法でアクセスすることができます。

デバイス名の構文はファイル名と完全に同一であるため、プログラム側でデバイス名のための特別な処理を行う必要はありません。これは新しいMSX-DOS 2のファンクションだけでなく、従来のCP/M互換のFCBファンクションにも適用されます。デバイス用に予約されているファイル名は以下の通りです。

```text
     CON  - 画面出力、キーボード入力
     PRN  - プリンタ出力
     LST  - プリンタ出力（PRNと同一）
     AUX  - 補助入出力
     NUL  - ヌルデバイス（空のデバイス）
```

これらの名前がファイル名の主要部（拡張子を除く部分）として現れた場合、それは実際の物理デバイスを指し、拡張子は無視されます。ファイルを扱うほとんどのファンクションコールでデバイス名を使用できます。例えば、`CON` というファイル名を「ファイル名の変更（RENAME）」ファンクションや「ファイルの削除（DELETE）」ファンクションに指定してもエラーは返されず、単にデバイスに対して何も行わずに成功します。

上記の `AUX` デバイスはデフォルトでは何も行いませんが、シリアルドライバなどのルーチンをここにフック（接続）して使用することができます。`NUL` デバイスは実際には何もしないデバイスであり、出力した文字は無視され、入力を行うと常に EOF（End-Of-File）が返されます。`LST` と `PRN` は同一のデバイス（プリンタ）です。

`CON` デバイスは、キーボードからの入力や画面への出力に使用されます。`CON` デバイスから入力を行う際、システムは1行ずつ読み込み、ユーザーがコマンドライン編集機能を使用できるようにします。ユーザーがキャリッジリターン（Enterキー）を押した時点で初めて、入力データが確定してプログラムに渡されます。入力の終わりは、行頭での `Ctrl-Z` 文字の入力によって示されます。

システムは起動時に、これらの標準デバイスに対していくつかのファイルハンドルをあらかじめオープンします（詳細はセクション3.3を参照）。プログラムはこれらの標準ファイルハンドルを使用して標準デバイスにアクセスすることができます。あるいは、従来のCP/M形式のキャラクター入出力ファンクション（ファンクション `01h`〜`0Bh`）を使用することも可能です。どちらの方法も使用できますが、それぞれ独自のバッファリングスキームを持っているため、これらを混ぜて使用するとバッファ内で文字が消失する恐れがあり、通常は混在させるべきではありません。

コマンドラインでリダイレクト（再指向）が指定された場合、標準ファイルハンドルとCP/Mキャラクターファンクションの両方がリダイレクトされます。ただし、ディスクファイルにアクセスする際の速度がキャラクターファンクションより大幅に向上するため、標準ファイルハンドルを使用し、大きめのブロック単位でリード/ライトを行う方法が強く推奨されます。

コマンドラインでリダイレクトが指定されている場合でも、プログラムはリダイレクトをバイパスして、画面へ直接出力したりキーボードから直接入力したりする必要がある場合があります（ディスクエラー処理ルーチンなど）。これを容易にするために、キャラクターファンクションのリダイレクトを一時的にキャンセルできるファンクション（ファンクション `70h`）が用意されています。

### 3.3 ファイルハンドル
ファイルハンドルは、新しいMSX-DOSファンクションを使用してファイルの読み書きを行うための仕組みです。また、ファイル属性の変更など、ファイルを操作するその他の様々な処理にも使用されます。

ファイルハンドルは、オープンされている特定のファイルまたはデバイスを指す8ビットの数値です。新しいファイルハンドルは、「ファイルハンドルのオープン（Open file handle）」（ファンクション `43H`）または「ファイルハンドルの作成（Create file handle）」（ファンクション `44H`）を実行した際に割り当てられます。このファイルハンドルを使用してデータを入出力し、使い終わったら「ファイルハンドルのクローズ（Close file handle）」（ファンクション `45H`）または「ファイルハンドルの削除（Delete file handle）」（ファンクション `52H`）を呼び出すまで保持されます。ファイルハンドルが指すファイルの名前を変更したり、属性を変更したりする操作も行えます。

MSX-DOSが新しいファイルハンドルを割り当てる際は、常に空いている一番小さな番号が使用されます。現バージョンでの最大ファイルハンドル数は `63` です。将来のバージョンではこの数が増やされる可能性がありますが、`127` を超えることはないため、ファイルハンドルが負の数（ビット7が1）になることはありません。

ファイルハンドル用に使用される内部データ構造のメモリ領域は、16KBのRAMセグメント（データセグメント）内に動的に確保されるため、同時にオープンできるファイルハンドルの数に固定の制限はありません。このデータセグメントは TPA の外側に保持されるため、ここにデータを保存しても TPA のサイズが減少することはありません。システムは、このデータセグメント内にファイルハンドルの情報だけでなく、ディスクバッファや環境文字列も保持しています。

いくつかのファイルハンドルは事前に定義されており、プログラムが起動した時点で既にオープンされています。これらは標準の入出力デバイスを指しています。従来のCP/MスタイルのMSX-DOSキャラクターI/Oファンクションも、内部的にはこれらのファイルハンドルを参照しています。

トランジェントプログラムが起動した際に渡される標準入出力ファイルハンドルは、コマンドインタプリタが使用していたオリジナルそのものではなく、その「コピー」です。そのため、プログラム内でこれらのファイルハンドルを自由にクローズしたり、別の場所にオープンし直したりしても、終了前に元に戻す必要はありません。

デフォルトのファイルハンドルとその割り当て先は以下の通りです。

* **0** - 標準入力（`CON`）
* **1** - 標準出力（`CON`）
* **2** - 標準エラー出力（`CON`）
* **3** - 標準補助入出力（`AUX`）
* **4** - 標準プリンタ出力（`PRN`）

コマンドインタプリタがコマンド（トランジェントプログラムなど）を実行しようとする直前に、システムは「フォーク（Fork）」ファンクション（ファンクション `60H`）を実行します。これにより、新しいプログラムが「サブルーチン」として実行されることがシステムに通知され、現在オープンされているすべてのファイルハンドルが複製されます。したがって、新しいプログラムはオリジナルのハンドルではなく、そのコピーを使用することになります。

トランジェントプログラムが既存のファイルハンドルをクローズしたり、新しくオープンしたりしてファイルハンドルを変更しても、変更されるのはプログラム自身のファイルハンドルセットだけであり、親（コマンドインタプリタなど）のセットは変更されません。プログラムが終了すると、コマンドインタプリタは「ジョイン（Join）」ファンクション（ファンクション `61H`）を実行し、フォーク時に返されたプロセスIDを渡します。これにより、プログラムが終了したことがシステムに伝わり、そのプログラムが使用していたすべてのファイルハンドルが破棄されます。

システムは、各ハンドルのコピーがいくつ存在するかを「参照カウント」で管理しているため、プログラムがファイルハンドルをクローズし忘れて終了した場合でも、不要になったファイルハンドルを自動的に整理・クローズできます。これにより、行儀の悪いプログラムのせいでファイルハンドルが枯渇する事態を防ぎます。

これらの「フォーク」および「ジョイン」ファンクションは、必要であればユーザープログラムから呼び出して使用することも可能です。なお、「ジョイン」はファイルハンドルの整理に加え、プログラムが解放し忘れたユーザー割り当てRAMセグメントも自動的に解放します。

### 3.4 ファイル情報ブロック
ディスク上のファイルを操作する新しいMSX-DOSファンクションの多くは、ドライブ名、パス名、および曖昧さのないファイル名を含む、末尾がヌル文字（`00h`）で終わる文字列（**ASCIIZ文字列**）への単純なポインタを渡すだけで動作します。通常、高レベル言語のインターフェースなどを通じて行われる操作はこちらです。

より複雑な操作（ディレクトリ内にある未知のファイルやサブディレクトリの検索など）を行うために、これらのファンクションに **ファイル情報ブロック（FIB: File Info Block）** を渡すことができます。

FIBは、特定のファイルまたはサブディレクトリに関するディスク上のディレクトリ情報（ディレクトリエントリ）を格納するための、ユーザーメモリ上の **64バイト** の領域です。FIBの情報は、MSX-DOSの新設された「検索」ファンクション（「最初のファイル検索（Find first entry）」（ファンクション `40H`）、「新規ファイル検索（Find new entry）」（ファンクション `42H`）、「次のファイル検索（Find next entry）」（ファンクション `41H`））によって書き込まれます。FIBのフォーマットは以下の通りです。

```text
     0 - 常に 0FFh
 1..13 - ファイル名（ASCIIZ文字列形式）
    14 - ファイル属性バイト
15..16 - 最終更新時刻
17..18 - 最終更新日付
19..20 - 開始クラスタ番号
21..24 - ファイルサイズ
    25 - 論理ドライブ番号
26..63 - 内部情報（書き換え禁止）
```

いくつかのファンクションは引数としてパス名文字列とFIBのどちらでも受け取れる設計になっているため、FIBの先頭のバイトは、それがパス名文字列ではなくFIBであることを識別するために **常に `0FFh`** でなければなりません。

ファイル名は直接表示するのに適した形式（ASCIIZ文字列）で格納されます。スペースは取り除かれ、拡張子がある場合はその前にドット（`.`）が挿入され、すべて大文字に変換されます。ただし、そのエントリが「ボリュームラベル（Volume Label）」である場合は、ドットによる区切り文字はなく、スペースを含んだままで、大文字への変換も行われません。

ファイル属性バイトは、ファイルに関するフラグを表す1バイトです。フォーマットは以下の通りです。

* **Bit 0 - READ ONLY（読込専用）**: セットされている場合、ファイルへの書き込みや削除はできませんが、読み込み、名前変更、移動は可能です。
* **Bit 1 - HIDDEN FILE（隠しファイル）**: セットされている場合、「最初のファイル検索」ファンクションにおいて、検索属性バイトの「隠しファイル」ビットがセットされている場合にのみ検索にヒットします。コマンドインタプリタが提供するディスク上のファイル/ディレクトリにアクセスするコマンドの多くは、隠しファイルを検索対象に含めるための `/H` オプションを持っています。
* **Bit 2 - SYSTEM FILE（システムファイル）**: MSX-DOSの処理上、このビットは「隠しファイル」ビットと全く同様に作用します。ただし、「新規ファイル検索」および「ファイル作成」ファンクションを実行する際、同名のシステムファイルが存在していても自動的には削除されません。コマンドインタプリタが提供する通常のコマンドでは、システムファイルへのアクセスは許可されません。
* **Bit 3 - VOLUME NAME（ボリューム名）**: セットされている場合、このエントリはディスクのボリューム名を定義します。ルートディレクトリにのみ存在し、1つしか作成できません。このビットがセットされている場合、他の属性ビットは無視されます。
* **Bit 4 - DIRECTORY（ディレクトリ）**: セットされている場合、このエントリはファイルではなくサブディレクトリであることを示します。したがって、データの読み書きのためにオープンすることはできません。サブディレクトリに対しては、隠しファイル属性（Bit 1）のみが意味を持ちます。
* **Bit 5 - ARCHIVE BIT（アーカイブ）**: ファイルに書き込みが行われてクローズされるたびに、このビットがセットされます。このビットは、例えば `XCOPY` コマンドなどがファイルが変更されたかどうかを判断するために参照されます。
* **Bit 6 - 予約領域（常に 0）**
* **Bit 7 - DEVICE BIT（デバイス）**: このビットがセットされている場合、このFIBがディスクファイルではなくキャラクターデバイス（`CON` など）を指していることを示します。この時、他の属性ビットはすべて無視されます。

最終更新時刻は、以下の形式で2バイトにエンコードされています。

```text
     Bits 15..11 - 時 (0..23)
     Bits 10...5 - 分 (0..59)
     Bits  4...0 - 秒 / 2 (0..29)
```

最終更新日付は、以下の形式で2バイトにエンコードされています。すべてのビットがゼロの場合、有効な日付が設定されていないことを意味します。

```text
     Bits 15...9 - 年 (0..99。それぞれ西暦 1980年〜2079年に対応)
     Bits  8...5 - 月 (1..12。それぞれ 1月〜12月に対応)
     Bits  4...0 - 日 (1..31)
```

ファイルサイズは、32ビットの数値（下位バイトが先）で格納されます。サブディレクトリの場合は常にゼロになります。

論理ドライブは、1バイトのドライブ番号です。`1` が `A:`、`2` が `B:` などに対応します。元々のファンクション呼び出しで `0`（デフォルトドライブ）を指定していた場合でも、ここにはデフォルトドライブの実際のドライブ番号が書き込まれるため、ゼロになることはありません。

内部情報は、ディスク上のどの場所にディレクトリエントリが格納されているかをMSX-DOSに示すためのものです。これにより、FIBを他のファンクションに渡すことで、該当するディレクトリエントリの削除、名前変更、オープンなどの処理を行えます。また、ここに格納されているデータにより、「次のファイル検索」ファンクション（ファンクション `41H`）は前回の続きから検索を再開し、一致する次のファイルを探すことができます。**ユーザーはこの内部情報を直接参照したり、変更したりしてはなりません。**

FIBは、「最初のファイル検索」、「新規ファイル検索」、「次のファイル検索」ファンクションによって書き込まれます。これらのファンクションは、ディレクトリ内から条件に合致するエントリを探し出し、FIBに必要な情報を設定します。

「最初のファイル検索」は、指定されたファイル名に一致し、かつ適切な属性を持つ最初のエントリを検索します。「次のファイル検索」は、前の「最初のファイル検索」から始まる検索処理を引き継ぎ、FIBを次の一致するエントリ情報で更新します。

「新規ファイル検索」は、「最初のファイル検索」と似ていますが、一致するエントリを探すのではなく、新しくエントリを作成し、あたかも「最初のファイル検索」がそれを発見したかのようにFIBを作成して返します。

検索ファンクションによって作成されたFIBの用途は2つあります。1つ目は、ファイル名やファイルサイズなど、FIBに含まれる情報を単に参照することです。例えば `DIR` コマンドは、この情報を画面に出力するためにFIBを使用しています。

もう1つの重要な用途は、ディレクトリエントリに対する操作を行うために、このFIBを別のMSX-DOSファンクションにパラメータとして渡すことです。ファンクション仕様書に記載されている多くのMSX-DOSファンクション（レジスタ `DE` にパラメータを受け取るもの）は、ドライブ/パス/ファイルの文字列へのポインタだけでなく、FIBへのポインタも受け取ることができます。どちらの場合でも、操作対象となる特定のファイルやディレクトリが特定されます。

FIBをパラメータとして受け取ることができるファンクションは、「ファイルまたはサブディレクトリの削除」（ファンクション `4DH`）、「ファイルまたはサブディレクトリの名前変更」（ファンクション `4EH`）、「ファイルまたはサブディレクトリの移動」（ファンクション `4FH`）、「ファイル属性の取得/設定」（ファンクション `50H`）、「ファイルの作成日時・更新日時の取得/設定」（ファンクション `51H`）、および「ファイルハンドルのオープン」（ファンクション `43H`）です。これらはすべて、指定されたファイルやディレクトリに対してそれぞれの処理を行います。

また、FIBはパス名文字列の代わりに「最初のファイル検索」や「新規ファイル検索」ファンクションに渡すこともできます。この場合、渡されるFIBはファイルではなくディレクトリを指している必要があり、かつレジスタ `HL` に検索するファイル名文字列（通常は `*.*` を意味するヌル文字列など）を渡します。FIBが指定するディレクトリ内から、そのファイル名に一致するものが検索されます。この機能は、コマンドインタプリタが `DIR A:UTIL` のように、`UTIL` がディレクトリであった場合に期待される処理を実行するために必要となります。

### 3.5 環境変数（環境文字列）
MSX-DOSは、データセグメント内に「環境文字列（Environment Strings）」のリストを保持しています。環境文字列は、名前と、それに関連付けられた値のペアで構成されます。名前と値はどちらもユーザー定義可能です。これらはシステムコールレベルでは、「環境文字列の取得」（ファンクション `6BH`）、「環境文字列の設定」（ファンクション `6CH`）、および「環境文字列の検索」（ファンクション `6DH`）を介してアクセスされます。

環境文字列の名前は、ファイル名として使用できる任意の文字からなる、空ではない文字列です。名前は最大 255文字まで指定できます。文字列が定義されると、名前の文字は自動的に大文字に変換されます（ただし、名前の比較時には大文字・小文字は区別されません）。

環境文字列の値は、ヌル文字以外の文字で構成される文字列で、最大 255文字まで指定できます。すでに定義されている環境文字列の値を「ヌル文字列」に設定すると、その環境文字列はリストから削除されます。同様に、定義されていない環境文字列を読み出そうとすると、ヌル文字列が返されます。値については、大文字への自動変換は行われず、文字列内の文字に対する解釈も行われません。

トランジェントプログラムが `COMMAND2.COM` からロードされて実行される際、プログラムが読み取れるように2つの特別な環境文字列が自動的に設定されます。

1. **`PARAMETERS`**  
   コマンド名自体を除いた、コマンドライン引数全体の文字列に設定されます。これはCP/M互換のためにアドレス `80h` に設定されるものと同様ですが、大文字への変換が行われていないオリジナルの文字列です。
2. **`PROGRAM`**  
   ディスク上でプログラムを特定するために使用された完全なパスに設定されます。最初にドライブ名、次にルートディレクトリからのパス、そしてプログラムの実際のファイル名が続きます。必要であれば、「パス名の解析（Parse Pathname）」ファンクション（ファンクション `5CH`）を使用して、ドライブ、パス、ファイル名を分割することができます。

環境文字列 `PROGRAM` にはいくつかの用途があります。主な用途は、プログラム自身がロードされたのと同じディレクトリから、オーバーレイファイル（分割ロード用ファイル）をロードすることです。`PROGRAM` の最後の要素（つまりプログラム自身のファイル名）をオーバーレイファイルのファイル名に置き換えることで新しいパス文字列を作り、これを「ファイルのオープン」などのASCIIZ文字列を受け取るMSX-DOS 2ファンクションに渡すことができます。

なお、一部のCP/Mプログラムはトランジェントプログラムをロードして実行する機能を持ちますが、この場合はCP/Mプログラム側で `PROGRAM` や `PARAMETERS` の環境文字列が再設定されないため、それらの環境文字列は以前そのCP/Mプログラム自体がロードされたときの状態のままになります。もし作成するプログラムが `PROGRAM` や `PARAMETERS` を利用しつつ、CP/Mプログラムからも起動できるようにしたい場合は、ページ0のアドレス `0037h` にある `LOAD_FLAG` という変数を確認してください。このフラグはMSX-DOS 2のファンクションコールを呼び出すたびに `0` にリセットされますが、コマンドインタプリタがトランジェントプログラムを実行する直前には、非ゼロ（`0` 以外）に設定されます。同様に、もし新しいトランジェントプログラムが他のプログラムをロードする機能を持ち、`PROGRAM` や `PARAMETERS` を設定する場合は、実行前にこの `LOAD_FLAG` を非ゼロに設定する必要があります。

もう1つの特別な環境文字列として **`APPEND`** があります。これはコマンドインタプリタからユーザーが設定できるもので、CP/M互換の「ファイルオープン (FCB)」ファンクションで使用されます。このファンクションコールが実行された際に対象ファイルが見つからない場合、`APPEND` で指定された代替ディレクトリが検索されます。ただし、新しく作成するプログラムでこのファンクションや `APPEND` 環境文字列を使用することは想定されていません。

この他にも、コマンドインタプリタの起動時にいくつかの環境文字列が設定され、ユーザーによるシステム機能やオプションの制御に使用されます。トランジェントプログラムがこれらを参照すると便利な場合があります。例えば、プログラム内で日時を表示する場合に `PATH` 環境文字列や、`DATE`、`TIME` 環境文字列を読み取ることなどが考えられます。デフォルトで用意されている環境文字列の詳細については、『コマンド仕様書』を参照してください。

### 3.6 ファイルコントロールブロック
MSX-DOS 2用に新しく作成されたプログラム、あるいはMSX-DOS 2用に修正されたMSX-DOS 1やCP/Mのプログラムにおいて、従来のCP/M互換FCBファンクションを使用することは推奨されませんが、参考のためにこれらのファンクションで使用されるFCBのフォーマットを以下に記載します。このフォーマットはCP/MやMSX-DOS 1で使用されていたFCBとほぼ同様ですが、一部のフィールドの使用方法が異なります（ただし、一般的には互換性があります）。

基本FCBの長さは **33バイト** です。この形式のFCBは、ファイル管理操作（削除、名前変更など）や、シーケンシャル（順次）リード/ライトに使用できます。ランダムリード/ライトを使用する場合は、FCBの末尾にランダムレコード番号を格納するための追加の **3バイト** が必要です。また、MSX-DOS 1互換のブロックリード/ライトファンクションでは、さらにもう3バイト（場合によっては4バイト）を使用します。詳細はファンクション仕様書を参照してください。

FCBのレイアウトを以下に示します。ここでは各フィールドの一般的な説明を行います。各ファンクションにおける個別の具体的な使用方法については、仕様が自明でないものに限り、ファンクション仕様書に詳細が記載されています。

* **`00h` - ドライブ番号**  
  `1`〜`8`（`1`がA:、`2`がB:など）。`0` を指定するとデフォルトドライブになります。使用するすべてのFCBであらかじめ設定しておく必要があります。MSX-DOSファンクションの呼び出しによって書き換えられることはありません（`APPEND` が有効な状態での「ファイルオープン」時を除く）。
* **`01h`...`08h` - ファイル名**  
  左詰めで、余った部分はスペースで埋められます。曖昧なファイル名が許可されているファンクション（ファンクション仕様書参照）では、ワイルドカード文字 `?` を含めることができます。ファイル名の比較時は大文字と小文字は区別されません。新しくファイルを作成する際は、名前は自動的に大文字に変換されます。
* **`09h`...`0Bh` - 拡張子**  
  ファイル名と同様に格納されます。なお、CP/Mとは異なり、拡張子文字のビット7はフラグ（R/O属性やシステム属性など）として解釈されません。
* **`0Ch` - エクステント番号（下位バイト）**  
  オープンまたは作成を行う前に、プログラム側で通常 `0` に初期化しておく必要があります。シーケンシャルリード/ライトによって使用および更新され、ランダムリード/ライト時にも設定されます。これはCP/MおよびMSX-DOS 1と互換性があります。
* **`0Dh` - ファイル属性**  
  オープン、作成、またはファイル検索時に設定されます。
* **`0Eh`**  
  * **エクステント番号（上位バイト、CP/Mファンクション時）**: オープンおよび作成時に `0` にクリアされます。シーケンシャルリード/ライトにおいては、より大きなファイルにアクセスできるように、エクステント番号の拡張部分として使用・更新されます。CP/Mの仕様とは異なりますが、CP/Mの通常のFCB使用方法とは競合せず、MSX-DOS 1とも同一です。
  * **レコードサイズ（下位バイト、MSX-DOS 1ブロックファンクション時）**: ブロックリード/ライトを使用する前に、プログラム側で必要なレコードサイズを設定しておく必要があります。
* **`0Fh`**  
  * **レコード数（CP/Mファンクション時）**: オープンおよび作成時に設定され、シーケンシャルまたはランダムのリード/ライトによって必要に応じて変更されます。CP/MおよびMSX-DOS 1と同一です。
  * **レコードサイズ（上位バイト、MSX-DOS 1ブロックファンクション時）**: ブロックリード/ライトを使用する前に、プログラム側で必要なレコードサイズを設定しておく必要があります。
* **`10h`...`13h` - ファイルサイズ（バイト数、下位バイトが先）**  
  ファイルサイズは128バイト境界に切り上げられることなく、バイト単位で正確に記録されます。このフィールドはオープンおよび作成時に設定され、書き込みによってファイルが拡張された場合に更新されます。クローズファンクションを呼び出した際にディスクに書き戻されるため、**プログラム側でこの値を変更してはなりません。** これはMSX-DOS 1と同一ですが、この領域にアロケーション（割り当て）情報を格納するCP/Mとは異なります。
* **`14h`...`17h` - ボリュームID**  
  このFCBがアクセスしている特定のディスクを識別するための4バイトの数値です。オープンおよび作成時に設定され、その後のリード、ライト、クローズ時にディスクが変更されていないかチェックするために使用されます。プログラム側で変更してはなりません。この領域に最終更新日時を記録していたMSX-DOS 1や、アロケーション情報を記録していたCP/Mとは異なります。
* **`18h`...`1Fh` - 内部情報**  
  ファイルがディスク上のどこにあるかを特定するための情報が含まれます。**プログラム側で書き換えてはなりません。** ここに保持されるデータはMSX-DOS 1のものと類似していますが、完全に同一ではなく、CP/Mのものとは根本的に異なります。
* **`20h` - 現在のエクステント内のレコード番号 (0...127)**  
  最初のシーケンシャルリード/ライトを実行する前に、プログラム側で通常 `0` に設定しておく必要があります。シーケンシャルリード/ライトによって使用および更新されます。また、ランダムリード/ライトによっても設定されます。CP/MおよびMSX-DOS 1互換です。
* **`21h`...`24h` - ランダムレコード番号（下位バイトが先）**  
  このフィールドはオプションであり、ランダムまたはブロックのリード/ライトを使用する場合にのみ必要です。これらの処理を実行する前に設定する必要があり、ブロックリード/ライト時は更新されますが、ランダムリード/ライト時は更新されません。「ランダムレコードの設定」ファンクションによっても設定されます。

MSX-DOS 1には存在しCP/Mにはないブロック操作においては、レコードサイズが 64バイト未満の場合は4バイトすべてが使用され、レコードサイズが 64バイト以上の場合は最初の3バイトのみが使用されます。ランダムリード/ライトにおいては、最初の3バイトのみが使用されます（レコードサイズは128バイトと仮定されます）。これはCP/MおよびMSX-DOS 1と互換性があります。

## 4. 画面制御コード
以下は、MSX-DOSのキャラクターファンクション、BIOSコール、またはデバイス `CON` への書き込みによってキャラクター出力を行う際に使用できる、すべてのコントロールコードおよびエスケープシーケンス（VT-52互換のコントロールコードを含む）の一覧です。これらはすべてMSX-DOS 1と互換性があります。

画面は「横 2〜80文字 × 縦 24行」です。印字可能文字が表示されると、カーソルは次の位置へ移動し、行の末尾に達すると次の行の先頭に回り込みます。右下の角の位置に文字が書き込まれた場合、画面は上へスクロールし、カーソルは次の新しい行の先頭に配置されます。

エスケープシーケンス内の文字（アルファベット）は大文字・小文字を正確に区別する必要があります。シーケンス内のスペースは見やすさのために挿入されているだけであり、実際のシーケンスの一部ではありません。数値を表す `<n>` や `<m>` は、通常 `20h`（ASCIIスペースコード）のオフセットが加えられた1バイトのデータとしてシーケンスに含めます。

* **`Ctrl-G` (`07h`)**: ベル（警告音）を鳴らす。
* **`Ctrl-H` (`08h`)**: カーソルを左へ移動する。前の行の末尾へ回り込み、画面の左上端で停止する。
* **`Ctrl-I` (`09h`)**: タブ。次の8文字ごとのカラム位置までスペースで埋める。行末に達した場合は次の行の先頭に回り込み、右下の角に達した場合は画面をスクロールする。
* **`Ctrl-J` (`0Ah`)**: ラインフィード（改行）。画面下端で実行された場合は画面をスクロールする。
* **`Ctrl-K` (`0Bh`)**: カーソルをホーム位置（画面左上）へ移動する。
* **`Ctrl-L` (`0Ch`)**: 画面を消去し、カーソルをホーム位置へ移動する。
* **`Ctrl-M` (`0Dh`)**: キャリッジリターン（復帰）。
* **`Ctrl-[` (`1Bh`)**: `ESC` 文字（以下のエスケープシーケンスを開始する）。
* **`Ctrl-\` (`1Ch`)**: カーソルを右へ移動する。次の行の先頭へ回り込み、画面の右下端で停止する。
* **`Ctrl-]` (`1Dh`)**: カーソルを左へ移動する。前の行の末尾へ回り込み、画面の左上端で停止する。
* **`Ctrl-^` (`1Eh`)**: カーソルを上へ移動する。画面上端で停止する。
* **`Ctrl-_` (`1Fh`)**: カーソルを下へ移動する。画面下端で停止する。
* **`7Fh`**: 1文字削除し、カーソルを左へ移動する。前の行の末尾へ回り込み、画面上端で停止する。

## 5. マッパーサポートルーチン
MSX-DOS 2には、メモリーマッパーを支援するルーチンが含まれています。これにより、MSXアプリケーションやMSX-DOSトランジェントプログラムは、RAMディスクや他のシステムソフトウェアと衝突することなく、基本64KBを超えるメモリを利用することができます。

### 5.1 マッパーの初期化
DOSカーネルは初期化時に、システム内にメモリーマッパーが存在すること、および最低 128KB のRAMが利用可能であることを確認します。カーネルは 128KB 以上のマッパーRAMを搭載したスロットを少なくとも1つ発見すると、最も容量の大きいスロット（容量が同じスロットが複数ある場合は最もスロット番号が小さいスロット）を選択し、そのスロットをシステムRAMとして使用できるように設定します。メモリーマッパー上のメモリが不足している場合、MSX-DOS 2は起動しません。

次に、カーネルはこのスロット（プライマリーマッパースロット）内で利用可能な 16KB のRAMセグメントのテーブルを構築します。最初の4セグメント（64KB）はユーザー用に、最も数値の大きい2セグメントはシステム用（1つはDOSカーネルコード用、もう1つはDOSカーネルワークスペース用）として確保されます。それ以外のセグメント（最低2つ）は、初期状態では「空き（free）」としてマークされます。その後、他のRAMマスタースロット（存在する場合）についても同様のテーブルを構築し、それらのセグメントはすべて初期状態で「空き」としてマークされます。

### 5.2 マッパー変数とルーチン
マッパーサポートルーチンは、DOSシステム領域内にあるいくつかの変数を使用します。これらのテーブルはユーザープログラムから様々な用途で参照・使用することができますが、**書き換えてはなりません。** テーブルの内容は以下の通りです。

```text
アドレス      機能
+0        マッパースロットのスロットアドレス
+1        16KB RAMセグメントの総数（1〜255。プライマリスロットでは8〜255）
+2        空いている 16KB RAMセグメントの数
+3        システムに確保されている 16KB RAMセグメントの数（プライマリでは最低6）
+4        ユーザーに確保されている 16KB RAMセグメントの数
+5...+7   未使用（常に 0）
+8...     他のマッパースロットのエントリ。他になければ +8 の位置は 0
```

プログラムは、いくつかのサブルーチンを呼び出すことでマッパーサポート機能を使用します。これらは、MSX-DOSシステム領域内にあるジャンプテーブルを介してアクセスされます。ジャンプテーブルの内容は以下の通りです。

```text
アドレス  エントリー名   機能
+00h   ALL_SEG   16KBセグメントを確保（アロケート）する。
+03h   FRE_SEG   16KBセグメントを解放（フリー）する。
+06h   RD_SEG    セグメント A のアドレス HL から A レジスタに1バイト読み込む。
+09h   WR_SEG    セグメント A のアドレス HL に E レジスタの値を1バイト書き込む。
+0Ch   CAL_SEG   セグメント間コールを実行する。呼び出しアドレスは IYh:IX
+0Fh   CALLS     セグメント間コールを実行する。呼び出しアドレスは CALLS 命令の次の行
+12h   PUT_PH    ページ（HLのビット14,15で指定）にセグメントをマップする。
+15h   GET_PH    現在のページ（HLで指定）にマップされているセグメントを取得する。
+18h   PUT_P0    ページ0にセグメントをマップする。
+1Bh   GET_P0    ページ0の現在のセグメントを取得する。
+1Eh   PUT_P1    ページ1にセグメントをマップする。
+21h   GET_P1    ページ1の現在のセグメントを取得する。
+24h   PUT_P2    ページ2にセグメントをマップする。
+27h   GET_P2    ページ2の現在のセグメントを取得する。
+2Ah   PUT_P3    サポート対象外。ページ3の変更は禁止されているため、呼び出しても NOP として動作。
+2Dh   GET_P3    ページ3の現在のセグメントを取得する。
```

プログラムは、マッパーサポート用の拡張BIOSコールを使用して、これらのアドレスを取得することができます。将来のバージョンでこれらのアドレスが変更される可能性があるため、またMSX-DOSのマッパーサポートルーチン以外のルーチンを使用できるようにするために、このBIOSコールが提供されています。

拡張BIOSを使用するにあたり、プログラムはページ3の `FB20h` にある `HOKVLD` フラグを確認する必要があります。もしビット0（LSB）が `0` であれば、拡張BIOSおよびマッパーサポートは存在しません。それ以外の場合は、`FFCAh`（ページ3内）の `EXTBIO` エントリーが設定されており、様々なパラメータを渡して呼び出すことができます。なお、ディスクから起動されたプログラムなど、MSX-DOS環境を前提としたアプリケーションでは、この事前の確認テストは実質的に不要であり、次のステップへ直接進むことができます。

次に、プログラムは拡張BIOSの「デバイス番号」をレジスタ `D` に、「ファンクション番号」をレジスタ `E` に設定し、その他の必要なパラメータを各レジスタに設定して、ページ3のアドレス `FFCAh`（`EXTBIO`）をコールします。このとき、**スタックポインタ（SP）は必ずページ3内を指していなければなりません。** 指定されたデバイス番号に対応する拡張BIOSが存在する場合、レジスタ `AF`、`BC`、`HL` の内容はファンクションに応じて更新されます。存在しない場合は、これらのレジスタの値は保持されます。レジスタ `DE` は常に保存されます。なお、いずれの場合も、裏レジスタ（`AF'`、`BC'`、`DE'`、`HL'`）およびインデックスレジスタ（`IX`、`IY`）の値は破壊されることに注意してください。

マッパーサポート拡張BIOSで利用可能なファンクションは以下の通りです。

#### * マッパー変数テーブルの取得（Get mapper variable table）

* **パラメータ:**
  * `A` = `0`
  * `D` = `4` （マッパーサポートのデバイス番号）
  * `E` = `1`
* **結果:**
  * `A` = プライマリーマッパーのスロットアドレス
  * `DE` = 予約領域
  * `HL` = マッパー変数テーブルの開始アドレス

#### * マッパーサポートルーチンアドレスの取得（Get mapper support routine address）

* **パラメータ:**
  * `A` = `0`
  * `D` = `4`
  * `E` = `2`
* **結果:**
  * `A` = メモリーマッパーセグメントの総数
  * `B` = プライマリーマッパーのスロット番号
  * `C` = プライマリーマッパーの空きセグメント数
  * `DE` = 予約領域
  * `HL` = ジャンプテーブルの開始アドレス

上記の拡張BIOSを呼び出す際、レジスタ `A` はあらかじめ `0` にしておく必要があります。マッパーサポートが存在しない場合はレジスタの内容は変更されず、存在する場合には `A` には `0` 以外の値が返されます。したがって、呼び出し時に `A` を `0` に設定しておき、戻ってきたときの `A` の値を確認することで、マッパーサポートルーチンが存在するかどうかを判断できます。

拡張BIOSによって返されるプライマリーマッパーのスロットアドレスは、現在のページ3におけるRAMのスロットアドレスと同一であり、一般的な環境（DISK-BASICやMSX-DOS）では、ページ2にも同じRAMスロットが選択されています。MSX-DOS環境下では、ページ0およびページ1にも同様にこのRAMスロットが選択されています。

### 5.3 マッパールーチンの使用方法
プログラムは、「`ALL_SEG`」ルーチンを呼び出すことで、いつでも 16KB のRAMセグメントを要求できます。空きセグメントがない場合はエラーが返され、空きがある場合はプログラムが使用可能な新しいセグメント番号が返されます。プログラムは、自身に明示的に割り当てられたセグメント、および基本64KBを構成する初期の4セグメント以外を**勝手に使用してはなりません。**

セグメントは「ユーザーセグメント」または「システムセグメント」として確保できます。ユーザーセグメントはプログラム終了時に自動的に解放されますが、システムセグメントはプログラム側で明示的に解放しない限り解放されません。通常、プログラムでは「ユーザーセグメント」を確保してください。

RAMセグメントへのアクセスは、指定したセグメントに対してバイトの読み書きを行う「`RD_SEG`」および「`WR_SEG`」ルーチンを介して行われます。「`CAL_SEG`」および「`CALLS`」ルーチンを使用すると、現在のMSXシステムにおけるスロット間コール（インタースロットコール）と非常によく似た方法で、セグメント間コールを行うことができます。

特定のページにセグメントを明示的に割り当てたり（マップ）、特定のページに現在どのセグメントが割り当てられているかを調べたりするルーチンも用意されています。ページ（ページ0〜3）をレジスタ `HL` に設定したアドレスの上位2ビットで指定するルーチン（「`PUT_PH`」および「`GET_PH`」）と、アクセスするページごとに用意された専用のルーチン（「`GET_Pn`」および「`PUT_Pn`」）があります。これらのルーチンは極めて高速に動作するため、これらを使用することによるプログラムのパフォーマンス低下はほとんどありません。

なお、マッパーサポートルーチンやその他すべてのシステム変数が含まれているため、**ページ3は絶対に書き換えてはなりません。** また、割り込み処理やスロット切り替えのエントリーポイントが含まれているため、**ページ0を書き換える場合は細心の注意を払う必要があります。** ページ1およびページ2は自由に書き換え可能です。

いずれのマッパーサポートルーチンも、現在のスロット選択状態には一切影響を与えません。例えば「`PUT_P1`」を呼び出した際、指定したRAMセグメントが実際にアドレス `4000h`〜`7FFFh` に現れるのは、マッパースロットがそのページ1において選択されている場合のみです。「`RD_SEG`」および「`WR_SEG`」ルーチンは、現在のページ0またはページ1におけるページングやスロット選択の状態に関係なく、常に該当のRAMセグメントにアクセスしますが、呼び出し時に**マッパーRAMスロットがページ2で選択されている必要があります。** これは、ルーチン内でのスロット切り替えを省いて処理を高速化するためです。また、スタックがページ2にあってはなりません。これらのルーチンを実行すると、割り込み禁止（DI）状態で復帰します。

### 5.4 セグメントの確保と解放
以下の2つのルーチンを呼び出すことで、セグメントの確保や解放を行えます。`AF` および `BC` 以外のすべてのレジスタは保存されます。エラーが発生した場合は、復帰時にキャリーフラグ（C）がセットされます。スロットの選択状態やRAMページングがどのような状態であってもこれらのルーチンを呼び出すことができ、いずれの状態も保存されます。また、呼び出し時に**スタックがページ0またはページ2にあってはなりません。**

プログラムは、自身で明示的に確保したセグメント（および基本64KBを構成する4つの初期セグメント）以外のセグメントを絶対に使用してはならず、解放したセグメントへのアクセスも継続してはなりません。

セグメントはユーザーセグメントまたはシステムセグメントとして確保できます。唯一の違いは、ユーザーセグメントはプログラム終了時に自動的に解放されるのに対し、システムセグメントは自動解放されない点です。通常、一時的な処理のためにメモリを使用する場合はユーザーセグメントを確保してください。ユーザーセグメントは常に番号の小さい空きセグメントから順に確保され、システムセグメントは番号の大きい空きセグメントから順に確保されます。

「セグメントの確保」時のエラーは、通常、空きセグメントが存在しないことを示しますが、レジスタ `A` や `B` に無効なパラメータを渡した場合にも発生します。「セグメントの解放」時のエラーは、指定されたセグメント番号が存在しないか、すでに解放されていることを示します。

#### `ALL_SEG`（セグメントの確保）
* **パラメータ:**
  * `A` = `0` : ユーザーセグメントを確保  
    `A` = `1` : システムセグメントを確保
  * `B` = `0` : プライマリーマッパーから確保  
    `B` ≠ `0` : スロットアドレス `FxxxSSPP` のマッパーから確保（`0` の場合はプライマリー）  
    * `xxx` = `000` : 指定されたスロットからのみ確保
    * `xxx` = `001` : 指定された以外のスロットから確保
    * `xxx` = `010` : 指定されたスロットからの確保を試み、失敗した場合は他のスロットから試行
    * `xxx` = `011` : 指定された以外のスロットからの確保を試み、失敗した場合は指定スロットから試行
* **結果:**
  * キャリーセット (C)  ⇒ 空きセグメントなし（エラー）
  * キャリークリア (NC) ⇒ 確保成功
  * `A` = 新しいセグメント番号
  * `B` = 確保されたマッパースロットのスロットアドレス（呼び出し時に `B=0` だった場合は `0`）

#### `FRE_SEG`（セグメントの解放）
* **パラメータ:**
  * `A` = 解放するセグメント番号
  * `B` = `0` : プライマリーマッパー  
    `B` ≠ `0` : プライマリー以外のマッパー
* **結果:**
  * キャリーセット (C)  ⇒ エラー
  * キャリークリア (NC) ⇒ 正常解放

### 5.5 セグメント間リード／ライト
任意のマッパーRAMセグメントに対して、1バイトの読み書きを行います。呼び出し手順は、MSXシステムROMが提供するスロット間（インターシステム）のリード／ライトルーチンと非常によく似ています。レジスタ `AF` を除くすべてのレジスタは保存され、セグメント番号が有効かどうかのチェックは行われません。

アドレス（`HL`）の上位2ビットは無視され、データは常にページ2を介して読み書きされます。セグメント番号が示す16KBセグメントはどのページにも割り当て可能ですが、ルーチンはページ0やページ1の現在のページングやスロット選択状態に関係なく、常に正しいセグメントにアクセスします。ただし、呼び出し時に**マッパーRAMスロットがページ2で選択されている必要があります。** これにより、ルーチン内で余分なスロット切り替えを排除し、高速化を図っています。また、スタックがページ2に存在してはなりません。これらのルーチンは復帰時に割り込みを禁止します。

#### `RD_SEG`（セグメント間リード）
* **パラメータ:**
  * `A` = 読み込み元セグメント番号
  * `HL` = セグメント内のアドレス
* **結果:**
  * `A` = 該当アドレスから読み込まれた値
  * 他のすべてのレジスタは保存されます。

#### `WR_SEG`（セグメント間ライト）
* **パラメータ:**
  * `A` = 書き込み先セグメント番号
  * `HL` = セグメント内のアドレス
  * `E` = 書き込む値
* **結果:**
  * `A` = 破壊されます。
  * 他のすべてのレジスタは保存されます。

### 5.6 セグメント間コール
セグメント間コールを実行するための2つのルーチンが提供されています。これらは、MSXシステムROMが提供する2つのスロット間コールルーチン（`CALSLT`）をモデルに作成されており、使用方法も同様です。

呼び出すセグメントが実際に存在するかどうかのチェックは行われないため、事前に存在することを確認する責任はユーザーにあります。呼び出されたセグメントは指定のアドレスページにページインされますが、ルーチン側でスロット選択の変更は一切行われないため、そのページでマッパースロットが有効になっていることを確認する責任はユーザーにあります（これも高速動作を優先するための仕様です）。

このルーチンを使用してページ3へのセグメント間コールを試みることはできません。もし実行された場合、ページ3は決して変更してはならないため、ページングを変更することなく単に指定アドレスを直接コールします。ページ0を呼び出す場合は、割り込み処理やその他のエントリーポイントとの干渉を避けるために注意が必要です。また、コールによってスタック領域がページアウトされないように配慮する必要があります。

これらのルーチンは、スロット間コールとは異なり、呼び出し先に制御を移す前に**自動的に割り込みを禁止しません。** そのため、呼び出し先ルーチン内で割り込みフラグが変更されない限り、呼び出し元と同じ割り込み状態のまま戻ってきます。

内部処理でレジスタ `IX`、`IY`、および裏レジスタ `AF'`、`BC'`、`DE'`、`HL'` を使用するため、これらをパラメータの受け渡しに使用することはできません。これらのレジスタはルーチンおよび呼び出し先によって値が破壊されます。その他のレジスタ（`AF`、`BC`、`DE`、`HL`）は、そのまま呼び出し先ルーチンに渡され、呼び出し先からそのまま呼び出し元へ戻されます。

#### `CAL_SEG`
* **パラメータ:**
  * `IY` = 呼び出し先セグメント番号
  * `IX` = 呼び出し先アドレス
  * `AF`、`BC`、`DE`、`HL` は呼び出し先ルーチンにそのまま渡されます。
  * その他のレジスタは書き換えられます。
* **結果:**
  * `AF`、`BC`、`DE`、`HL`、`IX`、`IY` は呼び出し先から戻された値になります。その他のレジスタは破壊されます。

#### `CALLS`
* **パラメータ:**
  * `AF`、`BC`、`DE`、`HL` は呼び出し先ルーチンにそのまま渡されます。
  * その他のレジスタは書き換えられます。
* **呼び出し手順:**
  ```asm
  CALL  CALLS
  DB    SEGMENT   ; 呼び出し先セグメント
  DW    ADDRESS   ; 呼び出し先アドレス
  ```
* **結果:**
  * `AF`、`BC`、`DE`、`HL`、`IX`、`IY` は呼び出し先から戻された値になります。その他のレジスタは破壊されます。

### 5.7 ダイレクトページングルーチン
ハードウェアを直接操作することなく、現在のページング状態を操作するためのルーチンです。これらのルーチンを使用することで、将来ハードウェアの詳細に変更があった場合でも、互換性を保つことができます。ルーチンは極めて高速です。

4つの各ページレジスタに対して直接読み書きを行うルーチンが用意されています。セグメント番号の妥当性チェックは行われません。なお、レジスタに書き込まれた値は同時にメモリ上にも保存され、現在のレジスタ値を取得する要求に対しては、ハードウェアのレジスタ値を直接読み取るのではなく、メモリ上に保存されている値が返されます。これは、システム内に複数のマッパーレジスタが存在する場合に発生するハードウェアの競合エラーを回避するためです。ユーザーは常にこれらのルーチンを介してメモリーマッパーを操作する必要があります。

「`GET`」ルーチンは、実際の物理レジスタを読み取ることなく、内部で管理しているレジスタのイメージ値を返します。これにより、例えば「`PUT_P1`」で設定したセグメント番号は、その後の「`GET_P1`」呼び出しによって確実に取得できます。ハードウェアのレジスタを直接読み取ると、セグメント番号の上位ビットなどが保持されない場合があり、異なる値が返される可能性があります。

「`PUT_P3`」ルーチンも用意されていますが、実際にはダミー（何もしないルーチン）であり、ページ3のレジスタを書き換えることはありません。ページ3の変更は決して行ってはならないためです。「`GET_P3`」ルーチンは期待通りに動作し、現在ページ3にマップされているセグメント番号を調べることができます。

もう1つのペア（「`GET_PH`」および「`PUT_PH`」）も同じ機能を持ちますが、こちらはレジスタ `H` の上位2ビットによって対象ページを指定します。これは、レジスタ `HL` にアドレスが格納されている場合に便利で、このルーチンを実行してもレジスタ `HL` の内容は破壊されません。「`PUT_PH`」も、ページ3のレジスタを決して書き換えることはありません。

#### `PUT_Pn`
* **パラメータ:**
  * `n` = `0`、`1`、`2`、`3` （対象ページを指定）
  * `A` = 設定するセグメント番号
* **結果:** なし。すべてのレジスタは保存されます。

#### `GET_Pn`
* **パラメータ:**
  * `n` = `0`、`1`、`2`、`3` （対象ページを指定）
* **結果:**
  * `A` = 現在マップされているセグメント番号
  * 他のすべてのレジスタは保存されます。

#### `PUT_PH`
* **パラメータ:**
  * `H` = 対象アドレスの上位バイト
  * `A` = 設定するセグメント番号
* **結果:** なし。すべてのレジスタは保存されます。

#### `GET_PH`
* **パラメータ:**
  * `H` = 対象アドレスの上位バイト
* **結果:**
  * `A` = 現在マップされているセグメント番号
  * 他のすべてのレジスタは保存されます。

これらの直接ページングルーチンを使用してページング状態を変更する前に、プログラムは必ず「`GET_Pn`」ルーチンを呼び出して**初期状態の4つのセグメントを調べ、保存しておくべきです。** システムの将来のバージョンでこれらの初期セグメント値が変更される可能性があるため、特定の固定値を前提にした設計にしないでください。

## 6. エラー
新設されたすべてのMSX-DOS 2ファンクション（ファンクションコード `40h` 以上）は、レジスタ `A` に「エラーコード」を返します。成功した場合は `0` になります。エラーが発生した場合は、`0` 以外の値となり、その値によってエラーの具体的な内容を特定できます。

MSX-DOS 2はファンクションコールの復帰直前に `OR A` 命令を実行するため、トランジェントプログラムでは `CALL 5` の直後に `JR NZ` 命令を配置してエラーの発生を判定するのが一般的です。多くのプログラムでは、このエラー分岐先でエラーコードをレジスタ `B` にロードし、「エラーコード付き終了」ファンクションを呼び出します。これによりエラーコードがコマンドインタプリタに返され、対応する適切なエラーメッセージが出力されます。

また、プログラム自身が「エラーコード解説（Explain Error Code）」ファンクションを呼び出して、MSX-DOS 2ファンクションから返されたエラーコードに対する具体的なメッセージテキストを取得することもできます。

エラーコードの値は `FFh` から始まり、降順（値が小さくなる方向）に定義されています。`40h` 未満の値は「ユーザーエラー」用に確保されており、システムによって使用されることはありません。プログラムが独自のカスタムエラーを定義して呼び出し元に返すために使用できます。なお、`20h` 未満のユーザーエラーがコマンドインタプリタに返された場合は、エラーメッセージは表示されません。

「エラーコード解説」ファンクションを呼び出した際、指定されたエラーコードに対応する登録メッセージが存在しない場合、エラー番号 `<n>` に応じて `System error <n>` または `User error <n>` という汎用文字列が返されます。

以下は、現在定義されているすべてのエラー番号、対応するメッセージ、およびその意味の一覧です。あわせて、ソースファイル等でシンボルとして使用される「ニーモニック（Mnemonic）」も記載しています。

### 6.1 ディスクエラー
このグループのエラーは、通常、ディスクエラーハンドリングルーチンに渡されるものです。デフォルトでは、これらは「Abort, Retry（中止、再試行）」エラーとして報告されます。これらのエラー（「フォーマットエラー」を除く）は、エラーハンドリングルーチンに渡されるため、通常のBDOSコールの戻り値としては直接返されません。

#### `Incompatible disk` (`.NCOMP`, `0FFh`)
ディスクをそのドライブでアクセスすることができません（例：片面ドライブに両面ディスクを挿入した場合など）。

#### `Write error` (`.WRERR`, `0FEh`)
ディスクへの書き込み中に、一般的なエラーが発生しました。

#### `Disk error` (`.DISK`, `0FDh`)
ディスクに関する一般的な不明なエラーが発生しました。

#### `Not ready` (`.NRDY`, `0FCh`)
ディスクドライブが応答しません。通常、ドライブにディスクが入っていないことを意味します。

#### `Verify error` (`.VERFY`, `0FBh`)
ベリファイ（書き込み確認）機能が有効な状態において、セクターを書き込んだ後に正常に読み戻すことができませんでした。

#### `Data error` (`.DATA`, `0FAh`)
CRC（巡回冗長検査）エラーチェックによって不良が検出されたため、セクターを読み取れませんでした。通常、ディスクの物理的な損傷を示します。

#### `Sector not found` (`.RNF`, `0F9h`)
ディスク上で要求されたセクターが見つかりませんでした。通常、ディスクの物理的な損傷を示します。

#### `Write protected disk` (`.WPROT`, `0F8h`)
ライトプロテクト（書き込み禁止）タブが貼られたディスクに対して、書き込み処理を試みました。

#### `Unformatted disk` (`.UFORM`, `0F7h`)
ディスクがフォーマットされていないか、異なる記録形式のディスクです。

#### `Not a DOS disk` (`.NDOS`, `0F6h`)
他のオペレーティングシステム用（DOS以外）にフォーマットされたディスクであるため、MSX-DOSからアクセスできません。

#### `Wrong disk` (`.WDISK`, `0F5h`)
MSX-DOSがアクセスしている最中に、ディスクが差し替えられました。正しいディスクに戻す必要があります。

#### `Wrong disk for file` (`.WFILE`, `0F4h`)
ファイルがオープンされている最中に、ディスクが差し替えられました。正しいディスクに戻す必要があります。

#### `Seek error` (`.SEEK`, `0F3h`)
ディスク上の指定されたトラックを見つけることができませんでした。

#### `Bad file allocation table` (`.IFAT`, `0F2h`)
ディスク上のFAT（ファイルアロケーションテーブル）が破損しています。`CHKDSK` コマンド等を使用してデータを復旧できる可能性があります。

#### （エラーメッセージなし） (`.NOUPB`, `0F1h`)
このエラーは、MSX-DOS内部のディスク交換処理（ディスクチェンジハンドリング）で常にトラップされるため、対応するユーザーメッセージはありません。

#### `Cannot format this drive` (`.IFORM`, `0F0h`)
フォーマットが許可されていないドライブ（例：RAMディスクなど）をフォーマットしようとしました。

---

### 6.2 MSX-DOSファンクションエラー
これらのエラーは、通常のMSX-DOSファンクションコールから返されます。各エラーの発生条件の詳細は、ファンクション仕様書を参照してください。

#### `Internal error` (`.INTER`, `0DFh`)
内部エラー。通常は発生しません。

#### `Not enough memory` (`.NORAM`, `0DEh`)
16KBのシステムデータセグメントにおいて、MSX-DOSの管理メモリが不足しました。セクターバッファの数を減らすか、いくつかの環境変数を削除してください。また、RAMディスクを作成するための空きセグメントが不足している場合にも発生します。

#### `Invalid MSX-DOS call` (`.IBDOS`, `0DCh`)
無効なファンクション番号を使用してMSX-DOSコールが行われました。通常の無効なコールではエラーは返されませんが、「直前のエラーコードの取得（Get previous error code）」ファンクションを呼び出した際にこのエラーが返されることがあります。

#### `Invalid drive` (`.IDRV`, `0DBh`)
指定されたドライブ番号、またはパス文字列内のドライブ文字が、現在のシステムに存在しません。

#### `Invalid filename` (`.IFNM`, `0DAh`)
ファイル名文字列の構文が正しくありません。このエラーはファイル名単体の文字列に対してのみ発生し、パスを含む全体文字列に対しては発生しません。

#### `Invalid pathname` (`.IPATH`, `0D9h`)
パス文字列を受け取るすべてのファンクションで発生する可能性があります。パス文字列の構文に誤りがあることを示します。

#### `Pathname too long` (`.PLONG`, `0D8h`)
パス文字列を受け取るすべてのファンクションで発生する可能性があります。指定された完全なパス（カレントディレクトリを含む）が 63文字を超えていることを示します。

#### `File not found` (`.NOFIL`, `0D7h`)
ディスク上で指定されたファイルが見つからない場合に、ファイルを検索するすべてのファンクションから返されます。ディレクトリが指定されて見つからなかった場合にもこのエラーが返されます。それ以外のケースでは、後述の `.NODIR` エラーが返されます。

#### `Directory not found` (`.NODIR`, `0D6h`)
パス文字列の中で指定された中間ディレクトリが見つかりませんでした。

#### `Root directory full` (`.DRFUL`, `0D5h`)
「ファイル作成」または「移動」ファンクションにおいて、ルートディレクトリに新しいエントリを追加しようとしましたが、ルートディレクトリの容量がすでに上限に達しています。ルートディレクトリは拡張することができません。

#### `Disk full` (`.DKFUL`, `0D4h`)
書き込み処理中に、ディスクの空き容量が不足しました。また、ディスクが完全に満杯の状態で、サブディレクトリを新規作成、または拡張しようとした場合にも発生します。

#### `Duplicate filename` (`.DUPF`, `0D3h`)
「名前変更」または「移動」ファンクションにおいて、変更先（移動先）のディレクトリに、指定したファイル名がすでに存在しています。

#### `Invalid directory move` (`.DIRE`, `0D2h`)
サブディレクトリを、自分自身の下位フォルダ（子孫ディレクトリ）に移動しようとしました。これを行うと、ディレクトリ構造の中に孤立したループが発生してしまうため、禁止されています。

#### `Read only file` (`.FILRO`, `0D1h`)
「読込専用（Read only）」属性が設定されているファイルに対して、書き込みや削除を行おうとしました。

#### `Directory not empty` (`.DIRNE`, `0D0h`)
空ではない（ファイルや子ディレクトリが含まれている）サブディレクトリを削除しようとしました。

#### `Invalid attributes` (`.IATTR`, `0CFh`)
ファイルの属性を不適切な方法で変更しようとした場合、あるいはサブディレクトリにしか適用できない操作をファイルに対して行おうとした場合に発生します。また、ボリューム名を表すFIBの不適切な使用によっても発生します。

#### `Invalid . or .. operation` (`.DOT`, `0CEh`)
サブディレクトリ内の特殊エントリである `.`（カレント）や `..`（親）に対して、名前変更や移動など、許可されていない不正な操作を行おうとしました。

#### `System file exists` (`.SYSX`, `0CDh`)
既存のシステムファイルと同名のファイル、またはサブディレクトリを作成しようとしました。システムファイルは自動的には上書き削除されません。

#### `Directory exists` (`.DIRX`, `0CCh`)
既存のサブディレクトリと同名のファイル、またはサブディレクトリを作成しようとしました。サブディレクトリは自動的には削除されません。

#### `File exists` (`.FILEX`, `0CBh`)
既存のファイルと同名のサブディレクトリを作成しようとしました。サブディレクトリ作成の際に、既存のファイルが自動的に削除されることはありません。

#### `File already in use` (`.FOPEN`, `0CAh`)
すでに別のファイルハンドルがオープンされているファイルに対して、そのファイルハンドルを経由せずに、削除、名前変更、移動、属性変更、日時の変更などを行おうとしました。

#### `Cannot transfer above 64K` (`.OV64K`, `0C9h`)
ディスク転送領域（DTA）が `0FFFFh` の境界を超えて配置されようとしました。

#### `File allocation error` (`.FILE`, `0C8h`)
ファイルのクラスターチェーン情報が破損しています。`CHKDSK` を使用して、可能な限りファイルを復旧してください。

#### `End of file` (`.EOF`, `0C7h`)
ファイルポインタがすでにファイルの末尾（EOF）かそれ以降を指している状態で、さらに読み込みを行おうとしました。

#### `File access violation` (`.ACCV`, `0C6h`)
ファイルハンドルに設定されているアクセス権に反する読み書きを試みました。いくつかの標準ファイルハンドルは、「読込専用」または「書込専用」モードでオープンされています。

#### `Invalid process id` (`.IPROC`, `0C5h`)
「ジョイン（Join）」ファンクションに渡されたプロセスIDが無効です。

#### `No spare file handles` (`.NHAND`, `0C4h`)
すべてのファイルハンドルが使用されている状態で、新たにオープンまたは作成を行おうとしました。現バージョンでは最大 64個のファイルハンドルを使用できます。

#### `Invalid file handle` (`.IHAND`, `0C3h`)
指定されたファイルハンドルの値が、許容されている最大値を超えています。

#### `File handle not open` (`.NOPEN`, `0C2h`)
指定されたファイルハンドルは、現在オープンされていません。

#### `Invalid device operation` (`.IDEV`, `0C1h`)
デバイス用のファイルハンドルやFIBに対して、検索や移動など、デバイスには適用できない無効な操作を行おうとしました。

#### `Invalid environment string` (`.IENV`, `0C0h`)
環境変数の名前に、使用できない文字が含まれています。

#### `Environment string too long` (`.ELONG`, `0BFh`)
環境変数の名前、または値の文字列が、許容最大長である 255文字を超えているか、プログラム側が用意したバッファに収まりきりません。

#### `Invalid date` (`.IDATE,` `0BEh`)
「日付の設定」ファンクションに渡された日付パラメータが不正です。

#### `Invalid time` (`.ITIME`, `0BDh`)
「時刻の設定」ファンクションに渡された時刻パラメータが不正です。

#### `RAM disk (drive H:) already exists` (`.RAMDX`, `0BCh`)
すでにRAMディスクが存在する状態で、重ねてRAMディスクを作成しようとしました。

#### `RAM disk does not exist` (`.NRAMD`, `0BBh`)
現在RAMディスクが存在しない状態で、RAMディスクを削除しようとしました。なお、存在しないRAMディスクドライブ（通常はH:）にアクセスしようとした場合は、前述の `.IDRV`（無効なドライブ）エラーが返されます。

#### `File handle has been deleted` (`.HDEAD`, `0BAh`)
該当するファイルハンドルが指していたファイル自体が削除されたため、そのファイルハンドルは使用できなくなりました。

#### （内部エラー） (`.EOL`, `0B9h`)
内部エラー。通常は発生しません。

#### `Invalid sub-function number` (`.ISBFN`, `0B8h`)
IOCTLファンクション（ファンクション `4Bh`）に渡されたサブファンクション番号が無効です。

---

### 6.3 プログラム終了エラー
以下のエラーはシステム内部で生成され、強制終了（アボート）ルーチンに渡されるものです。通常のファンクションコールの戻り値として返されることはありません。なお、アボートルーチンには、プログラム自身が「エラーコード付き終了」ファンクションを呼び出した際のエラーコードもそのまま渡されます。

#### `Ctrl-STOP pressed` (`.STOP`, `09Fh`)
キャラクターI/Oを含むシステム内のほぼすべての場所で、`Ctrl-STOP` キーの押下が検出されました。

#### `Ctrl-C pressed` (`.CTRLC`, `09Eh`)
ステータス確認を伴うキャラクター処理ファンクションにおいて、`Ctrl-C` キーの押下が検出されました。

#### `Disk operation aborted` (`.ABORT`, `09Dh`)
ディスクエラーに対して、ユーザーによる指示、またはシステムによる自動処理によって、ディスク操作が中止（アボート）されました。アボートルーチンのレジスタ `B` には、原因となった元のディスクエラーコードがセカンダリエラーコードとして渡されます。

#### `Error on standard output` (`.OUTERR`, `09Ch`)
標準出力チャンネルにおいて、キャラクターファンクション（ファンクション `01h`〜`0Bh`）によるアクセス中にエラーが発生しました。元のエラーコードは、アボートルーチンのレジスタ `B` にセカンダリエラーコードとして渡されます。通常、このエラーはプログラムが標準ファイルハンドルを変更している場合にのみ発生します。

#### `Error on standard input` (`.INERR`, `09Bh`)
標準入力チャンネルにおいて、キャラクターファンクション（ファンクション `01h`〜`0Bh`）によるアクセス中にエラーが発生しました。元のエラーコードは、アボートルーチンのレジスタ `B` にセカンダリエラーコードとして渡されます。最も代表的なエラーは `.EOF`（エンドオブファイル）です。通常、このエラーはプログラムが標準ファイルハンドルを変更している場合にのみ発生します。

---

### 6.4 コマンドエラー
これらのエラーは、MSX-DOSファンクションコールから返されるものではなく、コマンドインタプリタによって使用されます。トランジェントプログラムから呼び出し元にエラーを返す際にも有用であるため、ここに記載されています。コマンドインタプリタから見た各エラーの具体的な意味については、『コマンド仕様書』を参照してください。

#### `Wrong version of COMMAND` (`.BADCOM`, `08Fh`)
`COMMAND2.COM` が自身のトランジェント部をディスクからロードしましたが、そのチェックサムが一致しませんでした。

#### `Unrecognized command` (`.BADCM`, `08Eh`)
入力されたコマンドは内部コマンドではなく、かつ同名の `.COM` または `.BAT` ファイルもディスク上に見つかりませんでした。

#### `Command too long` (`.BUFUL`, `08Dh`)
バッチファイル（`.BAT`）内のコマンドが、1行の上限である 127文字を超えました。

#### （エラーメッセージなし） (`.OKCMD`, `08Ch`)
コマンドラインから渡されたコマンドを実行した後に、`COMMAND2.COM` が内部で使用するエラーコードです。

#### `Invalid parameter` (`.IPARM`, `08Bh`)
コマンドに渡されたパラメータが、数値の範囲外など、何らかの理由で無効です。

#### `Too many parameters` (`.INP`, `08Ah`)
コマンドが必要とするすべてのパラメータを解析した後も、コマンドライン上に余分な文字列（区切り文字以外の文字）が残っています。

#### `Missing parameter` (`.NOPAR`, `089h`)
パラメータが指定されるべき箇所で、コマンドラインの末尾（行末）に達しました。

#### `Invalid option` (`.IOPT`, `088h`)
コマンドラインにおいて、`/`（スラッシュ）の後に指定されたオプション文字が、そのコマンドには存在しません。

#### `Invalid number` (`.BADNO`, `087h`)
数値が指定されるべき場所に、数字以外の文字が指定されました。

#### `File for HELP not found` (`.NOHELP`, `086h`)
ヘルプファイルが見つからないか、指定されたヘルプのキーワードが無効です。

#### `Wrong version of MSX-DOS` (`.BADVER`, `085h`)
コマンドインタプリタはこのエラーを直接使用せず、独自のエラーメッセージを出力します。しかし、プログラム自身がこのエラーを返せるように、エラーコードが定義されています。

#### `Cannot concatenate destination file` (`.NOCAT`, `084h`)
`CONCAT` コマンドにおいて、結合先（出力先）のファイルが、結合元（入力元）のファイル指定に合致してしまっています。

#### `Cannot create destination file` (`.BADEST`, `083h`)
`COPY` コマンドにおいて、作成しようとしたコピー先ファイルが、コピー元のファイルのいずれか（あるいは現在すでに使用中の他のファイル）を上書きしてしまいます。

#### `File cannot be copied onto itself` (`.COPY`, `082h`)
`COPY` コマンドにおいて、指定されたコピー先ファイルを作成すると、コピー元のファイルをそのまま上書きしてしまいます（自分自身へのコピー）。

#### `Cannot overwrite previous destination file` (`.OVDEST`, `081h`)
`COPY` コマンドにおいて、コピー元にワイルドカード（曖昧なファイル名）を指定しているにもかかわらず、コピー先としてワイルドカードを使用していない単一のファイル名（かつディレクトリでもデバイスでもないもの）が指定されました。
