# Nextor 2.1 Alpha 2

* **著者**: Konamiman (2015年3月)
* **公式サイト**: [http://www.konamiman.com#nextor](http://www.konamiman.com#nextor)

---

## 1. Alpha 2 の新機能

Nextor 2.1 Alpha 1 には、Nextor 2.0 の全機能に加え、**ディスクイメージファイルをドライブレターにマウントする機能**が追加されました。ディスクイメージファイルをマウントすると、通常の MSX-DOS / MSX BASIC のコマンドやツールを使用して、その中に含まれるファイルやディレクトリにアクセスできるようになります。この機能については [2. ファイルのマウント](#2-ファイルのマウント) で説明します。

さらに、Nextor 2.1 Alpha 2 では新たな機能が追加されました。それは、ディスクイメージファイルを実際のフロッピーディスクのように使用して、コンピュータを**ディスクエミュレーションモード**で起動する機能です。これにより、Nextor を使用して、お気に入りの MSX-DOS 2 非対応ゲームをプレイできるようになります。この機能については [3. ディスクエミュレーションモード](#3-ディスクエミュレーションモード) で説明します。

## 2. ファイルのマウント

### 2.1. ファイルのマウント方法

ファイルは、`COMMAND2.COM` プロンプトからアップデート版の `MAPDRV.COM` ツールを使用するか、BASIC プロンプトから `CALL MAPDRV` コマンドを使用してマウントします。

#### MAPDRV.COM の構文
```text
MAPDRV <drive> <file> [/ro]
```
* **実行例 (G: ドライブに TOOLS.DSK ファイルをマウントする場合):**
  ```text
  MAPDRV G: TOOLS.DSK
  ```
* **読み取り専用モード (`/ro`):**
  「`/ro`」を追加すると、ファイルは読み取り専用モードでマウントされます。このとき、マウントされたドライブに書き込みを行おうとすると「Write protected disk（書き込み禁止ディスク）」エラーが発生します。

#### CALL MAPDRV の構文
```text
CALL MAPDRV(<drive>, <file> [,0|1])
```
* **実行例 (G: ドライブに TOOLS.DSK ファイルをマウントする場合):**
  ```text
  CALL MAPDRV("G:", "TOOLS.DSK")
  ```
* **読み取り専用モード (`[,0|1]`):**
  ファイル名の後ろに「`,1`」を追加すると、ファイルは読み取り専用モードでマウントされます。

> **注意:** ディスクイメージファイルに「読み取り専用」属性が設定されている場合、`/ro` や `,1` などの修飾子が指定されていなくても、常に読み取り専用モードでマウントされます。

#### アンマウントの方法
ファイルをアンマウントするには、マウントされているドライブに対して別のマッピングを設定します（通常のパーティションマッピングを設定するか、単にドライブの割り当てを解除します）。
```text
MAPDRV <drive> U
CALL MAPDRV(<drive>, -1)
```

### 2.2. ルールと制限事項

マウント可能なディスクイメージファイルは、**サイズが 512 バイト以上、最大 32 MByte** である必要があります。また、ファイル内には適切な FAT ファイルシステムがすでに含まれている必要があります（マウントされたドライブに対して `FORMAT` コマンドを実行することはできません）。

また、以下の制限事項が適用されます：

* **パーティションの禁止:** ファイルにパーティションを含めることはできません。含まれるファイルシステムは、ファイルの先頭から開始されている必要があります。
* **同一ドライブでのマウント禁止:** ファイル自体が存在するのと同じドライブに、そのファイルをマウントすることはできません。
  ```text
  MAPDRV A: A:TOOLS.DSK --> Error
  ```
* **複数ドライブでの重複マウント禁止:** 同じファイルを同時に 2 つのドライブにマウントすることはできません。
  ```text
  MAPDRV B: TOOLS.DSK
  MAPDRV C: TOOLS.DSK --> Error
  ```
* **再帰的なマウントの禁止:** マウントされたディスクイメージファイル内にあるファイルを、さらにマウント（ネスト）することはできません。
  ```text
  MAPDRV B: TOOLS.DSK
  MAPDRV C: B:FILE.DSK --> Error
  ```
* **マウント中ドライブの変更禁止:** ドライブ内に現在マウントされているファイルが 1 つ以上存在する場合、そのドライブのマッピング状態を変更することはできません。
  ```text
  MAPDRV B: A:TOOLS.DSK
  MAPDRV A: U --> Error
  ```
* **マウント中ファイルへの直接アクセスの禁止:** マウントされているファイルを開いたり、変更（名前変更、移動、削除、上書き、属性変更）したりすることはできません。
  ```text
  MAPDRV B: TOOLS.DSK
  TYPE TOOLS.DSK --> Error
  ECHO HELLO > TOOLS.DSK --> Error （以下の「既知のバグ」を参照）
  REN TOOLS.DSK X.DSK --> Error
  MOVE TOOLS.DSK SOMEDIR\ --> Error
  DEL TOOLS.DSK --> Error
  ATTRIB +R TOOLS.DSK --> Error
  ```

### 2.3. ファンクションコールの変更

#### `_MAPDRV` ファンクションコール (7Ch)
ファイルのマウントを可能にするために拡張されました。入力パラメータは以下の通りです：

```text
B  = 3
HL = ファイル名へのパス、または FIB
D  = 0：デフォルトマウント（ファイルに読み取り専用属性がない限り、書き込み可能）
     1：読み取り専用マウントを強制
```

#### `_GDLI` ファンクションコール (79h)
ファイルがマウントされているドライブのデータバッファに、以下の情報を返すようになりました：

```text
+0: 3
+1: マウントされているファイルが存在するドライブ（0 = A:、など）
+2: フラグ：ファイルが読み取り専用モードでマウントされている場合は 1、それ以外は 0
+3: 0（今後のフラグ用に予約）
+4: 表示可能な形式のファイル名（最大12文字、末尾にヌル文字を含む）
```

※詳細は「Nextor Programmers Reference（プログラマーズリファレンス）」を参照してください。

---

### 2.4. 新しいエラーコード

2つの新しいエラーコードが導入されました：

* **「File is mounted（ファイルはマウントされています）」** (`.FMNT`, DOSエラーコード `B2h`, BASICエラーコード `80`)
  マウントされているファイルを開こうとしたり、変更しようとしたりしたとき、またはルールで禁止されている操作を行ったときに発生します。
* **「Bad file size（不正なファイルサイズです）」** (`.BFSZ`, DOSエラーコード `B1h`, BASICエラーコード `81`)
  512バイト未満、または 32 MByte より大きいファイルをマウントしようとしたときに発生します。

---

### 2.5. 既知のバグ

「ファイルハンドル作成」ファンクションコール（`_CREATE`, `44h`）を介してマウントされたファイルを上書きしようとする（例: `ECHO HELLO > TOOLS.DSK` コマンドの実行など）と、実際には処理が成功してファイルが上書きされてしまいます。本来であれば「File is mounted」エラーが返されるべきです。

## 3. ディスクエミュレーションモード

### 3.1. ディスクエミュレーションモードの開始と終了方法

#### 開始方法
Nextor は、プライマリ Nextor コントローラが制御するデバイスのプライマリパーティションのルートディレクトリに **`NEXT_DSK.DAT`** というファイルを見つけると、ディスクエミュレーションモードで起動します。このファイルには、エミュレーションに使用されるディスクイメージファイルの情報が含まれています。

`NEXT_DSK.DAT` ファイルは、付属の **`EMUFILE.COM`** ツールを使用して作成します。ほとんどの場合は、以下を実行するだけで簡単に作成できます。
* `EMUFILE file1.dsk file2.dsk file3.dsk`
* `EMUFILE game\*.dsk`
* `EMUFILE game\`

※追加オプション等の情報は、パラメータなしで `EMUFILE` を実行して確認してください。

#### 終了（一時無効化）方法
ディスクエミュレーションモードを無効にして通常通り起動するには、**起動中に「`0`」キーを押し続けてください。** 次回起動時に再びエミュレーションモードに入らないようにするには、手動で `NEXT_DSK.DAT` ファイルを削除または名前変更する必要があります。

---

### 3.2. エミュレートするファイルの切り替え

1回のエミュレーションセッションで最大32個のディスクイメージファイルを指定できますが、**同時にアクティブにできるのは1つだけ**です。

* **切り替えキー:** `1`〜`9`（1番目から9番目のファイル）、および `A`〜`W`（それ以降のファイル、アルファベット順）。
* **切り替え手順:** コンピュータがファイルを読み込もうとしている（ディスクアクセスしている）間に、対応するキーを押します。これにより、ディスク交換がエミュレートされます。
  * *例:* 2枚組のゲームで、ディスク2への入れ替えを指示された場合、2番目のファイルを指す「`2`」キーと、ゲーム側の指示キー（スペースキーなど）を同時に押します。
* **GRAPHキーを使用した一時停止:** 
  ディスクアクセス中に **`GRAPH`** キーを押すと、CAPS ランプが点灯し、キーを離して目的のファイルキーを押すまでコンピュータが一時停止します。これは、BASIC プロンプトなどで直接キーを入力するとコマンド入力と干渉してしまう（例: `FILES` コマンド実行中にキーを押すと Syntax Error になる）のを防ぐのに便利です。

---

### 3.3. ルールと制限事項

* **コントローラ制限:** プライマリコントローラは、デバイスベースのドライバを備えた Nextor カーネルである必要があります。
* **配置制限:** `NEXT_DSK.DAT` ファイルとすべてのディスクイメージファイルは、プライマリコントローラが制御するデバイス内に配置する必要があります（異なるパーティションや異なる物理デバイス上にあっても構いません）。
* **セクタ依存:** `NEXT_DSK.DAT` には絶対セクタ情報が記録されるため、イメージファイルを移動すると使用できなくなります（ファイル名の変更も同様です）。使用する直前に作成することをお勧めします。
* **ファイル仕様:** ディスクイメージファイルは 512 バイト以上 32 MByte 以下で、パーティションを含まず、適切な FAT12 ファイルシステムが含まれている必要があります（エミュレーションモード内での `FORMAT` は動作しません）。
* **断片化禁止:** ディスクイメージファイルはデバイス上で**連続したセクタに配置（非断片化）**されている必要があります。
* **起動モード:** エミュレーションモードは常に **DOS 1 モードおよび Z80 モード**で開始されます。
  * *R800モードでの起動手順:* 起動中に `GRAPH` キーと「`2`」キーを同時に押し続け、CAPS ランプが点灯したら両キーを離して「`1`」キーを押します。
* **他コントローラの無効化:** エミュレーションモード開始時、プライマリ以外のすべての Nextor コントローラが無効になります。MSX-DOS カーネル（内蔵FDDなど）は自動的には無効になりませんが、起動中に **`SHIFT`** キーを押し続けることで強制的に無効化し、メモリを解放できます。
* **マッピング優先順位 (`NEXTOR.DAT` 併用時):**
  エミュレーションモードを開始するには、Nextor が `NEXTOR.DAT` よりも前に `NEXT_DSK.DAT` を検出する必要があります。そのため、`NEXT_DSK.DAT` を以下のいずれかの場所に配置してください：
  1. `NEXTOR.DAT` と同じパーティション（ルートディレクトリ内での相対的な位置は不問）
  2. 同じデバイス内の、より番号の小さいプライマリパーティション
  3. より番号の小さいデバイス

### 3.4. メモリの解放方法

システムに Nextor ドライブとフロッピーディスクドライブの両方が割り当てられるため、空きメモリ量が減少し、一部のゲームが正常に動作しない場合があります。以下の方法でメモリの空き容量を増やすことができます：

* **内蔵フロッピーの無効化:** 起動中に **`SHIFT`** キーを押して、内蔵フロッピーディスクドライブ（およびその他の MSX-DOS カーネル）を無効にします。
* **割当ドライブ数の削減:** 起動中に「**`5`**」キーを押して、Nextor が割り当てるドライブ数を「1つ」に制限します（複数デバイスが接続されている場合に有効）。
  * *5つ以上のイメージを使用している場合:* 起動中に CAPS ランプが点灯するまで **`GRAPH`+`5`** キーを押し続け、点灯したらキーを離して「`1`」キーを押します。

---

### 3.5. 既知のバグ

* `EMUFILE.COM` ツールは、ディスクイメージファイルが断片化（フラグメンテーション）されていないかの検証を行いません。
* プライマリ Nextor コントローラに複数のデバイス（例: MegaFlashROM SCC+ SD の2枚のSDカード等）が存在する場合、Nextor は追加のデバイスに対してダミーのドライブレターを割り当てます。MSX-DOS デバイスはこれらの後に割り当てられます。
  * *例（デバイスが3つの場合）:* A:（エミュレートイメージ）、B: / C:（ダミー）、D:（内蔵FDD）
  これらのダミードライブには FAT バッファ用のメモリは割り当てられません。

## 4. その他の有用な情報

> [!WARNING]
> **警告 (アルファ版について)**
> 本ソフトウェアはアルファ版です。徹底的なテストは行われておらず、バグが含まれている可能性があります。使用前に必ずデータのバックアップを行ってください。

> [!WARNING]
> **警告 (メディアの抜き差しについて)**
> ファイルをマウントした後は、そのファイルが含まれているメディア（SDカード等）を絶対に取り出したり交換したりしないでください。データの消失や予期しないシステム動作を引き起こす原因になります。

#### 起動キー仕様の変更 (2.1 alpha 2 以降)
* **`CTRL`**: 仮想のセカンドフロッピーディスクドライブを**有効**にします（キーを押さないと無効になります）。フロッピーディスクに関する `CTRL` キーの意味が、従来の MSX-DOS とは逆になります。
* **`5`**: 接続デバイス数に関わらず、Nextor カーネルが割り当てるドライブ数を1つだけに制限します（前述のダミードライブ問題を防止できます）。

#### その他の仕様
* フロッピーディスクエミュレーションモードでディスクイメージにアクセスしている間は、**CAPS LOCK ランプが点灯**します。
* `CALL MAPDRV` コマンドはディスクエミュレーションモード内では動作しません（仕様です）。
* アップデートされた `DRVINFO.COM` ツールおよび `CALL DRVINFO` コマンドは、マウントされたドライブのファイル名と元の保存先ドライブを以下のように表示します。
  ```text
  Drive G: is assigned to:
  File TOOLS.DSK on drive A: (read-only)
  ```
* 空のディスクイメージファイルを最も簡単に作成する方法は、Konamiman の MSX サイトから **`NestorDiskImageCreator`** をダウンロードして使用することです。
  * [NestorDiskImageCreator（ndicreat.lzh）](http://konamiman.com/msx/megascsi/ndicreat.lzh)
