本マニュアルは、MSX-DOS バージョン 2.20 が提供する MSX-DOS 関数コールについて詳細に説明するものです。


## 1. はじめに

本書は、MSX-DOS 2 の各関数コールについて詳細に解説しています。ファイルハンドル、ファイル情報（fileinfo）ブロック、環境文字列などのシステム機能全般について説明している「プログラムインターフェース仕様書」と併せてお読みください。

MSX-DOS の関数を呼び出すには、システムが実行される2つの異なる環境（MSX-DOS 環境とディスクBASIC環境）に対応した2種類の方法があります。MSX-DOS 環境下で実行されるトランジエントプログラムは、`CALL 00005h` 命令を使用して関数にアクセスする必要があります。一方、ディスクBASICやその他のMSXプログラムが、ディスクBASIC環境（通常はROMから実行）からシステムにアクセスする場合は、`CALL 0F37Dh` 命令を使用する必要があります。

`0F37Dh` を経由してシステムを呼び出す場合、特にエラー処理やアボート（中断）ルーチンに関して一部の制限があります。また、関数呼び出し時にマスターディスクROMがページ1にマッピングされるため、パラメータをページ1（4000h〜7FFFh）に配置して渡すことはできません（ディスクBASIC自体の処理である場合を除く）。各関数の説明において、必要に応じてこれらの違いについて言及しています。


## 2. 関数一覧

以下は関数コールの完全な一覧です。
- **CPM**: CP/M 2.2 の同等機能と互換性があることを示します。
- **MSX1**: MSX-DOS バージョン1と互換性があることを示します。
- **NEW**: MSX-DOS 2.xx で新しく追加された関数であることを示します。
- アスタリスク（`*`）は、ユーザー定義のディスクエラー通知ルーチン（関数 64h および 70h を参照）から安全に呼び出せる関数であることを示します。

## 3. 関数ごとの詳細定義

以下に、古い関数と新しい関数の両方を含む各 MSX-DOS 関数の詳細な仕様を示します。関数名の後ろの括弧内にあるラベル名は、`CODES.MAC` で定義されている公開シンボル名です。プログラムを作成する際は、極力これらのシンボル名を使用してください。

40h 未満の関数の多くは、具体的なエラーコードではなく、エラーフラグを返します。エラーフラグがセットされた場合、実際の詳細なエラー原因は「直前のエラーコードの取得（関数 65h）」を呼び出すことで取得できます。40h 以上の関数はすべて、Aレジスタに直接エラーコードを返します。様々な関数から共通して返される一般的なエラーについては「プログラムインターフェース仕様書」に記載されています。本仕様書では、それぞれの関数に特有の主なエラー条件について説明します。

ディスク上の情報を変更する関数の多くは、実行直後に自動的にディスクバッファをフラッシュ（ディスクへの即時書き込み）するわけではありません。そのため、関数呼び出しの直後にディスクが最新の状態に更新されているとは限りません。これには「ファイル作成」「書き込み」「削除」「名前変更」「属性変更」「日時変更」といったすべての関数が含まれます。書き込み処理の後に必ずバッファをフラッシュし、ディスク内容を確定させる関数は、「バッファのフラッシュ」「クローズ」「ハンドル固定 (Ensure)」のみです。


### 3.1 プログラムの終了 (00H)

```text
パラメータ:  C = 00H (_TERM0)
結果:        呼び出し元には戻りません
```

この関数は、終了コード 0 でプログラムを終了します。MSX-DOS 1 および CP/M との互換性のために提供されています。プログラムを終了する推奨される方法は、「エラーコードを指定して終了（関数 62h）」を使用し、正常終了であれば終了コードに 0 を渡す方法です。プログラム終了時に発生する処理の詳細については、関数 62h の説明および「プログラムインターフェース仕様書」を参照してください。この関数は、呼び出し元に戻ることはありません。


### 3.2 コンソール入力 (01H)

```text
パラメータ:  C = 01H (_CONIN)
結果:        L=A = キーボードからの入力文字
```

標準入力（ファイルハンドル 0 - 通常はキーボード）から1文字読み込み、それを標準出力（ファイルハンドル 1 - 通常は画面）にエコーバックします。入力可能な文字がない場合、文字が入力されるまで待機します。

「コンソールステータス（関数 0Bh）」で説明されている各種制御文字は、この関数内でもトラップされ、それぞれの制御目的に応じて処理されます。これらの制御文字が検出された場合は処理が実行された後、次の文字入力を待ちます。したがって、これらの制御文字がこの関数からユーザープログラムに直接返されることはありません。


### 3.3 コンソール出力 (02H)

```text
パラメータ:  C = 02H (_CONOUT)
             E = 出力する文字
結果:        なし
```

Eレジスタに渡された文字を標準出力（ファイルハンドル 1 - 通常は画面）に出力します。プリンタエコーが有効になっている場合、文字はプリンタにも出力されます。各種制御コードやエスケープシーケンスは、画面制御コードとして解釈されます。これらは、標準的な VT-52 制御コードのサブセットであり、詳細は「プログラムインターフェース仕様書」に記載されています。TAB（タブ文字）は8カラムごとの位置に展開されます。

処理中にコンソール入力ステータスのチェックが行われ、もし「コンソールステータス（関数 0Bh）」で定義されている特殊制御文字が検出された場合は、同様に処理されます。それ以外の入力文字は、後の「コンソール入力」のために内部に保存されます。


### 3.4 補助入力 (03H)

```text
パラメータ:  C = 03H (_AUXIN)
結果:        L=A = 入力文字
```

補助入力デバイス（ファイルハンドル 3）から1文字読み込みます。入力可能な文字がない場合は、文字が準備できるまで待機します。この関数を使用する前に、補助入力デバイスがシステムにインストールされている必要があります。補助入力デバイスがインストールされていない場合は、この関数は常にファイルの終端を表す文字（Ctrl-Z / 1Ah）を返します。


### 3.5 補助出力 (04H)

```text
パラメータ:  C = 04H (_AUXOUT)
             E = 出力する文字
結果:        なし
```

Eレジスタに渡された文字を補助出力デバイス（ファイルハンドル 3）に書き込みます。この関数を使用する前に、補助出力デバイスがインストールされている必要があります。インストールされていない場合、出力された文字は単に破棄されます。


### 3.6 プリンタ出力 (05H)

```text
パラメータ:  C = 05H (_LSTOUT)
             E = 出力する文字
結果:        なし
```

Eレジスタに渡された文字を標準プリンタデバイス（ファイルハンドル 4 - 通常はパラレルプリンタ）に送信します。画面出力をプリンタにエコーバックする際にも、同じチャンネルが使用されます。この関数自体はTAB文字をスペースに展開しません（ただし、Ctrl-P によるプリンタエコーを伴う画面出力では展開されます）。


### 3.7 直接コンソールI/O (06H)

```text
パラメータ:  C = 06H (_DIRIO)
             E = 00H...FEH - 出力する文字
               = FFH       - 入力要求
結果:        A=L = 入力時: 00H - 入力文字なし
                          それ以外 - 入力された文字
                   出力時: 未定義
```

入力時（呼び出し時に E = FFH の場合）、標準入力（ファイルハンドル 0）のキーボードを調べ、入力文字がなければ 00h を返します。文字が準備されていれば、それをエコーバックなし、制御文字チェックなしで読み込み、Aレジスタに返します。

出力時（呼び出し時に E <> FFH の場合）、Eレジスタの文字を標準出力（ファイルハンドル 1）に直接出力します。TAB展開やプリンタエコーは行われません。また、この関数による出力中はコンソールステータスのチェックは実施されません。なお、この関数自体はTABの展開処理を行いませんが、VT-52制御コード処理による画面上への展開効果は機能します。


### 3.8 直接コンソール入力 (07H)

```text
パラメータ:  C = 07H (_DIRIN)
結果:        L=A = 入力文字
```

この関数は、関数 06h の入力オプション（E = FFH）とほぼ同一ですが、入力文字が準備されていない場合に待機する点が異なります。関数 06h と同様に、エコーバックや制御文字のチェックは行われません。なお、この関数は CP/M の同等番号の機能（I/Oバイトの取得）とは互換性がありません。


### 3.9 エコーなしコンソール入力 (08H)

```text
パラメータ:  C = 08H (_INNOE)
結果:        L=A = 入力文字
```

この関数は、入力された文字が標準出力にエコーバックされない点を除き、関数 01h と同じです。同一の制御文字チェックが実行されます。CP/M の同等番号の機能（I/Oバイトの設定）とは互換性がありません。


### 3.10 文字列出力 (09H)

```text
パラメータ:  C = 09H (_STROUT)
             DE = 文字列のアドレス
結果:        なし
```

DEレジスタが指すアドレスの文字列を、通常のコンソール出力ルーチン（関数 02h）を使って出力します。文字列は `$`（ASCII 24h）によって終端されている必要があります。


### 3.11 バッファ付き一行入力 (0AH)

```text
パラメータ:  C = 0AH (_BUFIN)
             DE = 入力バッファのアドレス
結果:        なし
```

DEは、入力データを格納するためのバッファを指している必要があります。バッファの最初のバイト（DE+0）には、バッファが保持できる最大文字数（0〜255）を設定しておきます。標準入力デバイス（ファイルハンドル 0 - 通常はキーボード）から1行の入力が読み取られ、バッファに格納されます。入力は、キャリッジリターン（CR）が検出された時点で終了します。

入力された文字数（CR自体は含まない）は（DE+1）に格納されます。バッファの容量に空きがある場合は、入力された文字列の直後にCR文字が格納されます。

キーボードから入力する場合（通常のケース）、簡易的なラインエディタおよび、以前に入力した行を編集して再入力できる 256 バイトの循環履歴バッファが利用可能です。これらの編集機能の詳細は別の「コマンド仕様書」に記載されているため、ここでは省略します。入力バッファがフルになった場合、それ以上文字が入力されようとするたびにコンソールのベル（警告音）が鳴ります。入力された各文字は標準出力にエコーバックされ、プリンタエコーが有効であればプリンタにも出力されます。


### 3.12 コンソールステータス (0BH)

```text
パラメータ:  C = 0BH (_CONST)
結果:        L=A = 00H: キー入力なし
                 = FFH: キー入力あり
```

キーボードからの入力（文字が準備されているか）を示すフラグをAレジスタに返します。文字が準備されている場合、それが読み取られ、一部の特殊な制御文字であるかどうかが検査されます。その特殊文字に該当しない場合、文字は内部の1バイトバッファに保存され、その後にこの関数が呼び出された際にはキーボードを再確認することなく即座に「文字あり」を返します。この関数が「文字あり」を返した場合、その文字は関数 01h や 08h で読み取ることができます。

検出された文字が `Ctrl-C` の場合、ユーザー定義のアボートルーチンがあればそれを経由して、プログラムは `.CTRLC` エラーで終了します。`Ctrl-P` であればプリンタエコーが有効になり、`Ctrl-N` であれば無効になります。`Ctrl-S` であれば、別のキーが押されるまで処理を一時停止（ウェイト）させ、キーが押された後に「文字なし」を返します。この一時停止を解除するために押されたキーの文字は、それが `Ctrl-C`（プログラム終了を引き起こす）でない限り、無視されます。これらと同様の入力チェックは、関数 01h, 02h, 08h, 09h, 0Ah でも行われます。


### 3.13 バージョン番号の取得 (0CH)

```text
パラメータ:  C = 0CH (_CPMVER)
結果:        L=A = 22H
             H=B = 00H
```

この関数は、エミュレートしている CP/M のバージョン番号を返します。現在のシステムでは常にバージョン 2.2（22h）を返します。


### 3.14 ディスクリセット (0DH)

```text
パラメータ:  C = 0DH (_DSKRST)
結果:        なし
```

内部バッファ内で書き込みを待機しているすべてのデータをディスクに書き込みます。CP/M とは異なり、ディスクを交換可能にするためにこの関数を明示的に呼び出す必要はありません。また、ディスク転送アドレス（DTA）はデフォルト値の 80h にリセットされます。


### 3.15 ディスクの選択 (0EH)

```text
パラメータ:  C = 0EH (_SELDSK)
             E = ドライブ番号 (0=A:, 1=B:, ...)
結果:        L=A = 利用可能なドライブ数 (1...8)
```

指定されたドライブをデフォルトドライブに設定します。また、CP/M との互換性のために、カレントドライブの番号がアドレス `0004h` にも格納されます。Aレジスタに返される利用可能なドライブ数に、RAMディスクは含まれません。


### 3.16 ファイルのオープン [FCB] (0FH)

```text
パラメータ:  C = 0FH (_FOPEN)
             DE = 未オープンのFCBを指すポインタ
結果:        L=A = 0FFH: ファイルが見つからない
                 = 00H : ファイルが見つかった
```

未オープンの FCB には、ドライブ番号（0はカレントドライブ、1はA:などを表す）、ファイル名、および拡張子（ワイルドカードを含む曖昧な指定も可）が設定されている必要があります。指定されたドライブのカレントディレクトリから一致するファイルが検索され、存在すればオープンされます。サブディレクトリやシステムファイルに一致した場合は無視され、ファイル名にワイルドカードが含まれる場合は最初に一致した条件に合うファイルがオープンされます。

FCB にはデバイス名（コロンなし）を指定することも可能で、これによりデバイスを通常のディスクファイルと同様に扱うことができます。標準デバイス名は「プログラムインターフェース仕様書」に定義されています。

エクステント番号の低位バイトはこの関数によって変更されず、指定されたエクステントを保持できるだけの十分なサイズを持つファイルのみがオープンされます。通常、トランジエントプログラムはこの関数を呼び出す前にエクステント番号を 0 に設定します。エクステント番号の高位バイトは、CP/M との互換性を確保するために 0 に設定されます。

FCB 内のファイル名および拡張子は、ディレクトリから実際にオープンされたファイル名に置き換えられます。これは通常、元の記述と同じですが、曖昧なファイル名や小文字のファイル名を使用した場合には、異なるものに更新されることがあります。

レコード数は、ファイルのサイズから計算され、指定されたエクステント内の 128 バイトレコードの数として設定されます。ファイルサイズフィールド、ボリュームID、および8バイトの予約領域もセットアップされます。カレントレコード（current record）フィールドやランダムレコード（random record）フィールドはこの関数では変更されません。これらを初期化してから読み書き関数を呼び出すのは、アプリケーションプログラム側の責任です。

ファイルが見つからなかった場合、環境変数 `APPEND` が確認されます。この環境変数が設定されている場合、それは2番目に検索を行うべきディレクトリを指定する「ドライブ/パス」文字列として解釈されます。指定されたディレクトリからファイルが再検索され、見つかった場合は上記と同様にオープンされます。この場合、元のFCBのドライブ指定が 0（デフォルト）だったときでも正しくアクセスできるよう、ファイルが見つかった実際のドライブ番号がFCBのドライブバイトにセットされます。


### 3.17 ファイルのクローズ [FCB] (10H)

```text
パラメータ:  C = 10H (_FCLOSE)
             DE = オープン済みFCBを指すポインタ
結果:        L=A = 0FFH: クローズ失敗
                 = 00H : クローズ成功
```

FCBは、事前にオープン関数または作成関数によってオープンされている必要があります。ファイルが読み込み専用でアクセスされていた場合、この関数は実質的に何も行いません。ファイルへの書き込みが行われていた場合、バッファリングされているすべてのデータがディスクに書き込まれ、ディレクトリエントリが適切に更新されます。クローズした後もファイルにアクセスすることは可能であるため、この関数は「ハンドルを固定（Ensure）」する処理と同等とみなすことができます。


### 3.18 最初のファイル検索 [FCB] (11H)

```text
パラメータ:  C = 11H (_SFIRST)
             DE = 未オープンのFCBを指すポインタ
結果:        L=A = 0FFH: ファイルが見つからない
                 = 00H : ファイルが見つかった
```

FCBで指定されたドライブ（FCBが 0 の場合はデフォルトドライブ）のカレントディレクトリを対象に、FCB内のファイル名および拡張子に一致するファイルを検索します。ファイル名にはワイルドカード（`?` 文字）を使用でき、その場合は最初に一致したファイルが検出されます。FCB内のエクステントフィールドの低位バイトが使用され、このエクステント番号を満たす十分なサイズを持つファイルのみが一致対象となります。通常、プログラムはこの関数を呼び出す前にエクステントフィールドを 0 に設定します。システムファイルおよびサブディレクトリは検出対象から除外されます。

一致するファイルが見つかった場合（A=0）、ディレクトリエントリの内容がドライブ番号を先頭に付加した形でDTA（ディスク転送アドレス）のアドレスにコピーされます。これは、必要に応じてそのままオープン関数のFCBとして使用することができます。エクステント番号は検索用FCBと同じエクステントの低位バイトに設定され、レコード数は適切に初期化されます（オープン時と同様）。ディレクトリエントリの属性バイトは S1 バイトの位置に格納されます（本来の属性位置はエクステントバイトとして使用されるため）。

一致するファイルが見つからなかった場合（A=0FFh）、DTAの内容は変更されません。いずれの場合も、DEが指す検索元のFCBは一切変更されません。この関数は、検索を継続するための十分な情報を内部に記憶するため、次の「次のファイル検索」を実行する際に、元のFCBを保存しておく必要はありません。

なお、CP/M では、ドライブ番号に `?` を指定すると、割り当て済み・未割り当てを問わずすべてのディレクトリエントリが検索に一致します。また、エクステントフィールドに `?` を指定すると、ファイルのエクステントに関係なくすべて一致します。これらの機能は通常、CP/M ファイルシステムに依存した特殊なプログラム（「STAT」など）でのみ使用されるものであり、MSX-DOS 1 および 2 には存在しません。


### 3.19 次のファイル検索 [FCB] (12H)

```text
パラメータ:  C = 12H (_SNEXT)
結果:        L=A = 0FFH: ファイルが見つからない
                 = 00H : ファイルが見つかった
```

直前の「最初のファイル検索」で指定したファイル名に一致する、次のファイルを続けて検索します。返される結果は「最初のファイル検索」と同一であり、同様のルールが適用されます。検索を継続するための情報は MSX-DOS 内部で保持されているため、「最初のファイル検索」で使用した元のFCBがメモリ上に残っている必要はありません。


### 3.20 ファイルの削除 [FCB] (13H)

```text
パラメータ:  C = 13H (_FDEL)
             DE = 未オープンのFCBを指すポインタ
結果:        L=A = 0FFH: 削除されたファイルなし
                 = 00H : ファイル削除成功
```

FCBで指定されたディスクのカレントディレクトリ内にある、FCBのファイル名（ワイルドカード指定可）に一致するすべてのファイルを削除します。サブディレクトリ、システムファイル、隠しファイル、および読み取り専用（Read Only）ファイルは削除されません。1つでもファイルの削除に成功すれば A=0 を返します。A=FFh が返された場合は、1つもファイルが削除されなかったことを意味します。


### 3.21 順次読み込み [FCB] (14H)

```text
パラメータ:  C = 14H (_RDSEQ)
             DE = オープン済みFCBを指すポインタ
結果:        L=A = 01H: エラー (ファイルの終端に達した)
                 = 00H: 読み込み成功
```

ファイルから次の連続する 128 バイトのレコードを、現在のDTA（ディスク転送アドレス）に読み込みます。対象のレコード位置は、カレントエクステント（高位・低位バイト）およびカレントレコードによって定義されます。レコードの読み込みに成功すると、カレントレコードがインクリメントされます。これが 080h に達すると、0 にリセットされ、エクステント番号がインクリメントされます。レコード数フィールドも、必要に応じて自動的に最新情報に更新されます。

CP/M とは異なり、ファイルサイズが必ずしも 128 の倍数とは限らないため、不完全に満たされた最終レコードが存在することがあります。これが発生した場合、不足している部分は 0 で埋められた状態でプログラムのDTAにコピーされます。


### 3.22 順次書き込み [FCB] (15H)

```text
パラメータ:  C = 15H (_WRSEQ)
             DE = オープン済みFCBを指すポインタ
結果:        L=A = 01H: エラー (ディスクフル)
                 = 00H: 書き込み成功
```

現在のDTAから 128 バイトのデータを、カレントレコードおよびエクステントで指定されるファイル位置に書き込みます。書き込み後、レコード位置は適切にインクリメントされます。ファイルが拡張されたり、新しいエクステントに移動したりした場合、レコード数バイトは正しく更新されます。ファイルが拡張された場合、FCB内のファイルサイズも更新されます。


### 3.23 ファイルの作成 [FCB] (16H)

```text
パラメータ:  C = 16H (_FMAKE)
             DE = 未オープンのFCBを指すポインタ
結果:        L=A = 0FFH: 作成失敗
                 = 00H : 作成成功
```

指定されたドライブのカレントディレクトリに新しいファイルを作成し、読み書きができる状態でオープンします。FCBにはドライブ、ファイル名、およびエクステント番号の低位バイトが設定されている必要があり、ファイル名にワイルドカードを含めることはできません。無効なファイル名が作成されないよう、エラーチェックが行われます。

要求された名前のファイルが既に存在する場合、動作はエクステント番号の値に依存します。通常、この値は 0 であり、この場合は既存の古いファイルが削除されて新しいファイルが作成されます。しかし、エクステント番号が 0 以外の場合、既存のファイルは削除されずにそのままオープンされます。これは、エクステントごとに明示的に作成を行う必要があった初期の CP/M バージョンとの互換性を維持するための挙動です。

いずれの場合も、作成されたファイルは指定されたエクステント番号でオープンされ、通常のオープン関数（0FH）を呼び出したときと同様の状態になります。


### 3.24 ファイル名の変更 [FCB] (17H)

```text
パラメータ:  C = 17H (_FREN)
             DE = 未オープンのFCBを指すポインタ
結果:        L=A = 0FFH: 変更失敗
                 = 00H : 変更成功
```

未オープンの FCB には通常のドライブ名と変更前のファイル名を設定し、さらに（DE+17）から始まる位置に変更後の新しいファイル名を設定します。指定されたドライブのカレントディレクトリ内で、最初のファイル名に一致するすべてのファイルが、2番目のファイル名に変更されます。2番目のファイル名に `?` が含まれる場合、その位置の元の文字はそのまま残されます。重複したファイル名や不正な名前が作成されないようチェックが行われます。サブディレクトリ、隠しファイル、システムファイルの名称は変更されません。


### 3.25 ログインベクトルの取得 (18H)

```text
パラメータ:  C = 18H (_LOGIN)
結果:        HL = ログインベクトル
```

現在利用可能な各ドライブに対応するビットをセットした値を HL レジスタに返します。Lレジスタのビット0がドライブ「A:」に対応します。現在のシステムでは、最大8つのドライブ（「A:」から「H:」）がサポートされているため、通常 H レジスタは 0 で返されます。


### 3.26 カレントドライブの取得 (19H)

```text
パラメータ:  C = 19H (_CURDRV)
結果:        L=A = カレントドライブ番号 (0=A:, 1=B:, ...)
```

現在のデフォルトドライブ番号を返します。


### 3.27 ディスク転送アドレス(DTA)の設定 (1AH)

```text
パラメータ:  C = 1AH (_SETDTA)
             DE = 設定するディスク転送アドレス (DTA)
結果:        なし
```

DEレジスタで渡されたアドレスをディスク転送アドレス（DTA）として登録します。このアドレスは、その後に実行されるすべての FCB 形式の読み書きコール、「最初のファイル検索」「次のファイル検索」でのディレクトリエントリの格納、およびアブソリュート（絶対セクタ）読み書きで使用されます。新しく追加された MSX-DOS 2 形式の読み書き関数（ハンドル形式）では、このアドレスは使用されません。DTAは「ディスクリセット」コールによってデフォルトの 80h に戻ります。


### 3.28 アロケーション情報の取得 (1BH)

```text
パラメータ:  C = 1BH (_ALLOC)
             E = ドライブ番号 (0=カレント, 1=A:, ...)
結果:        A = クラスタあたりのセクタ数
             BC = セクタサイズ (常に 512)
             DE = ディスク上の総クラスタ数
             HL = ディスク上の空きクラスタ数
             IX = DPBを指すポインタ
             IY = FATの最初のセクタを指すポインタ
```

指定されたドライブのディスクに関するさまざまな情報を返します。この関数は、アロケーションベクタのアドレスを返す CP/M の同等機能とは互換性がありません。MSX-DOS 1 とは異なり、IYのアドレスからアクセスできるのは FAT の「最初のセクタ」のみであり、そこに存在するデータは次の MSX-DOS コールが呼び出されるまでの間のみ有効です。


### 3.29 ランダム読み込み [FCB] (21H)

```text
パラメータ:  C = 21H (_RDRND)
             DE = オープン済みFCBを指すポインタ
結果:        L=A = 01H: エラー (ファイルの終端に達した)
                 = 00H: 読み込み成功
```

FCB内の3バイトのランダムレコード番号（FCBの 21h...23h バイト目）で指定される位置から、128 バイトのレコードを現在の DTA に読み込みます。CP/M とは異なり、ランダムレコード番号の3バイトすべてが有効に使用されます。ファイルの末尾で部分的なレコードを読み込んだ場合は、不足部分を 0 で埋めた上でDTAにコピーされます。

ランダムレコード番号は変更されないため、プログラムが番号を明示的に変更しない限り、この関数を連続して呼び出すと同じレコードが繰り返し読み込まれます。副次的な効果として、この関数を呼び出すと、カレントレコードとエクステントがこのランダムレコード番号と同じ位置を指すように自動設定されます。これにより、ランダム読み込みの後に通常の「順次読み込み（または書き込み）」を続けて行うことが可能となり、その場合は同じレコード位置から処理が継続されます。また、エクステントに対するレコード数バイトも適切に設定されます。


### 3.30 ランダム書き込み [FCB] (22H)

```text
パラメータ:  C = 22H (_WRRND)
             DE = オープン済みFCBを指すポインタ
結果:        L=A = 01H: エラー (ディスクフル)
                 = 00H: エラーなし
```

現在のDTAから 128 バイトのレコードを、FCB内の3バイトのランダムレコード番号（21h...23h バイト目）で指定される位置に書き込みます。3バイトすべての値が使用されます。指定されたレコード位置が現時点でのファイル末尾よりも先にある場合、その間にある未初期化のディスク領域が割り当てられて隙間が埋められます。

ランダムレコード番号フィールドの内容は変更されませんが、カレントレコードとエクステントフィールドは書き込み先のレコードを指すように更新されます。ファイルサイズが拡張された場合、または書き込みによって新しいエクステントが作成された場合、レコード数バイトは適切に調整されます。


### 3.31 ファイルサイズの取得 [FCB] (23H)

```text
パラメータ:  C = 23H (_FSIZE)
             DE = 未オープンのFCBを指すポインタ
結果:        L=A = 0FFH: ファイルが見つからない
                 = 00H : ファイルが見つかった
```

「ファイルのオープン（関数 0FH）」と全く同様に、FCBに指定されたファイル名に一致する最初のファイルを検索します。見つかったファイルのサイズは 128 バイト単位に切り上げられ、レコード数が決定されます。FCBの3バイトのランダムレコードフィールドにこのレコード数が設定されます（これは、存在しない最初のレコード番号を指すことになります）。ランダムレコード番号の4バイト目は変更されません。


### 3.32 ランダムレコードの設定 [FCB] (24H)

```text
パラメータ:  C = 24H (_SETRND)
             DE = オープン済みFCBを指すポインタ
結果:        なし
```

カレントレコードおよびエクステント番号から算出される現在のレコード位置を、FCBの3バイトのランダムレコードフィールドに設定します。ランダムレコード番号の4バイト目は変更されません。そのレコードがファイル内に実際に存在するかどうかのチェックは行われません。


### 3.33 ランダムブロック書き込み [FCB] (26H)

```text
パラメータ:  C = 26H (_WRBLK)
             DE = オープン済みFCBを指すポインタ
             HL = 書き込むレコード数
結果:        A = 01H: エラー
               = 00H: エラーなし
```

現在のDTAから、ランダムレコード番号で定義されるファイル位置にデータを書き込みます。1レコードのサイズは、FCB内のレコードサイズフィールド（0Ehおよび0Fhバイト目）で決定されます。このフィールドは、ファイルをオープンした後、この関数を呼び出す前にユーザーが設定しておく必要があります。レコードサイズが 64 バイト未満の場合はランダムレコード番号の4バイトすべてが使用され、64 バイト以上の場合は最初の3バイトのみが使用されます。

書き込むレコード数は HL レジスタで指定され、レコードサイズとの掛け算によって転送するデータ量が決定されます。転送サイズが 64KB を超える場合はエラーが返されます（1回の最大転送量制限）。

データの書き込み後、ランダムレコードフィールドは次のレコード番号を指すように調整されます（HLレジスタの値が加算されます）。カレントレコードおよびエクステントフィールドは使用されず、変更もされません。ファイルが拡張された場合は、ファイルサイズフィールドが更新されます。

レコードサイズは 1 から 0FFFFh までの任意の値に設定できます。小さなレコードサイズを使用しても、大きなレコードサイズに比べて効率が落ちることはありません。そのため、レコードサイズを 1 に設定して、書き込みレコード数（HL）を実質的な「バイト数」として扱うことも可能です。複数回に分けて細かく書き込むよりも、1回の大きな転送を行う方が高速に処理できるため、可能な限り一度にまとめて書き込むことを推奨します。

書き込むレコード数（HL）に 0 を指定した場合、ディスクへのデータ書き込みは行われませんが、ファイルのサイズがランダムレコードフィールドに指定された値（バイト数）に切り詰められます（または拡張されます）。これはファイルの長さを現在のサイズより長くすることも短くすることも可能で、必要に応じてディスクスペースが割り当て、または解放されます。この方法で新しく割り当てられたディスクスペースは、特定の値で初期化されることはありません。


### 3.34 ランダムブロック読み込み [FCB] (27H)

```text
パラメータ:  C = 27H (_RDBLK)
             DE = オープン済みFCBを指すポインタ
             HL = 読み込むレコード数
結果:        A = 01H: エラー (通常はファイルの終端に達したため)
               = 00H: エラーなし
             HL = 実際に読み込まれたレコード数
```

この関数は、前述の「ランダムブロック書き込み」の対となる機能であり、使用上の注意点などもほぼ同様です。一度に大きなブロックを読み込むことで、従来の CP/M の処理に比べて大幅に高速化できます。

例えば、ファイルから 20KB のデータを読み込みたい場合、1KB ずつ 20 回に分けて読み込むよりも、20KB を一度の関数コールで読み込む方がはるかに効率的です。なお、レコードサイズを 1 にしてレコード数を 20K（20480）にするか、あるいはレコードサイズを 20K にしてレコード数を 1 にするか、またはその中間的な組み合わせにするかによる処理上の違いはありません。

実際に読み込まれたレコード数が HL レジスタに返されます。読み込み中にファイルの終端（EOF）に遭遇した場合、この値は要求されたレコード数よりも小さくなります。その場合、不完全な末尾レコードは 0 で埋められた上でユーザーのDTAにコピーされます。ランダムレコードフィールドは、読み込まれなかった最初のレコード位置を指すように調整されます（HLに返された実際の読み込み数が加算されます）。


### 3.35 ゼロフィル付きランダム書き込み [FCB] (28H)

```text
パラメータ:  C = 28H (_WRZER)
             DE = オープン済みFCBを指すポインタ
結果:        L=A = 01H: エラー
                 = 00H: エラーなし
```

この関数は「ランダム書き込み（関数 22h）」とほぼ同一ですが、ファイルを拡張する必要がある場合に、新しく割り当てられたディスククラスタがデータ書き込みの前にあらかじめ 0 で塗りつぶされる点が異なります。


### 3.36 日付の取得 (2AH)

```text
パラメータ:  C = 2AH (_GDATE)
結果:        HL = 年 (1980...2079)
             D = 月 (1=1月...12=12月)
             E = 日 (1...31)
             A = 曜日 (0=日曜日...6=土曜日)
```

内蔵カレンダーの現在の日付を上記のフォーマットで返します。


### 3.37 日付の設定 (2BH)

```text
パラメータ:  C = 2BH (_SDATE)
             HL = 年 (1980...2079)
             D = 月 (1=1月...12=12月)
             E = 日 (1...31)
結果:        A = 00H: 設定成功 (有効な日付)
                 FFH: 設定失敗 (無効な日付)
```

指定された日付の妥当性をチェックし、正しければ新しいシステム日付として保存します。妥当性チェックには、各月の日数やうるう年の完全な検証が含まれます。日付が無効である場合、現在のシステム日付は変更されません。日付はリアルタイムクロック（RTC）チップに保存されるため、マシンの電源を切っても保持されます。

```text
パラメータ:  C = 2CH (_GTIME)
結果:        H = 時 (0...23)
             L = 分 (0...59)
             D = 秒 (0...59)
             E = 1/100秒 (常に0)
```

システムクロックの現在の時刻を上記のフォーマットで返します。


### 3.39 時刻の設定 (2DH)

```text
パラメータ:  C = 2DH (_STIME)
             H = 時 (0...23)
             L = 分 (0...59)
             D = 秒 (0...59)
             E = 1/100秒 (無視されます)
結果:        A = 00H: 設定成功 (有効な時刻)

```

内蔵のシステムクロックを指定された時刻に設定します。指定された時刻が無効である場合、Aレジスタに 0FFh を返してエラーを示し、現在のシステム時刻は変更されません。時刻はリアルタイムクロック（RTC）チップに保存されるため、マシンの電源を切っても保持され、正確にカウントされ続けます。


### 3.40 ベリファイフラグの設定/解除 (2EH)

```text
パラメータ:  C = 2EH (_VERIFY)
             E = 0: ベリファイを無効化
               = 0以外: ベリファイを有効化
結果:        なし
```

すべてのディスク書き込み処理における自動ベリファイ（書き込み検証）の有効/無効を切り替えます。MSX-DOS の起動時はデフォルトで無効になっています。ベリファイを有効にするとシステムの信頼性は向上しますが、書き込み速度は低下します。なお、この機能はディスクドライブのデバイスドライバに依存しており、ドライバ側がサポートしていない場合はベリファイ処理は行われません。


### 3.41 アブソリュートセクタ読み込み (2FH)

```text
パラメータ:  C = 2FH (_RDABS)
             DE = セクタ番号
             L = ドライブ番号 (0=A:, 1=B:, ...)
             H = 読み込むセクタ数
結果:        A = エラーコード (0であればエラーなし)
```

ファイルを介さずに、ディスクから直接セクタ単位でデータを読み込みます。セクタ番号を物理的なディスク位置に正しく変換するために、対象ディスクは有効な MSX-DOS フォーマットである必要があります。セクタは現在のDTA（ディスク転送アドレス）に読み込まれます。ディスクエラーが発生した場合は、通常の方法でシステムに報告されます。


### 3.42 アブソリュートセクタ書き込み (30H)

```text
パラメータ:  C = 30H (_WRABS)
             DE = セクタ番号
             L = ドライブ番号 (0=A:, 1=B:, ...)
             H = 書き込むセクタ数
結果:        A = エラーコード (0であればエラーなし)
```

ファイルを介さずに、ディスクに直接セクタ単位でデータを書き込みます。セクタ番号を物理的なディスク位置に正しく変換するために、対象ディスクは有効な MSX-DOS フォーマットである必要があります。データは現在のDTA（ディスク転送アドレス）から書き込まれます。ディスクエラーが発生した場合は、通常の方法でシステムに報告されます。


### 3.43 ディスクパラメータの取得 (31H)

```text
パラメータ:  C = 31H (_DPARM)
             DE = 32バイトの書き込みバッファを指すポインタ
             L = ドライブ番号 (0=デフォルト, 1=A:, 2=B:, ...)
結果:        A = エラーコード
             DE = 保存されます
```

指定されたドライブに挿入されているディスクのフォーマットに関連する一連のパラメータを、ユーザープログラム内の32バイトのバッファに書き込んで返します。これは、アブソリュート（絶対）セクタの読み書きを行うプログラムが、セクタ番号を自ら解釈・計算する際に便利です。返されるパラメータには、プログラムで扱いやすいように一部冗長な情報も含まれています。バッファに格納されるパラメータブロックのフォーマットは以下の通りです。

```text
DE+0      - 物理ドライブ番号 (1=A: など)
DE+1,2    - セクタサイズ (現在は常に512バイト)
DE+3      - クラスタあたりのセクタ数 (0以外の2のべき乗)
DE+4,5    - 予約セクタ数 (通常は1)
DE+6      - FATのコピー数 (通常は2)
DE+7,8    - ルートディレクトリのエントリ数
DE+9,10   - 総論理セクタ数
DE+11     - メディア記述子バイト (Media Descriptor)
DE+12     - FAT1つのセクタ数
DE+13..14 - ルートディレクトリの開始セクタ番号
DE+15..16 - データ領域の開始セクタ番号
DE+17..18 - 最大クラスタ番号
DE+19     - ダーティディスクフラグ (Dirty Disk Flag)
DE+20..23 - ボリュームID (-1 = ボリュームIDなし)
DE+24..31 - 予約領域 (現在は常に0)
```

「ダーティディスクフラグ」は、そのディスク上に `UNDEL` コマンドで修復可能な（削除された直後の）ファイルが存在するかどうかを示します。このフラグは、新たにファイルアロケーション（書き込みなど）が行われるとリセットされます。


### 3.44 最初の検索エントリの取得 (40H)

```text
パラメータ:  C = 40H (_FFIRST)
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
             HL = ファイル名を表すASCIIZ文字列 (DEがファイル情報ブロックへのポインタの場合のみ)
             B = 検索属性
             IX = 新しいファイル情報（fileinfo）ブロックを指すポインタ
結果:        A = エラーコード
             (IX) = 一致したエントリの詳細情報が書き込まれます
```

DEに指定された文字列の「ドライブ/パス」部分、またはファイル情報ブロックが検索対象のディレクトリを指定します。もしファイル情報ブロックが（ディレクトリではなく）特定のファイルを指している場合は、`.IATTR` エラーが返されます。DEで渡された文字列の「ファイル名」部分、またはHLに格納されたASCIIZファイル名文字列が、一致判定に使用されます。一致するファイルが見つからない場合は `.NOFIL` エラーが返されます。見つかった場合は、IXが指すファイル情報（fileinfo）ブロックに一致したエントリの詳細が書き込まれます。

ファイル名にはワイルドカード（`?` または `*`）を含めることができ、その場合は最初に一致したエントリが返されます。ファイル名の指定が空の場合（DEの指す文字列が空、または末尾が `\` である場合や、HLの指す文字列が空の場合）、この関数はファイル名に `*.*` が指定されたものとして動作し、すべての名前に一致します。

Bレジスタの属性バイトは、検索対象とするエントリのタイプを指定します。これが 0 の場合、隠しファイルやシステムファイル、ディレクトリを除いた通常のファイルのみが検索対象になります。Bレジスタ内のディレクトリ、隠し、システム属性ビットがセットされている場合、それらに合致するエントリも通常ファイルに加えて検索対象に含まれます。読み取り専用（Read Only）属性ビットおよびアーカイブ（Archive）属性ビットは無視されます。

Bレジスタのボリュームラベル属性ビットがセットされている場合、この検索は特殊な排他的検索となり、ボリュームラベルエントリのみが検索されます。この場合、渡されたファイル情報ブロックや検索文字列は（ドライブ指定を除き）すべて無視されます。これは、ルートディレクトリにボリュームラベルが存在すれば、指定されたファイル名に関係なく常にそれが検出されることを意味します。

DEが既存のファイル情報ブロックを指している場合、必要に応じてIXにそれと同じファイル情報ブロックを指すアドレスを渡すことができます。この場合、一致が検出されると、新しいファイル情報が古い情報の上に上書きされます。


### 3.45 次の検索エントリの取得 (41H)

```text
パラメータ:  C = 41H (_FNEXT)
             IX = 前回の「最初の検索エントリ取得」で使用したファイル情報ポインタ
結果:        A = エラーコード
             (IX) = 次に一致したエントリの詳細情報が書き込まれます
```

この関数は、事前に呼び出された「最初の検索エントリの取得」の後にのみ使用できます。前回の検索で指定された（通常はワイルドカードを含む）ファイル名に一致する次のエントリをディレクトリから検索します。それ以上一致するエントリが存在しない場合は `.NOFIL` エラーが返されます。存在する場合は、ファイル情報ブロックが次のエントリの情報に更新されます。


### 3.46 新規エントリの作成・検索 (42H)

```text
パラメータ:  C = 42H (_FNEW)
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
             HL = ファイル名を表すASCIIZ文字列 (DEがファイル情報ブロックへのポインタの場合のみ)
             B  = b0..b6: 作成するファイル属性
                  b7    : 新規作成限定フラグ (Create New Flag)
             IX = 雛形（テンプレート）となるファイル名を含む、新しいファイル情報ブロックへのポインタ
結果:        A = エラーコード
             (IX) = 作成された新しいエントリの情報が書き込まれます
```

この関数は、前述の「最初の検索エントリの取得」と非常に似ています。HLおよびDEパラメータは、ディレクトリを指定するために同様の方法で使用されます。しかし、指定されたディレクトリからファイルを検索する代わりに、その名前で新しいディレクトリエントリを作成します。作成された新しいエントリの情報は、あたかも「最初の検索エントリの取得」で見つかったかのように、IXが指すファイル情報ブロックに格納されます。

指定された新しいファイル名の中にワイルドカード（`?` や `*`）が含まれている場合、それらはIXが指すファイル情報ブロックのファイル名部分にあらかじめ格納されている「テンプレート名」の対応する文字で置き換えられます。置き換えた結果がなお曖昧であったり、その他の理由でファイル名として不適切である場合は `.IFNM` エラーが返されます。この挙動は、ファイルのコピー時に自動的に名前を変更する（リネームコピー）といった処理に役立ちます。

「最初の検索エントリの取得」と同様に、ファイル名の指定が空である場合は `*.*` が指定されたものとして処理されます。この関数の場合、これはテンプレート名がそのまま新しいファイル名として作成に使用されることを意味します。

ルートディレクトリにエントリを格納する空きがない場合は `.DRFUL` エラーが返されます。また、サブディレクトリを拡張する必要があるにもかかわらずディスクに十分な空き容量がない場合は `.DKFUL` エラーが返されます。

Bレジスタの下位7ビットで渡される属性は、新しく作成されるエントリに割り当てられます。ボリュームラベル属性ビットがセットされている場合は、ルートディレクトリにボリュームラベルが作成されます。ディレクトリ属性ビットがセットされている場合はサブディレクトリが作成され、それ以外の場合はファイルが作成されます。ファイルを作成する際には、システム、隠し、読み取り専用の各属性ビットを設定可能です。サブディレクトリに対しては、隠し属性を設定できます。作成されたファイルは、常にアーカイブ（Archive）属性ビットがセットされた状態になります。

ファイルはサイズ 0、かつ現在の日時が適用されて作成されます。サブディレクトリの場合は1つのクラスタがあらかじめ割り当てられ、`.`（カレント）および `..`（親）エントリが適切に初期化されます。

指定された名前のエントリが既にディレクトリに存在する場合、その後の動作はBレジスタのビット7（新規作成限定フラグ）および存在するエントリのタイプに依存します。「新規作成限定」フラグがセットされている場合、常に `.FILEX` エラーを返します。このフラグをセットすることで、既存のファイルを誤って削除してしまうのを防ぐことができます。

エントリが既に存在し、かつ「新規作成限定」フラグがセットされていない場合、既存のエントリが新しいファイルを作成するために削除可能であるかがチェックされます。既存エントリが読み取り専用ファイル（`.FILRO` エラー）、システムファイル（`.SYSX` エラー）、またはサブディレクトリ（`.DIRX` エラー）である場合、あるいはそのファイルに対するファイルハンドルが現在オープンされている場合（`.FOPEN` エラー）はエラーが返され、削除は行われません。また、新しく作成しようとしているのがサブディレクトリである場合は、既存エントリが通常のファイルであっても削除されません（`.FILEX` エラー）。

これらのエラー（`.FILEX`, `.FILRO`, `.SYSX`, `.DIRX`, `.FOPEN`）が発生した場合、IXで指定されたファイル情報ブロックには「既に存在する既存エントリの情報」が書き込まれます。この情報は、あたかも「最初の検索エントリの取得」から返された情報であるかのように再利用することができます。


### 3.47 ファイルハンドルのオープン (43H)

```text
パラメータ:  C = 43H (_OPEN)
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
             A = オープンモード
                 b0: 1 = 書き込み禁止 (No Write)
                 b1: 1 = 読み込み禁止 (No Read)
                 b2: 1 = 子プロセスへ継承可能 (Inheritable)
                 b3..b7: 常に 0 でなければなりません
結果:        A = エラーコード
             B = 新しいファイルハンドル番号
```

指定するDEの文字列またはファイル情報ブロックは、ボリュームラベルやサブディレクトリではなく、通常のファイルを指している必要があります。ボリュームラベルを指定した場合は `.IATTR` エラーが、サブディレクトリを指定した場合は `.DIRX` エラーが返されます。

ファイルが正しく特定されると、Aレジスタで指定されたオープンモードに従って読み込みおよび/または書き込みが可能な状態でオープンされ、新しく割り当てられたファイルハンドル番号がBレジスタに返されます。ハンドル番号は利用可能なもののうち最も小さい値が選択されます。使用できる空きハンドルがない場合は `.NHAND` エラーが、メモリが不足している場合は `.NORAM` エラーが返されます。

Aレジスタの「書き込み禁止」ビットがセットされている状態でオープンされたハンドルに対して書き込みを行おうとした場合、または「読み込み禁止」ビットがセットされている状態で読み込みを行おうとした場合は、いずれも `.ACCV`（アクセス拒否）エラーが返されます。また、ファイル自体が読み取り専用属性を持っている場合も、書き込みは拒否されます（`.FILRO` エラー）。Aレジスタの「子プロセスへ継承可能」ビットがセットされている場合、このファイルハンドルは「子プロセスのフォーク（関数 60h）」呼び出し時に作成される新しいプロセスにそのまま引き継がれます。

「CON」や「NUL」といったシステム組み込みのデバイス名に一致するファイル名を指定してデバイスのファイルハンドルをオープンした場合、そのハンドルは常にアスキー（ASCII）モードとして初期化されます。これをバイナリ（Binary）モードに変更するには IOCTL 関数（関数 4Bh）を使用します。ただし、バイナリモードのデバイス読み込みにはファイルの終端（EOF）の概念がないため、読み込み処理の実行には十分な注意が必要です。


### 3.48 ファイルハンドルの作成 (44H)

```text
パラメータ:  C = 44H (_CREATE)
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
             A = オープンモード
                 b0: 1 = 書き込み禁止 (No Write)
                 b1: 1 = 読み込み禁止 (No Read)
                 b2: 1 = 子プロセスへ継承可能 (Inheritable)
                 b3..b7: 常に 0 でなければなりません
             B = b0..b6: 作成するファイル属性
                 b7    : 新規作成限定フラグ (Create New Flag)
結果:        A = エラーコード
             B = 新しいファイルハンドル番号
```

Bレジスタで指定された属性を持つファイルまたはサブディレクトリを、DEで指定された「ドライブ/パス/ファイル名」の位置に新規に作成します。Bレジスタでボリュームラベル属性を指定した場合は、`.IATTR` エラーが返されます。

何らかの原因でファイルやサブディレクトリが作成できなかった場合はエラーが返されます。発生しうる主なエラーは「新規エントリの作成・検索（関数 42h）」と共通しており、具体的には `.FILEX`、`.DIRX`、`.SYSX`、`.FILRO`、`.FOPEN`、`.DRFUL`、`.DKFUL` などです。同様に、Bレジスタのビット7（新規作成限定フラグ）がセットされている場合は、既存ファイルが存在しても削除は行われず、常に `.FILEX` エラーを返します。

作成する属性にサブディレクトリが指定されている場合は、隠し（Hidden）属性ビットも同時に指定して隠しディレクトリを作成することができます。ファイルを作成する場合は、隠し、システム、読み取り専用の各属性を指定可能です。無効な属性ビットは無視されます。ファイルが作成されると、自動的にアーカイブ（Archive）属性ビットがセットされます。

ファイルが作成された場合、前述の「ファイルハンドルのオープン」と同様に自動的にオープンされ、割り当てられたハンドル番号がBレジスタに返されます。Aレジスタで指定されたオープンモードの各パラメータは、オープン関数と同様に機能します。サブディレクトリを作成した場合は「オープン」されることはありません（ディレクトリをファイルハンドルとしてオープンすることはできないため）。その場合、Bレジスタには決して有効なハンドル番号にはならない 0FFh が返されます。


### 3.49 ファイルハンドルのクローズ (45H)

```text
パラメータ:  C = 45H (_CLOSE)
             B = ファイルハンドル番号
結果:        A = エラーコード
```

指定されたファイルハンドルを解放し、再利用可能な状態にします。対象のファイルへの書き込みが行われていた場合は、ディレクトリエントリが現在の新しい日時で更新され、アーカイブ属性ビットがセットされ、バッファリングされている未書き込みデータがディスクに強制的に書き出されます（フラッシュ）。クローズされたハンドルに対してこれ以降アクセスを行おうとすると、エラーが発生します。「ハンドルの複製」や「プロセスのフォーク」によって作成された、同じファイルを指す別のハンドルコピーが他に存在する場合は、それらを介して引き続きファイルにアクセスすることができます。


### 3.50 ファイルハンドルの固定 (46H)

```text
パラメータ:  C = 46H (_ENSURE)
             B = ファイルハンドル番号
結果:        A = エラーコード
```

ハンドルに関連付けられたファイルに対して書き込みが行われていた場合、現在の新しい日時にディレクトリエントリを更新し、アーカイブ属性ビットをセットし、キャッシュされているすべてのバッファデータを即座にディスクに書き込み（フラッシュ）ます。ファイルハンドル自体は解放されずにオープンのまま維持されるため、引き続きファイルへのアクセスが可能です。また、現在のファイルポインタ（シーク位置）も変更されません。


### 3.51 ファイルハンドルの複製 (47H)

```text
パラメータ:  C = 47H (_DUP)
             B = ファイルハンドル番号
結果:        A = エラーコード
             B = 新しい複製されたファイルハンドル番号
```

指定されたファイルハンドルのコピーを作成します。新しく割り当てられるハンドルは、現在空いているもののうち最も小さい番号が選択されます。空きハンドルがない場合は `.NHAND` エラーが返されます。複製された新しいハンドルは、元のハンドルとまったく同じファイルを指し、どちらを使っても同様にアクセスできます。一方のハンドルでファイルポインタを移動させると、もう一方のハンドルのポインタも連動して移動します。どちらか一方のハンドルをクローズしても、もう一方は開いたまま残され、引き続き使用可能です。

この関数によって作成された複製のハンドルは、内部で「新しく別途オープンされた」ハンドルとはみなされないため、ディレクトリエントリ共有上の `.FOPEN` エラーの原因にはなりません。そのため、複製されたハンドルのうち一方の名前を変更（関数 53h）したり、属性を変更（関数 55h）したりすると、その影響は同じファイルを指している両方のハンドルに適用されます。ただし、特に注意すべき点として、一方のハンドルを介して「ファイルの削除（関数 54h）」を呼び出した場合、ファイルの実体がディスクから消去されます。このとき、もう一方のハンドルはオープンされた状態のまま残りますが、安全にアクセスすることはできなくなります（クローズ、ハンドル固定、削除以外の操作を行うと `.FDEL` エラーが返されます）。


### 3.52 ファイルハンドルからの読み込み (48H)

```text
パラメータ:  C = 48H (_READ)
             B = ファイルハンドル番号
             DE = 読み込み先のバッファアドレス
             HL = 読み込むバイト数
結果:        A = エラーコード
             HL = 実際に読み込まれたバイト数
```

現在のファイルポインタの位置から、指定されたバイト数（HL）のデータを読み取り、DEで指定されたバッファ領域にコピーします。読み取り後、ファイルポインタは読み取られたデータの直後を指すように更新されます。もしファイルハンドルが「読み込み禁止」モードでオープンされていた場合は、`.ACCV` エラーが返されます。

何らかの理由で、実際に読み取られたバイト数が要求されたサイズ（HL）よりも小さくなることがあります。エラーが発生しなかった場合、実際に読み取られたバイト数がHLレジスタに返されます。一般的に、要求より少ないバイト数しか読み取れなかった場合でも、それを即座に致命的なエラーとはみなさず、次のデータを読み取るために再度読み込み処理を実行する設計にする必要があります（最終的に `.EOF` エラーが返されるまで繰り返します）。部分的な読み取りが発生した時点では `.EOF` エラーは返されず、読み込み可能なデータが 0 バイトの状態でさらに読み込もうとしたときに初めて `.EOF` エラーが返されます。この規則に従うことで、デバイスを指すファイルハンドルに対しても正しく読み取り処理を機能させることができます。

通常のディスクファイルの場合、読み取られたバイト数が要求サイズより小さくなるのは、ファイルの終端（EOF）に達したときのみです。その後の次の読み取り処理を実行すると、0 バイトが読み込まれ、`.EOF` エラーが返されます。

標準入出力などのデバイスハンドル（ファイルハンドル 0〜4 など）からデータを読み取る場合、挙動はそのデバイスの仕様およびアスキー/バイナリモード（関数 4Bh を参照）の設定に依存します。代表的な例として、最も一般的に使用される「CON」デバイスについて以下に説明します。

バイナリモードで「CON」デバイスから読み取る場合、キーボードからの入力はエコーバックや制御文字の解釈を一切行わず、そのままダイレクトに読み取られます。このモードでは常に要求された正確なバイト数が読み取られるまで待機し、ファイルの終端（EOF）に達するという状態は発生しません。バイナリモードのデバイス読み取りでは、EOFを検知できないため、プログラム側の制御に細心の注意が必要です。

アスキーモード（標準入力チャンネルの初期値）で「CON」デバイスから読み取りを行う場合、常に1行分の入力のみを読み込みます。入力は、一般的なコマンドラインと同様に、ユーザーによる編集機能（ラインエディタ）が効いた状態でキーボードから取得されます。入力された文字は画面にエコーバックされ、Ctrl-P が有効であればプリンタにもエコーバックされます。この処理中、特殊な制御文字（`Ctrl-P`、`Ctrl-N`、`Ctrl-S`、`Ctrl-C`）はすべてトラップされ、「コンソールステータス（関数 0Bh）」と同様に機能します。

ユーザーがキャリッジリターン（CR）を押すと、入力行は CR-LF の改行コードを末尾に付加した状態でバッファに転送され、読み込み関数は終了して適切なバイト数を返します。次の読み取り関数を呼び出すと、再び新しい行のバッファ入力処理が開始されます。もし、1行の入力文字数よりも関数で要求されたバイト数のほうが小さかった場合、まずは要求されたサイズ分だけデータが返され、その次の読み取り関数呼び出し時には、キーボード入力を新たに待つことなく残りのバッファデータが即座に返されます。これが繰り返され、1行分が完全に消費されるまで続きます。

ユーザーが入力した行の先頭文字が `Ctrl-Z`（1Ah）であった場合、これはファイル終端（EOF）の入力として解釈されます。この場合、入力された行自体は破棄され、読み取り関数は 0 バイトを返して `.EOF` エラーになります。なお、その直後に再度読み込み関数を呼び出すと通常状態に戻り、新しく次の行の入力を受け付けます。したがって、デバイスにおけるEOF状態は一時的なものです。


### 3.53 ファイルハンドルへの書き込み (49H)

```text
パラメータ:  C = 49H (_WRITE)
             B = ファイルハンドル番号
             DE = 書き込むデータのアドレス
             HL = 書き込むバイト数
結果:        A = エラーコード
             HL = 実際に書き込まれたバイト数
```

指定されたアドレス（DE）から、現在のファイルポインタの位置へ、指定されたバイト数（HL）のデータを書き込みます。書き込み後、ファイルポインタは書き込まれたデータの直後を指すように更新されます。もしファイルが「書き込み禁止」モードでオープンされていた場合は `.ACCV` エラーが返され、読み取り専用ファイルに書き込もうとした場合は `.FILRO` エラーが返されます。

書き込みによって現在のファイルの終端を超える場合、ファイルサイズは必要に応じて自動的に拡張されます。ファイルポインタがあらかじめファイルの終端を大きく越えた位置に設定されていた場合、その隙間を埋めるようにディスクスペースが自動的に割り当てられますが、この隙間のデータ内容は初期化されません。ディスクの空き容量が不足している場合は、`.DKFUL` エラーが返されます。この場合、部分的な書き込みは一切行われず、要求されたデータは1バイトも書き込まれません。

書き込みが成功した場合、通常、実際に書き込まれたバイト数の結果は無視しても差し支えありません。これは、書き込み処理が成功していれば要求されたバイト数と同じ値がHLに返り、失敗していればエラーコードがAレジスタに返ってHLは 0 になるためです。数バイトずつの細かな書き込みを繰り返すよりも、大きなブロックにまとめて一度に書き出すほうがはるかに処理効率が向上するため、プログラムは極力大きな単位で書き込みを実行するように設計してください。

この関数を呼び出すと、対象ハンドルに対して「変更（modified）フラグ」がセットされます。これにより、ハンドルが（明示的・暗示的を問わず）クローズされたり固定（Ensure）されたりした際に、ディレクトリエントリの更新（日時の変更、新しいディスク容量の確定）が自動的に行われます。また、ファイルが変更されたことを示すために、アーカイブ属性ビットがセットされます。

デバイスのファイルハンドルに対する書き込み処理は、ファイル終端の考慮や行入力処理の介在がないため、読み込みに比べて単純です。ただし、「CON」デバイスに対する書き込みでは、アスキーモードとバイナリモードで動作上の違いがあります。アスキーモードの書き込み中のみ、コンソールステータスのチェックが併せて実施され、またプリンタエコーが有効な場合はプリンタへの出力も連動して行われます。


### 3.54 ファイルハンドルポインタの移動 (4AH)

```text
パラメータ:  C = 4AH (_SEEK)
             B = ファイルハンドル番号
             A = 移動方式 (シークモード)
                 00H: ファイルの先頭からの相対位置
                 01H: 現在のポインタ位置からの相対位置
                 02H: ファイルの末尾からの相対位置
             DE:HL = 符号付き移動オフセット量 (32ビット)
結果:        A = エラーコード
             DE:HL = 移動後の新しいファイルポインタ位置
```

指定されたファイルハンドルに関連付けられているファイルポインタ（シーク位置）を、指定されたモードとオフセットに基づいて変更し、移動後の新しいポインタ位置を DE:HL に返します。移動の基準点は、Aレジスタのシークモードによって以下のように決定されます。

- **A = 0**: ファイルの先頭。オフセットは正の値でなければなりません。
- **A = 1**: 現在のファイルポインタの位置。オフセットには正または負の値を指定できます。
- **A = 2**: ファイルの末尾。オフセットには正または負の値を指定できます。

現在位置（A=1）に対してオフセット 0 を指定すると、現在のファイルポインタの位置を変更せずに取得することができます。また、ファイル末尾（A=2）に対してオフセット 0 を指定すると、ファイルの現在の正確なサイズを取得できます。ポインタをファイルの末尾を越えた位置に移動させること自体は可能（かつ、時に有効）であり、シークの時点ではエラーチェックは実施されません。このファイルハンドルに対して、「ハンドルの複製（関数 47h）」や「プロセスのフォーク（関数 60h）」で作られた他のコピーが存在する場合、それらのポインタ位置も共通して変更されます。

ファイルポインタは、ランダムアクセスが可能な通常のディスクファイルに対してのみ本来の意味を持ちます。デバイスハンドルに対してこの関数を実行した場合、データの読み書きに応じて内部のポインタ値は同様に更新されますが、シークを行って値を任意に変更してもデバイスの出力動作に実質的な影響はありません。


### 3.55 デバイスのI/O制御 (4BH)

```text
パラメータ:  C = 4BH (_IOCTL)
             B = ファイルハンドル番号
             A = サブファンクションコード
                 00H: ファイルハンドルのステータス取得
                 01H: アスキー/バイナリモードの設定
                 02H: 入力可能状態のテスト (データあり)
                 03H: 出力可能状態のテスト (書き込み可)
                 04H: 画面サイズの取得
             DE = 各サブファンクション用のパラメータ
結果:        A = エラーコード
             DE = 各サブファンクション用の戻り値
```

ファイルハンドルの様々な属性や状態を調査・変更するために使用されます。特に、指定されたファイルハンドルが「通常のディスクファイル」であるか、あるいは「デバイス」であるかを判定するのに最適です。これは、ディスクファイルとデバイスI/Oでプログラムの挙動を切り替えたい場合に重宝します。

ハンドル番号を B、行いたい処理に対応するサブファンクションコードを A に指定して呼び出します。一部のサブファンクションでは、DEレジスタを介して追加のパラメータを受け渡したり、結果を受け取ったりします。指定されたサブファンクションコードが無効な場合は、`.ISBFN` エラーが返されます。

**A = 00H: ファイルハンドルのステータス取得**
ファイルハンドルの状態を示す各種情報フラグを1ワード（2バイト）としてDEに返します。この戻り値ワードのフォーマットは、対象がデバイスであるかディスクファイルであるかによって異なり、ビット7によって判別可能です。

```text
デバイスの場合 (DEのビット7が 1):
  b0: 1 = コンソール入力デバイス (CONIN)
  b1: 1 = コンソール出力デバイス (CONOUT)
  b2..b4: 予約領域
  b5: 1 = アスキーモード / 0 = バイナリモード
  b6: 1 = ファイルの終端 (EOF)
  b7: 常に 1 (デバイスであることを示す)
  b8..b15: 予約領域

ディスクファイルの場合 (DEのビット7が 0):
  b0..b5: ドライブ番号 (0=A:, 1=B:, ...)
  b6: 1 = ファイルの終端 (EOF)
  b7: 常に 0 (ディスクファイルであることを示す)
  b8..b15: 予約領域
```

ファイル終端（EOF）フラグは、デバイスとディスクファイルで共通のビット位置に存在します。デバイスの場合、直前の読み込みで `.EOF` エラーが発生した際にこのビットがセットされ、次の読み込みが実行されるとクリアされます。ディスクファイルの場合は、単に現在のファイルポインタがファイルサイズに達しているかどうかの比較によって判定されます。

**A = 01H: アスキー/バイナリモードの設定**
この操作はデバイスハンドルに対してのみ許可されます。設定したいモード（1=アスキーモード、0=バイナリモード）を、DEレジスタのビット5（ステータス取得で戻される位置と同じ）に設定して呼び出します。DEレジスタのその他のビットは無視されます。

**A = 02H / 03H: 入力/出力可能状態のテスト**
ハンドルが即座にデータ転送可能な状態にあるかをテストします。結果は E レジスタに返され、準備ができていれば FFh、できていなければ 00h になります。「即座に可能」の具体的な条件はデバイスによって異なります。ディスクファイルハンドルの場合は、書き込み（03H）は常に可能です。読み込み（02H）については、ファイルポインタがEOFに達していない限り常に可能です。「CON」デバイスの入力準備テストでは、実際にキーボードの入力バッファが空でないかが調べられます。

**A = 04H: 画面サイズの取得**
ハンドルに関連付けられている「論理的な画面サイズ」を返します。行数が D レジスタに、桁（カラム）数が E レジスタに返されます。ディスクファイルのように画面サイズを持たないハンドルの場合、D と E はともに 0 になります。画面制御などを行うプログラムは、戻り値の 0 を「無制限（行/桁の制限なし）」として解釈する必要があります。例えば、この関数は `DIR /W` コマンドで1行にいくつのファイル名を出力するかを決定するために使用され、Eレジスタが 0 の場合はデフォルトで80桁として処理されます。


### 3.56 ファイルハンドルのテスト (4CH)

```text
パラメータ:  C = 4CH (_HTEST)
             B = ファイルハンドル番号
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
結果:        A = エラーコード
             B = 00H: 異なるファイルです
                 FFH: 同一のファイルです
```

この特殊な関数は、指定されたファイルハンドル（B）と、別のASCIIZファイルパス（またはファイル情報ブロック）が指すファイル（DE）が、ディスク上で「同一のファイル」を指しているかどうかを判定し、その結果をBレジスタにフラグ（FFh = 同一、00h = 異なる）として返します。ファイルハンドルがディスクファイルではなくデバイスを指している場合は、比較対象に関係なく常に B=00h（異なる）を返します。

この関数を使用することで、例えば `COPY` コマンドにおいて「自分自身へのファイルコピー」を検出し、安全に処理を中断してユーザーにエラーメッセージを表示することが可能になります。同様のファイル同一性テストが必要なアプリケーションにとって便利な機能です。


### 3.57 ファイルまたはサブディレクトリの削除 (4DH)

```text
パラメータ:  C = 4DH (_DELETE)
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
結果:        A = エラーコード
```

DEで指定されたファイル、またはサブディレクトリを物理的に削除します。この関数ではワイルドカード（`?` や `*`）の使用は許可されておらず、一度に削除できるのは単一のオブジェクトのみです。サブディレクトリを削除する場合は、そのディレクトリが完全に空である必要があります。空でない場合は `.DIRNE`（ディレクトリが空ではない）エラーが発生します。ディレクトリエントリに存在する `.` や `..` 自体を削除することはできません（`.DOT` エラー）。また、ルートディレクトリを削除することもできません。ファイルを削除する際、そのファイルに対して現在オープンされているファイルハンドルが存在する場合は `.FOPEN` エラーが発生し、ファイルが読み取り専用属性を持っている場合は `.FILRO` エラーが発生します。

削除されたのが通常のファイルである場合、割り当てられていたディスククラスタはすべて解放されます。対象ディスクが MSX-DOS 2 形式でフォーマットされている場合、後から `UNDEL` コマンド等を使ってファイルを救出（アンデリート）できるように、必要な削除前情報がディスク上の一部に一時保存されます。この情報は、次に新しくディスクの空き容量割り当て処理（他ファイルへの書き込みなど）が発生した時点で消失します。この関数の呼び出しにファイル情報ブロック（fileinfo）を使用した場合は、削除されたファイルの実体が既に存在しなくなっているため、そのファイル情報ブロックを（次のファイル検索に再利用する場合を除き）そのまま他の操作に使い回さないでください。

DEに「CON」などのデバイス名を指定してこの関数を呼び出した場合、エラーは発生しませんが、デバイスが実際に削除されることもありません。


### 3.58 ファイルまたはサブディレクトリの名称変更 (4EH)

```text
パラメータ:  C = 4EH (_RENAME)
             DE = 変更前のオブジェクトを指す「ドライブ/パス/ファイル名」ASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
             HL = 新しい「ファイル名」を表すASCIIZ文字列
結果:        A = エラーコード
```

DEで指定されたファイルまたはサブディレクトリの名前を、HLで指定された新しいファイル名に変更します。HLで渡す新しいファイル名文字列には、ドライブ名やディレクトリパスを含めることはできません（含めた場合は `.IFNM` エラーになります）。DEに「CON」などのデバイス名を指定した場合、エラーは発生しませんが名前が変更されることもありません。

変更前の名前を指定する文字列（DE）にワイルドカード文字を含めることはできず、一度に名前を変更できるのは1つのオブジェクトのみです。一方、変更後の新しい名前の文字列（HL）にはワイルドカード文字（`?`）を使用することが可能で、そのワイルドカードが存在する箇所の文字は変更前の名前の文字がそのまま維持されます。この際、無効な名前が作成されないようにチェックが行われます。例えば、「XYZ」という名前のファイルを、新しい名前文字列 "????A" にリネームすることはできません。これは変換結果が空白を含む不正なファイル名「XYZ A」になってしまうためであり、この場合は `.IFNM` エラーが返されます。

変更しようとする新しい名前が、そのディレクトリに既に存在する名前と重複する場合は、重複作成を防ぐために `.DUPF`（ファイル重複）エラーが返されます。サブディレクトリ内の `.` や `..` の名前を変更することはできず（`.IDOT` エラー）、名前を持たないルートディレクトリ自体の名称変更も不可能です。ファイルが現在別のハンドルでオープンされている場合は `.FOPEN` エラーが発生して名前変更は拒否されますが、クローズされていれば読み取り専用属性を持つファイルであっても名前を変更することは可能です。

なお、DEにファイル情報ブロックを指定してこの関数を呼び出しても、そのブロック内の名前情報は自動的に新しい名前に更新されません。関数実行後にそのファイル情報ブロックをそのまま使用する場合には注意が必要です。


### 3.59 ファイルまたはサブディレクトリの移動 (4FH)

```text
パラメータ:  C = 4FH (_MOVE)
             DE = 移動元のオブジェクトを指す「ドライブ/パス/ファイル名」ASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
             HL = 移動先となる「ディレクトリパス」を表すASCIIZ文字列
結果:        A = エラーコード
```

DEで指定されたファイルまたはサブディレクトリを、HLで指定された移動先ディレクトリ内に移動します。HLで渡す移動先パス文字列には、ドライブ名を含めることはできません。DEに「CON」などのデバイス名を指定した場合、エラーは発生しませんが実質的な移動も行われません。

パラメータのいずれの文字列にもワイルドカードを含めることはできません。そのため、この関数で直接移動できるのは単一のオブジェクト（ファイルまたはサブディレクトリ1つ）のみです。ただし、サブディレクトリを移動させた場合は、そのディレクトリに含まれるすべての配下ファイルやディレクトリも、構造を維持したまま一緒に移動します。移動先のターゲットディレクトリ内に、既に移動対象と同じ名前のエントリが存在する場合は、重複を防ぐために `.DUPF` エラーが返されます。サブディレクトリの `.` や `..` エントリを移動させることはできず（`.DOT` エラー）、またディレクトリを「それ自身の配下のサブディレクトリ」の中に移動させることも不可能です（`.DIRE` エラー。これを許可するとファイルシステム内に循環ループが形成され、孤立してしまうため）。ファイルがオープンされている場合は、`.FOPEN` エラーが発生して移動は拒否されます。

DEにファイル情報ブロックを指定して呼び出した場合、ファイル情報ブロックの内部情報（格納されているディレクトリの場所など）は自動的に更新されません。これは、ファイル情報ブロックを次のファイル検索（`_FNEXT`）で継続して使用できるようにするための仕様です。しかし、このファイル情報ブロックは移動したファイルの正しい場所をもはや指していないため、移動後のファイルに対して属性変更やオープンなどの操作を行うためにこの古い情報ブロックを再利用することは避けてください。


### 3.60 ファイル属性の取得/設定 (50H)

```text
パラメータ:  C = 50H (_ATTR)
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
             A = 0: 属性の取得 (Get)
                 1: 属性の設定 (Set)
             L = 新しく設定する属性バイト (A = 1 の場合のみ)
結果:        A = エラーコード
             L = 現在の属性バイト
```

通常、ファイルやサブディレクトリの属性を設定（変更）するために使用されます。属性を取得するためにも使用できますが、属性値を取得するだけであれば通常は「最初の検索エントリの取得（関数 40h）」の機能で十分です。A=0 で呼び出した場合、対象オブジェクトの現在の属性バイトが L レジスタに返されます。

A=1 で呼び出した場合、対象オブジェクトの属性が L レジスタで指定された新しい値に更新され、更新後の属性値が L レジスタに返されます。ファイルの場合に変更可能な属性は、システム、隠し、読み取り専用、およびアーカイブ属性ビットのみです。サブディレクトリに対して変更できるのは隠し属性ビットのみです。これら以外の属性ビットを変更しようとすると、`.IATTR` エラーが返されます。ファイル情報ブロック（fileinfo）を介してこの関数を呼び出した場合、ファイル情報ブロック自体に記録されている属性バイトは自動的には更新されません。

文字列パラメータにワイルドカードを使用することはできないため、一度の処理で属性を変更できるのは1つのオブジェクトのみです。ルートディレクトリはそもそも属性情報を持たないため、属性を変更することはできません。ファイルが現在オープンされている場合は `.FOPEN` エラーが発生し、属性変更は拒否されます。サブディレクトリ内の `.` および `..` ディレクトリの属性は変更可能です。「CON」などのデバイス名を指定して呼び出した場合は、エラーは発生しませんが、デバイスには属性が存在しないため実際の設定変更も行われません。


### 3.61 ファイル日時を取得/設定 (51H)

```text
パラメータ:  C = 51H (_FTIME)
             DE = ドライブ/パス/ファイル名を表すASCIIZ文字列
                  または、ファイル情報（fileinfo）ブロックへのポインタ
             A = 0: 日時の取得 (Get)
                 1: 日時の設定 (Set)
             IX = 新しく設定する時刻値 (A = 1 の場合のみ)
             HL = 新しく設定する日付値 (A = 1 の場合のみ)
結果:        A = エラーコード
             DE = 現在のファイル更新時刻値
             HL = 現在のファイル更新日付値
```

A=1 の場合、DEで指定されたファイルまたはサブディレクトリの最終更新日付と時刻を、指定された値で設定します。文字列パラメータにワイルドカードを含めることはできず、日時を変更できるのは1つのオブジェクトのみです。「CON」などのデバイス名を指定した場合、エラーは発生せず、デバイスの日時が変更されることもありません。

日付と時刻のデータフォーマットは、ディレクトリエントリやファイル情報ブロック内に格納されているものと全く同一です（詳細は「プログラムインターフェース仕様書」を参照）。指定された日時の値がカレンダーとして妥当であるかのチェックは行われず、渡された値がそのままディレクトリエントリに格納されます。ファイル情報ブロックをDEに渡して実行した場合、そのファイル情報ブロック内に格納されている日時情報は自動的には更新されません。

A=0 の場合は、対象のオブジェクトの現在の日時情報が、対応するレジスタに返されます。呼び出しの際に設定時刻を IX レジスタで受け取るのに対し、戻り値の時刻は DE レジスタに返される点に注意してください。ファイルが現在オープンされている場合、日時の読み取り（A=0）は可能ですが、設定変更（A=1）を行おうとすると `.FOPEN` エラーになります。


### 3.62 ファイルハンドルの削除 (52H)

```text
パラメータ:  C = 52H (_HDELETE)
             B = ファイルハンドル番号
結果:        A = エラーコード
```

指定されたファイルハンドルに関連付けられているファイルの実体をディスクから物理的に削除し、同時にそのファイルハンドルをクローズして解放します。対象のファイルに対して、新しく別途オープンされた別のファイルハンドルが現在も開いている場合は、`.FOPEN` エラーが発生して削除は拒否されます。このハンドルから「ハンドルの複製（関数 47h）」や「プロセスのフォーク（関数 60h）」によって作られたコピーハンドルが存在する場合、それらのコピーハンドルはすべて無効（Invalid）としてマークされ、以降それらを使ってアクセスを行おうとすると `.HDEAD` エラーになります。

発生しうるエラー条件や挙動は、「ファイルまたはサブディレクトリの削除（関数 4Dh）」と共通しています。なお、`.FILRO` や `.FOPEN` などのエラーが発生してファイルの実際の削除に失敗した場合であっても、渡されたファイルハンドル（B）自体は必ずクローズされて解放されます。

### 3.71 パス名の解析 (5BH)

```text
パラメータ:  C = 5BH (_PARSE)
             B = ボリュームラベルフラグ (bit 4)
             DE = 解析対象のASCIIZ文字列
結果:        A = エラーコード
             DE = 無効な文字（終端文字）を指すポインタ
             HL = 文字列内の「最後の要素（アイテム）」の開始位置を指すポインタ
             B = 解析結果フラグ (Parse Flags)
             C = 論理ドライブ番号 (1=A:, 2=B:, ...)
```

この関数は、純粋な「文字列処理」関数です。ディスクへのアクセスは一切行わず、ユーザーが渡した文字列の内容を変更することもありません。トランジエントプログラムがコマンドライン引数などの複雑なパスを解析するのを支援します。

Bレジスタのビット4（ボリュームラベルフラグ。属性バイトでボリュームラベルを示すビット位置と同じです）は、文字列を「ドライブ/パス/ファイル」として解析するか（0の場合）、それとも「ドライブ/ボリューム」として解析するか（1の場合）を指定します。

DEレジスタに返されるポインタは、パス文字列として無効な文字が最初に出現した位置を指します（文字列末尾のヌル文字を指すこともあります）。パス文字列としてどのような文字が使用できるか（構文規則）は、「コマンド仕様書」を参照してください。

HLレジスタに返されるポインタは、指定されたパス文字列における「最後の要素（一般的にはファイル名部分）」の最初の文字を指します。例えば、`A:\XYZ\P.Q /F` という文字列を渡した場合、DEはオプションスイッチの前の空白文字を指し、HLはファイル名「P.Q」の「P」の文字を指します。もし解析された文字列の末尾が `\` で終わっているか、ドライブ文字を除いて空である場合、「最後の要素」が存在しないため、HL と DE は同じ文字位置を指すことになります。このような場合、この関数を利用するプログラム側で必要に応じて個別の処理を記述する必要があります。

Cレジスタに返されるドライブ番号は、文字列で明示的に指定された論理ドライブを示します。文字列にドライブの指定（`A:` など）が含まれていなかった場合は、デフォルトドライブの番号が補完されて返されます。したがって、Cレジスタが 0 を返すことはありません。

Bレジスタに返される「解析結果フラグ」は、入力文字列に関する各種の情報をビットごとに示します。ボリュームラベルとして解析した場合（Bレジスタのビット4が 1 だった場合）、フラグのビット1, 4, 5, 6, 7 は常に 0 になります。ファイル名として解析した場合、ビット3から7は、文字列の最後の要素（ファイル名コンポーネント）に関する状態を示します。各ビットの意味は以下の通りです。

```text
b0: 1 = ドライブ名以外の何らかの文字が解析された
b1: 1 = ディレクトリパスが指定されている
b2: 1 = ドライブ名が明示的に指定されている
b3: 1 = 最後の要素にメインファイル名が存在する
b4: 1 = 最後の要素に拡張子が存在する
b5: 1 = 最後の要素にワイルドカード（曖昧な文字）が含まれる
b6: 1 = 最後の要素が "." または ".." である
b7: 1 = 最後の要素が ".." である
```


### 3.72 ファイル名の解析 (5CH)

```text
パラメータ:  C = 5CH (_PFILE)
             DE = 解析対象のASCIIZ文字列
             HL = 11バイトの書き込みバッファを指すポインタ
結果:        A = エラーコード (常に0)
             DE = 無効な文字（終端文字）を指すポインタ
             HL = 保存されます (バッファに解析後の名前が格納されます)
             B = 解析結果フラグ (Parse Flags)
```

この関数は、純粋な「文字列処理」関数です。ディスクへのアクセスは一切行わず、ユーザーが渡した文字列の内容を変更することもありません。主にトランジエントプログラムが、ファイル名などを整形して画面に出力するのを支援します。渡されたASCIIZ文字列を単一のファイル名として解析し、HLで指定された11バイトのバッファに、メイン名8バイト・拡張子3バイトのスペースパディング（余白をスペースで埋めた形式）で展開して格納します。

Bレジスタに返される「解析結果フラグ」は、前述の「パス名の解析（関数 5Bh）」と同じ形式ですが、ビット0, 1, 2 は常に 0 になります。入力文字列に有効なファイル名が含まれていない場合であっても、HLのバッファはすべてスペースで埋められて返されます。入力文字列に含まれる `*`（アスタリスク）は、適切な数の `?` に自動的に展開されます。ファイル名や拡張子の長さがシステムの上限を超えている場合、超過した文字は単に切り捨てられます。

DEレジスタに返されるポインタは、ファイル名として無効な最初の文字を指します（文字列末尾のヌル文字を指すこともあります）。どのような文字がファイル名として有効であるかは、「コマンド仕様書」を参照してください。


### 3.73 文字属性の検査 (5DH)

```text
パラメータ:  C = 5DH (_CHKCHR)
             D = 文字フラグ (Character Flags)
             E = 検査する文字コード
結果:        A = 0 (エラーは発生しません)
             D = 更新された文字フラグ
             E = 検査後の文字 (大文字化された文字)
```

この関数は、マシンの言語設定に依存しない方法で文字を大文字に変換したり、16ビット（マルチバイト）文字の判定を支援したり、ファイル名としての適性を評価したりします。入力および出力される「文字フラグ（Dレジスタ）」のビット割り当ては以下の通りです。

```text
b0: 1 = 大文字化を抑制する
b1: 1 = 16ビット文字の「第1バイト」である
b2: 1 = 16ビット文字の「第2バイト」である
b3: 1 = (ファイル名ではなく) ボリュームラベル名として検証する
b4: 1 = ファイル名/ボリュームラベルとして無効な文字である
b5...b7: 予約領域 (常に0)
```

**ビット0 (大文字化抑制)**
このビットが 0 の場合、渡された文字（E）は、そのマシンの内蔵言語設定ルールに従って大文字に変換されます。このビットが 1 の場合、大文字変換はスキップされ、入力された文字がそのまま返されます。

**ビット1 & 2 (16ビットマルチバイト文字フラグ)**
文字列の先頭文字を検査する際は、これら両方のフラグを 0 に設定してこの関数を呼び出します。関数から戻されたDレジスタのフラグ値を、そのまま次の文字の検査時に引き渡すようにループを構成することで、マルチバイト文字列（日本語漢字コードなど）を安全に走査できます。マルチバイト文字列を逆方向に走査する場合は、これらのフラグの追跡に注意が必要です。

**ビット4 & 3 (名前の無効文字判定)**
戻り値のビット4が 1 の場合、その文字がファイル名（またはボリュームラベル）の終端文字（使用できない文字）であることを示します。ビット3は、ファイル名とボリュームラベルで使用可能な文字セットが異なるため、どちらの規則で検証するかを切り替えるために使用します。なお、16ビット文字のコードの一部（第1・第2バイトいずれも）が、ファイル名やボリュームラベルの終端文字として誤判定されることはありません。


### 3.74 フルパス文字列の取得 (5EH)

```text
パラメータ:  C = 5EH (_WPATH)
             DE = 64バイトの書き込みバッファを指すポインタ
結果:        A = エラーコード
             DE = バッファにフルパス文字列が書き込まれます
             HL = パス文字列内の「最後の要素」を指すポインタ
```

この関数は、内部バッファから、直前の「最初の検索エントリの取得」または「新規エントリの作成・検索」で特定されたオブジェクト（ファイルやサブディレクトリ）の「ルートディレクトリからのフルパスおよびファイル名」を表す ASCIIZ 文字列をユーザーバッファにコピーします。返される文字列には、先頭のドライブ文字、および最初の `\` は含まれません。HLレジスタには、「パス名の解析（関数 5Bh）」と同様に、文字列内の最後の要素（ファイル名など）を指すポインタが返されます。

「最初の検索エントリの取得」などを呼び出す際、DEパラメータにディレクトリではなくファイル情報ブロック（fileinfo）を指定していた場合、この関数は、そのファイル情報ブロックが指すファイルまたはサブディレクトリに対応する正確なフルパス文字列を返します。この対象がサブディレクトリであった場合、その取得したファイル情報ブロックを別の「最初の検索エントリの取得」にDEとして引き渡し、そのサブディレクトリ内のファイルをさらに検索することができます。この場合、新しく見つかったファイルの情報が内部のフルパス情報に追加されるため、続けてこの関数を呼び出すことで、新しく検索されたファイルに対応する正しいフルパス文字列を取得することができます。

この「フルパス文字列」を保持しているシステム内部のバッファは、他の様々な関数を呼び出すことで書き換えられたり無効になったりするため、使用にあたっては注意が必要です。この関数は、関連する「最初の検索エントリの取得」や「新規エントリの作成・検索」を呼び出した直後に、ただちに実行するようにしてください。


### 3.75 ディスクバッファのフラッシュ (5FH)

```text
パラメータ:  C = 5FH (_FLUSH)
             B = ドライブ番号 (0=カレント, FFH=すべてのドライブ)
             D = 00H: フラッシュのみ実行
                 FFH: フラッシュを実行し、キャッシュを無効化 (Invalidate)
結果:        A = エラーコード
```

指定されたドライブ、またはすべてのドライブ（B = FFH の場合）の未書き込みディスクバッファを強制的にディスクに書き出し（フラッシュ）ます。Dレジスタに FFH が指定された場合、書き込みの後に該当ドライブに関連するすべてのメモリキャッシュが無効化（クリア）されます。


### 3.76 子プロセスのフォーク (60H)

```text
パラメータ:  C = 60H (_FORK)
結果:        A = エラーコード
             B = 親プロセスのプロセスID (Parent Process ID)
```

新しい子プロセスが開始されることをシステムに通知します。これは通常、新しいプログラムやサブコマンドが実行される前に呼び出されます。例えば、COMMAND2.COM は、任意の外部コマンドやトランジエントプログラムを実行する前に、必ずこの「フォーク」関数を呼び出します。

この関数を実行すると、子プロセス用に独立した新しいファイルハンドルセットが作成されます。このとき、親プロセス側で「子プロセスへ継承可能」属性ビットがセットされてオープンされていたすべてのファイルハンドルが、子プロセスのハンドルセットにそのまま複製（コピー）されます。この継承可能ビットがクリアされていたハンドルはコピーされず、子プロセス側では使用できません。なお、標準入出力などのシステム標準ハンドル（00h〜05h）はすべて継承可能として開かれているため、常に自動的に子プロセスへと複製されます。

システムは子プロセスに対して新しいユニークなプロセスIDを割り当て、Bレジスタには呼び出し元（親プロセス）のプロセスIDを返します。この親のIDは、後に「親プロセスへの合流（関数 61h）」を呼び出して親プロセスへ処理を戻す際に使用します。ハンドルセットの複製の際、メモリが不足している場合は `.NORAM` エラーが返されます。

子プロセスが受け取るファイルハンドルは、元のハンドルの参照情報を引き継いだ「コピー」であり、元のハンドル実体そのものではありません。そのため、子プロセス側でこれらのハンドル（例えば、標準出力であるハンドル1など）をクローズして別のファイルへ再オープンしても、親プロセスへ戻った際には、親の標準出力は変更されず元の状態でそのまま残ります。


### 3.77 親プロセスへの合流 (61H)

```text
パラメータ:  C = 61H (_JOIN)
             B = 合流先（親）のプロセスID、または 0
結果:        A = エラーコード
             B = 子プロセスから返された主要エラーコード (Primary Error Code)
             C = 子プロセスから返された副次エラーコード (Secondary Error Code)
```

Bレジスタで指定された親プロセスに切り替えて処理を戻し、子プロセスが終了時に返した主要エラーコードをBレジスタに、副次エラーコードをCレジスタに返します。親プロセスと子プロセスの関係は通常1対1ですが、適切な親のプロセスIDを指定することで、複数段の子プロセス階層を一気に飛び越えて呼び出し元に戻ることも可能です。指定されたプロセスIDが無効な場合は `.IPROC` エラーが返されます。

合流時、終了した子プロセスが所有していたファイルハンドルセットはシステムによって自動的にクローズされ、親プロセスのファイルハンドルセットが再びアクティブになります。また、子プロセスが動的に確保していたユーザーRAMセグメントもすべて自動的に解放されます。

呼び出し時に Bレジスタに 0 を指定した場合、システム全体の「部分初期化（再初期化）」が実行されます。開いているすべてのファイルハンドルが強制的にクローズされ、標準入力および標準出力ハンドルが再オープンされ、すべてのユーザー確保セグメントが解放されます。この「0を指定した初期化」は、コマンドインタプリタ自体が不整合な状態に陥る可能性があるため、後にコマンドインタプリタ（COMMAND2.COMなど）へ処理を戻す予定のある通常のユーザープログラムから呼び出すことは推奨されません。

この関数は、実際にファイルハンドルをクローズする（すなわち、ディスクアクセスを伴う可能性がある）処理を行うより前に、メモリの解放やプロセスIDの復元などの重要な切り替え処理を確実に完了させる設計になっています。これにより、バッファ書き出し中に万一ディスクエラーが発生してアボート（中断）した場合でも、親へのプロセス切り替え自体は安全に完了した状態を維持できます。ただし、もし「B = 0」の指定時にディスクエラーが発生して処理が中断された場合、デフォルトファイルハンドルの再オープン処理は完了しません。その場合は、再度「B = 0」でこの関数を呼び出す必要があります（この2回目の呼び出し時は、既にファイルがクローズされているためディスクアクセスは行われず、安全に初期化が成功します）。

なお、この関数を `0F37Dh`（ディスクBASIC環境）経由で呼び出した場合、BおよびCレジスタに子プロセスのエラーコードは返されません。これは、BASIC環境下におけるプログラムの終了やアボート処理はアプリケーション側で独自に制御する必要があるためです。エラーコードが必要な場合は、アボートベクトル等で事前に記録しておく必要があります。終了コードおよび副次エラーコードの意味については、「エラーコードを指定して終了（関数 62h）」を参照してください。


### 3.78 エラーコードを指定して終了 (62H)

```text
パラメータ:  C = 62H (_TERM)
             B = 終了時に報告するエラーコード
結果:        呼び出し元には戻りません
```

指定されたエラーコード（正常終了であれば 0）を伴ってプログラムを終了します。この関数は呼び出し元に戻ることはありません（後述のユーザーアボートルーチン内で強制的に戻る処理を行った場合を除く）。この関数の動作は、MSX-DOS 環境（`00005h` 経由）から呼び出されたか、ディスクBASIC環境（`0F37Dh` 経由）から呼び出されたかによって異なります。

**00005h（MSX-DOS環境）経由の呼び出し:**
「アボート終了ルーチンの定義（関数 63h）」によってユーザー定義のアボートルーチンが登録されている場合、そのアボートルーチンが、指定されたエラーコード（および副次コード 0）をパラメータとして呼び出されます。アボートルーチンが正常に終了してシステムに制御が戻った場合（またはアボートルーチンが登録されていなかった場合）、コントロールはプログラムをロードした親プロセス（通常はアドレス `0000h` のジャンプ先、多くの場合はコマンドインタプリタ）へと戻ります。渡されたエラーコードはシステムに記録され、次の「親プロセスへの合流（関数 61h）」の呼び出し元に引き渡されます。コマンドインタプリタは、終了コードが `20h...FFh` の範囲であれば対応するシステムエラーメッセージを表示し、それ未満の範囲であれば何も表示しません。

**0F37Dh（ディスクBASIC環境）経由の呼び出し:**
処理のコントロールは、アドレス `BREAKVECT` に定義されているアボートベクトルへと直接ジャンプします。BASIC環境下ではユーザーアボートルーチンは定義できないため、合流時（Join）にシステムがエラーコードを仲介して返すことはありません。したがって、必要であれば `BREAKVECT` の先のプログラム側でエラーコードを独自に保存・管理する必要があります。


### 3.79 アボート終了ルーチンの定義 (63H)

```text
パラメータ:  C = 63H (_DEFAB)
             DE = ユーザー定義アボートルーチンの開始アドレス
                  0000H を指定した場合は、登録を解除します
結果:        A = 0 (エラーは発生しません)
```

この関数は、MSX-DOS環境（`00005h` 経由）でのみ利用可能です。ディスクBASIC環境（`0F37Dh` 経由）から呼び出すことはできません。

DEレジスタに 0 以外のアドレスを渡すと、新しくユーザー定義のアボートルーチンが登録されます。0 を渡した場合は登録が解除されます。アボートルーチンは、トランジエントプログラムが（`0000h` への直接ジャンプ以外の理由で）システムを終了しようとする際に、自動的にシステムから呼び出されます。MSX-DOS 2 用に作成するプログラムは、従来の `0000h` へのジャンプではなく、この「エラーコードを指定して終了（関数 62h）」を使って終了するように実装してください。

アボートルーチンは、ユーザーのスタックがアクティブな状態で呼び出されます。IX、IY、および裏レジスタ群は、プログラムが関数呼び出しを行った時点のものがそのまま維持されており、TPA（トランジエントプログラムエリア）の全ページがマッピングされています。終了を引き起こした主要エラーコードがAレジスタに、副次エラーコードがBレジスタに渡されます。アボートルーチンが `RET` 命令で戻った場合、その時AおよびBレジスタに入っている値が、最終的に「親プロセスへの合流」関数へと引き渡される終了エラーコードとなり、コマンドインタプリタに戻った場合はメッセージ出力に使用されます。また、アボートルーチンは、`RET` で戻る代わりに、プログラム内のウォームスタート用アドレスへと直接ジャンプして処理を継続することも可能です。その時点でも、システムは完全に安定した動作状態にあり、すべての MSX-DOS 関数を安全に呼び出すことができます。

アボートルーチンに渡される主要エラーコード（Aレジスタ）は、プログラムが自ら「エラーコードを指定して終了」に渡した値（正常終了なら 0）です。これに加えて、キーボードから Ctrl-C や Ctrl-STOP が検出された場合（`.CTRLC` または `.STOP` エラー）、ディスクエラーに対してユーザーがアボート（中断）を選択した場合（`.ABORT` エラー）、または標準入出力用のシステム関数（01h〜0Bh）での処理中に何らかの通信エラーなどが発生した場合（`.INERR` または `.OUTERR` エラー）にも、このアボートルーチンが自動的に起動します。

`.ABORT`、`.INERR`、`.OUTERR` といったエラーは、システム内部で別の根本原因から派生して発生するエラーです。例えば、`.ABORT` は元々のドライブ未準備（`.NRDY`）などのエラーから派生し、`.INERR` はファイルの終端（`.EOF`）などのエラーから派生します。このような場合、その元々のエラーコード（`.NRDY` や `.EOF` など）が、副次エラーコードとしてBレジスタに格納されてアボートルーチンへと渡されます。それ以外の直接的なエラー終了では、副次エラーは存在しないため Bレジスタは 0 になります。

アボートルーチンから戻る際、単に `RET` を行うのではなく、スタックから戻り先アドレスをPOPして捨てる処理（`POP HL : RET` などと同等の処理）を実行すると、エラーが発生したまさにその MSX-DOS 関数、または BIOS コールの「直後の命令」からプログラムの実行を再開させることができます。これは、後述のディスクエラーハンドラルーチン（関数 64h）と併用することで、ディスクエラーが発生した際に対象のシステムコールの処理のみを局所的にキャンセルしてプログラムを継続させるような制御を実現するのに役立ちます。


### 3.80 ディスクエラーハンドラルーチンの定義 (64H)

```text
パラメータ:  C = 64H (_DEFER)
             DE = ユーザー定義ディスクエラーハンドラの開始アドレス
                  0000H を指定した場合は、登録を解除します
結果:        A = 0 (エラーは発生しません)
```

ディスクエラーが発生した際に呼び出されるユーザー定義の例外処理ルーチンのアドレスを指定します。エラーハンドラルーチンが呼び出される際、TPA（トランジエントプログラムエリア）全体は適切にマッピングされていますが、スタックはページ3にあるシステム固有のスタックがアクティブになっており、MSX-DOS関数が呼び出された時点のレジスタの値などは一切保持されていません。

エラーハンドラルーチン内からさらに MSX-DOS 関数を呼び出すことは可能ですが、多重のエラーによる無限ループ（再帰）を防ぐために細心の注意を払う必要があります。前述の「2. 関数一覧」において、アスタリスク（`*`）が付いている関数は、このディスクエラーハンドラ内から呼び出しても安全な関数です。このルーチンが呼び出される際、標準入出力がディスクファイルにリダイレクトされている場合を考慮し、システムメッセージを画面に確実に表示できるように、リダイレクト状態は一時的に無効化されます（詳細は「リダイレクト状態の取得/設定（関数 70h）」を参照してください）。

エラーハンドラルーチン自体の入力パラメータおよび戻り値の仕様は以下の通りです。IX、IY、および裏レジスタ群を含むすべてのレジスタの内容はルーチン内で変更（破壊）しても構いませんが、システム側のメモリマッピング状態およびスタックの整合性は維持して戻る必要があります。また、このルーチンから、プログラム内の別のアドレスへと直接ジャンプして逃げるような実装は避けてください。処理を中断してプログラムに戻りたい場合は、戻り値として A=1（アボート）を返してください。そうすれば、システムが登録されている前述の「アボートルーチン」を適切に起動させ、そこから任意のプログラム位置へと制御を移すことができます。

**入力パラメータ:**
```text
A = 発生したディスクエラーのエラーコード
B = 物理ドライブ番号
C = 詳細フラグ:
    b0: 1 = 書き込み処理中のエラー (0 = 読み込み処理中)
    b1: 1 = 「無視 (Ignore)」の選択肢を推奨しない
    b2: 1 = 「自動アボート (Auto-abort)」を推奨
    b3: 1 = DEレジスタのセクタ番号が有効である
DE = エラーが発生した論理セクタ番号 (Cのビット3が1の場合のみ有効)
```

**戻り値:**
```text
A = 0: システム標準のエラー処理表示（Aborted/Retry/Ignoreのプロンプト）に処理を委ねる
  = 1: 処理をアボート（中断）する
  = 2: 処理をリトライ（再試行）する
  = 3: エラーを無視して強行する
```


### 3.81 直前のエラーコードの取得 (65H)

```text
パラメータ:  C = 65H (_ERROR)
結果:        A = 0
             B = 直前に失敗した関数呼び出しのエラーコード
```

直前に呼び出されて失敗した MSX-DOS 関数の原因となったエラーコードを返します。この関数は、直接詳細なエラーコードを返さない、古い CP/M 互換（FCB形式）の関数で使用するために提供されています。例えば、FCB形式の「ファイルの作成」を呼び出して A=0FFh（失敗）が返された場合、その失敗原因（ルートディレクトリが満杯になった `.DRFUL` なのか、システムファイル重複による `.SYSX` なのか、など）をこの関数から取得することができます。


### 3.82 エラーコードの解説文字列取得 (66H)

```text
パラメータ:  C = 66H (_EXPLAIN)
             B = 解説を取得したいエラーコード
             DE = 64バイトの書き込みバッファを指すポインタ
結果:        A = 0
             B = 0、または変更なし
             DE = バッファにエラー解説（メッセージ）文字列が格納されます
```

指定されたエラーコードに対応する、人間が読める形式の解説テキスト（ASCIIZ形式）を取得してバッファに書き込みます。古い互換関数からエラー原因を得るには、事前に「直前のエラーコードの取得」を呼び出して実際の原因コードを特定してから、この関数を呼び出す必要があります。

エラーコードとそれぞれに対応する標準メッセージは「プログラムインターフェース仕様書」に一覧化されています。多言語化されたバージョンのシステムでは、対応する言語に翻訳されたテキストが返されます。指定されたエラーコードに対応する標準のメッセージ文字列が存在する場合、それがバッファにコピーされ、Bレジスタには 0 が返されます。システムに登録されていないエラーコードであった場合は、代わりに `System error 194` や `User error 45` といったフォーマットの代用文字列がバッファに書き込まれ、Bレジスタは変更されずにそのまま返されます（エラーコードの 40h...FFh はシステム定義エラー、00h...3Fh はユーザー定義エラーに分類されます）。


### 3.83 ディスクのフォーマット (67H)

```text
パラメータ:  C = 67H (_FORMAT)
             B = 対象ドライブ番号 (0=カレント, 1=A:, 2=B:, ...)
             A = サブコマンド
                 00H: 利用可能なフォーマットの「選択肢文字列」を取得する
                 01H...09H: 指定された選択肢の番号で実際にフォーマットを実行する
                 0AH...FDH: 無効な指定 (エラーになります)
                 FEH, FFH: 新しいブートセクタのみを書き込む
             HL = ディスクドライバ用の作業バッファのアドレス (A = 01H...09H の場合のみ)
             DE = バッファのサイズ (A = 01H...09H の場合のみ)
結果:        A = エラーコード
             B = 選択肢文字列が存在するメモリスロット番号 (A = 00H の場合のみ)
             HL = 選択肢文字列を指すメモリアドレス (A = 00H の場合のみ)
```

この関数はディスクの初期化（フォーマット）を行うためのもので、基本的にはシステム付属の `FORMAT` コマンドが使用することを想定して設計されています。ただし、他のプログラムから十分な注意を払って呼び出すことも可能です。Aレジスタに指定するコードによって3つの異なる処理を実行します。

**A = 00H: 選択肢文字列の取得**
該当するドライブのディスクドライバがサポートしているフォーマット形式の一覧（選択肢文字列。ASCIIZ形式）が格納されている、スロット番号（B）とメモリアドレス（HL）を返します。フォーマットが不可能なデバイス（RAMディスクなど）に対してこの処理を行うと `.IFORM` エラーが返されます。
一般的なフォーマットユーティリティは、返されたスロットとアドレスから文字列を読み出して画面に表示し（例：「1. 1DD / 2. 2DD」など）、ユーザーに入力を促します。そしてユーザーが選んだ番号（1〜9）を、今度は Aレジスタに設定して再度この関数を呼び出すことで、実際の初期化を行います。なお、HLに 0 が返された場合は、そのドライブが1種類のフォーマットしかサポートしておらず、ユーザーに選択を促すプロンプトを表示する必要がないことを意味します。どのような選択肢文字列が返されるかは、ドライブの物理的な仕様やドライバの実装に依存します。

**A = 01H...09H: フォーマットの実行**
指定されたフォーマット番号に基づいて、ドライブのディスクを警告プロンプトなしで即座に初期化します。HLおよびDEレジスタには、ディスクドライバがフォーマット処理中に一時的に使用するための十分な大きさのメモリバッファを指定しておく必要があります。必要なバッファサイズはドライバごとに異なるため、極力大きなサイズを確保して指定することを推奨します。バッファ領域がメモリのページ境界（16KB境界）をまたいでいる場合、システムはドライバへ渡すために、同一ページ内に収まる最大の領域を自動的に選択して引き渡します。多くのディスクドライバはこのバッファを全く使用しません。

**A = FFH または FEH: ブートセクタの更新**
ディスク全体を再初期化（物理フォーマット）するのではなく、MSX-DOS 2 形式に適合する新しいブートセクタのみを書き込みます。これは、古い MSX-DOS 1.0 形式のディスクを、ボリュームIDを付与した完全な MSX-DOS 2 形式のディスクへとアップグレードし、ディスクエラー検知やファイル救出（アンデリート）機能を有効にするために使用されます。
A = FEH の場合もほぼ同様ですが、ブートプログラムコード領域を上書きせずに、ディスクパラメータテーブルとボリュームIDのみを最新の正しい値に更新します。一部の古い MSX-DOS 1.0 環境などで作成された、不適切なブートセクタを持つディスクは、この処理を行って修正するまでは MSX-DOS 2 環境下で正常に認識されないことがあります。

ブートセクタ更新処理（FFH/FEH）は、主にシステム付属の `FIXDISK` ユーティリティが使用することを想定しています。この機能を別のプログラムから使用する場合は、事前に「選択肢文字列の取得（A=0）」を呼び出してエラーが返らないことを確認してください。もし `.IFORM` などのエラーが返るドライブであった場合、それは物理的にフォーマットなどの書き込み操作を行ってはならない（あるいは未対応の）ドライブであることを意味するため、ディスク破壊を防ぐために処理を中止する必要があります。


### 3.84 RAMディスクの作成/削除 (68H)

```text
パラメータ:  C = 68H (_RAMD)
             B = 00H: 現在のRAMディスクを消去する
                 01H...FEH: 指定された数のセグメントで新しくRAMディスクを作成する
                 FFH: 現在のRAMディスクのサイズを取得する
結果:        A = エラーコード
             B = RAMディスクのサイズ (セグメント数)
```

B = FFH の場合、現在RAMディスクに割り当てられている 16KB メモリセグメントの数をBレジスタに返します。戻り値が 0 の場合は、RAMディスクが作成されていないことを示します。

B = 00H の場合、既存のRAMディスクを消去します。この際、RAMディスク内に保存されていたすべてのデータは完全に消失します。最初からRAMディスクが存在していなかった場合は、エラーは発生せず単にそのまま戻ります。

B = 01H...FEH の場合、Bレジスタで指定された数の 16KB メモリセグメントを使用して、新しくRAMディスクを作成します。すでにRAMディスクが作成されている場合は `.RAMDX` エラーが返され、割り当てに利用できる空きメモリセグメントが1つもない場合は `.NORAM` エラーが返されます。指定されたサイズを満たすだけの空きセグメント数が不足している場合は、エラーは発生せず、その時点で利用可能な最大のサイズでRAMディスクが自動的に作成されます。

いずれの場合も、実際に作成（または維持）されたRAMディスクのサイズ（セグメント数）がBレジスタに返されます。なお、RAMディスク内の一部領域は、FAT（ファイルアロケーションテーブル）やルートディレクトリの管理領域としてシステムによって使用されるため、`DIR` や `CHKDSK` などのコマンドが報告する「ユーザーが利用可能な実際のディスク容量」は、ここで割り当てられた総メモリ容量よりも少なくなります。RAMディスクは、システムの物理的なドライブ数に関係なく、常にドライブ文字「H:」として割り当てられます。


### 3.85 セクタバッファの割り当て (69H)

```text
パラメータ:  C = 69H (_BUFFER)
             B = 0: 現在の割り当てバッファ数を取得する
                 0以外: 要求するバッファの数
結果:        A = エラーコード
             B = 現在（または設定後）の割り当てバッファ数
```

B = 0 の場合、現在システムに割り当てられているセクタバッファの総数をBレジスタに返します。

B = 0 以外の場合、セクタバッファの数を指定された値に変更しようと試みます（最小数は常に 2 です）。要求された数だけのバッファ領域を確保できない場合、エラーは発生せず、システムが割り当て可能な最大数が自動的に設定されてその数がBレジスタに返されます。バッファの数は、増やすだけでなく減らすことも可能です。

これらのセクタバッファは、通常の 64KB メモリ空間の外側（マッパーRAM上の専用の 16KB セグメント）に確保されるため、バッファの数を増やしても、トランジエントプログラムが使用できるメモリ容量（TPAのサイズ）が圧迫されることはありません。バッファ数を多く割り当てるほど、ディスクのFATセクタやディレクトリセクタがメモリ上に長くキャッシュされるため、ディスクアクセスの全体的な処理パフォーマンスが向上します。設定可能な最大バッファ数はおよそ20個です。


### 3.86 論理ドライブの割り当て [Assign] (6AH)

```text
パラメータ:  C = 6AH (_ASSIGN)
             B = 論理ドライブ番号 (1=A:, 2=B:, ...)
             D = 物理ドライブ番号 (1=A:, 2=B:, ...)
結果:        A = Error
             D = 物理ドライブ番号
```

システムの「論理ドライブから物理ドライブへの割り当て（マッピング）」機能を制御します。基本的には `ASSIGN` コマンドが使用することを目的としていますが、ユーザープログラムが任意の論理ドライブ番号を実際の物理ドライブ番号へと変換して調べたい場合にも利用できます。

B と D がともに 0 以外の場合、指定された論理ドライブを特定の物理ドライブへマッピングする新しい割り当てを登録します。

B が 0 以外で、D が 0 の場合、その論理ドライブ（B）に対して登録されている個別の割り当てを解除し、元の状態に戻します。

B と D がともに 0 の場合、登録されているすべての論理割り当てを一括して解除します。

B が 0 以外で、D が FFh の場合、その論理ドライブ（B）に現在マッピングされている実際の物理ドライブ番号がDレジスタに返されます（マッピングがなければ元の論理ドライブと同じ番号になります）。

一般的な MSX-DOS 関数呼び出し（文字列内のパス名や、パラメータとしてのドライブ指定）で扱うドライブ番号はすべて「論理ドライブ」です。ただし、前述の「ディスクエラーハンドラルーチン」などにシステムから引き渡されるドライブ番号は「物理ドライブ」であるため、`ASSIGN` コマンドによって割り当てが変更されている場合は、プログラムが認識している論理ドライブ名と一致しない場合がある点に注意してください。


### 3.87 環境変数の取得 (6BH)

```text
パラメータ:  C = 6BH (_GENV)
             HL = 環境変数名を表すASCIIZ文字列
             DE = 値（テキスト）を格納する書き込みバッファを指すポインタ
             B = バッファの最大許容サイズ
結果:        A = エラーコード
             DE = 保存されます (A = 0 の場合、バッファに値文字列が書き込まれます)
```

HLレジスタで指定された名前を持つ環境変数の、現在の値（文字列）を取得してバッファに書き込みます。環境変数名として使用できない無効な文字が含まれている場合は `.IENV` エラーが返されます。該当する名前の環境変数が登録されていない場合は、エラーにはならず、バッファに空の文字列（先頭にヌル文字のみ）が書き込まれます。値が存在する場合、その文字列がバッファにコピーされます。もし用意したバッファのサイズ（B）が格納する文字列よりも小さかった場合、文字列はバッファサイズに合わせて末尾が切り詰められ、終端のヌル文字を伴わない状態で書き込まれ、`.ELONG`（値が長すぎる）エラーが返されます。環境変数の仕様上、値の長さは最大でも 255 文字（終端ヌル文字を含む）を越えることはないため、常に 255 バイトのバッファを用意しておけば安全にすべての値を受け取ることができます。


### 3.88 環境変数の設定 (6CH)

```text
パラメータ:  C = 6CH (_SENV)
             HL = 環境変数名を表すASCIIZ文字列
             DE = 設定する値（テキスト）を表すASCIIZ文字列
結果:        A = エラーコード
```

新しい環境変数を登録、または既存の値を書き換えます。環境変数名として使用できない無効な文字が含まれている場合は `.IENV` エラーが返されます。設定しようとする値の文字列が 255 文字を超えている場合は `.ELONG` エラーが返され、環境変数を格納するためのシステムメモリが不足している場合は `.NORAM` エラーが返されます。すべての条件が満たされた場合、同一の名前を持つ既存の古い環境変数はリストから自動的に削除され、新しく指定された環境変数がリストの先頭に追加されます。DEに空の文字列（ヌル文字のみ）を指定してこの関数を呼び出した場合、該当する名前の環境変数はシステムから削除されます。


### 3.89 環境変数の検索 (6DH)

```text
パラメータ:  C = 6DH (_FENV)
             DE = 環境変数の登録インデックス番号 (1から始まる)
             HL = 環境変数名を格納する書き込みバッファを指すポインタ
結果:        A = エラーコード
             HL = 保存されます (バッファに環境変数名が書き込まれます)
```

現在システムに登録されている環境変数の名前の一覧を走査するために使用します。DEレジスタに指定するインデックス番号（最初の環境変数は DE = 1）に該当する環境変数がシステムに存在する場合、その「名前」の文字列が HL で指定されたバッファにコピーされます。用意したバッファのサイズが名前の文字列より小さかった場合、名前は途中で切り詰められ、終端ヌル文字を伴わない状態でバッファに書き込まれ、`.ELONG` エラーが返されます。名前の長さも最大で 255 文字を越えることはないため、255 バイトのバッファがあれば安全です。指定されたインデックス番号（DE）に対応する環境変数が存在しない（登録総数を超えている）場合は、バッファに空の文字列（ヌル文字のみ）が書き込まれます。環境変数名として空の文字列が登録されることは絶対にないため、空文字列が返ってきた時点でリストの終端に達したと判定できます。


### 3.90 ディスクチェック状態の取得/設定 (6EH)

```text
パラメータ:  C = 6EH (_DSKCHK)
             A = 00H: ディスクチェック設定を取得する (Get)
                 01H: ディスクチェック設定を変更する (Set)
             B = 00H: ディスクチェックを有効にする (A = 01H の場合のみ)
                 FFH: ディスクチェックを無効にする (A = 01H の場合のみ)
結果:        A = エラーコード
             B = 現在（または設定後）のディスクチェック設定値
```

A = 00H の場合、現在のシステム内部のディスクチェック変数の状態をBレジスタに返します。A = 01H の場合、指定された新しい設定値をシステムに登録します。00h は自動チェック有効、FFh は自動チェック無効を示します。デフォルト状態は有効です。

ディスクチェック機能が有効である場合、システムはファイルハンドル、ファイル情報（fileinfo）ブロック、または FCB を介してディスクにアクセスするたびに、毎回ブートセクタ情報を再確認し、途中でディスクが物理的に交換されていないかを検証します。この機能が有効であれば、処理の途中で誤って異なるディスクを挿入したことによるデータの混同やディスク内容の破損を確実に防ぐことができます。この機能を無効にすると、交換の誤検出を防ぐ代わりに、ユーザーが誤ってディスクを引き抜いて別メディアに書き換えてしまった場合に、FATの不整合などによるディスク全体のデータ破損を引き起こす危険性があります。ディスクドライブインターフェースのハードウェア仕様によっては、このチェックの実行に若干の処理オーバーヘッド（アクセスの遅延）が生じることがありますが、多くのディスクインターフェース（ディスク交換をハードウェアレベルで自動検出できるもの）ではパフォーマンスの低下は発生しません。データの安全性を確保するために、原則としてこの機能は常に有効にしておくことを強く推奨します。


### 3.91 MSX-DOS バージョン番号の取得 (6FH)

```text
パラメータ:  C = 6FH (_DOSVER)
結果:        A = エラーコード (常に 0)
             BC = MSX-DOS カーネル (ROM) のバージョン番号
             DE = MSXDOS2.SYS システムファイルのバージョン番号
```

実行中の MSX-DOS の正確なバージョン番号を取得します。ROMに内蔵されている MSX-DOS カーネルのバージョンが BC に、ディスクからロードされた `MSXDOS2.SYS` のバージョンが DE に返されます。これらのバージョン番号は BCD（2進化10進数）形式で表現されており、上位バイトにメジャーバージョン番号、下位バイトに2桁のマイナーバージョン番号が格納されます。例えば、バージョン「2.34」であれば、対応するレジスタの値は `0234h` になります。

従来の MSX-DOS 1.0 環境下などでこの関数を呼び出した場合に互換性を維持するため、プログラム内では常に以下の手順に従ってバージョン番号を評価するようにしてください。

1. まず、戻り値のAレジスタが 0 以外（エラー）であれば、それは MSX-DOS システム自体が起動していないことを意味します。
2. 次に、BCレジスタの B の値を確認します。これが 2 未満である場合、システムは MSX-DOS 2.00 よりも古いバージョン（MSX-DOS 1.0 など）であり、CおよびDEレジスタに返される値は未定義（無効）として無視する必要があります。
3. Bの値が 2 以上であれば、BC および DE の値を上記仕様に従って安全に使用することができます。一般的に、プログラムが要求する特定の DOS 2 機能が利用可能かを検証する場合は、DEレジスタに返される `MSXDOS2.SYS` のバージョンを確認してください。


### 3.92 リダイレクト状態の取得/設定 (70H)

```text
パラメータ:  C = 70H (_REDIR)
             A = 00H: 現在のリダイレクト状態を取得する (Get)
                 01H: リダイレクト状態を強制変更する (Set)
             B = 設定する新しい状態フラグ (A = 01H の場合のみ)
                 b0: 1 = 標準入力をリダイレクトした状態とみなす
                 b1: 1 = 標準出力をリダイレクトした状態とみなす
結果:        A = エラーコード
             B = 変更前（または取得された）リダイレクト状態フラグ
                 b0: 1 = 標準入力が現在リダイレクトされている
                 b1: 1 = 標準出力が現在リダイレクトされている
```

この関数は、主にディスクエラー通知ルーチン（例外ハンドラ）や、標準の入出力リダイレクト設定に関わらず、システムからの警告や出力を「常に実際の物理画面（コンソール）へ直接表示させたい」特殊な処理のために提供されています。

通常、従来の CP/M 互換であるキャラクターI/O関数（01h〜0Bh）はコンソールを対象に動作します。しかし、もしユーザーが標準入力や標準出力（ファイルハンドル 0 および 1）をクローズし、代わりに特定のディスクファイルを同じハンドル番号でオープン（リダイレクト）していた場合、これらのキャラクターI/O関数の入出力先も自動的にそのディスクファイルへと切り替わります。しかし、ディスクの書き込みエラーメッセージなどの致命的な警告は、このようにリダイレクトされているファイル内へ書き込むのではなく、何としても物理的なスクリーンの上に直接表示させる必要があります。

この関数を A = 1, B = 0 で呼び出すと、現在有効になっている一切のリダイレクト状態をシステム内部で一時的に無効化（キャンセル）することができます。これにより、その後に実行されるあらゆる互換キャラクターI/O関数による出力は、確実に物理的な画面へと出力されるようになります。また、呼び出し時の戻り値（Bレジスタ）として「変更前の本来のリダイレクト状態」が返されるため、メッセージ表示などの処理が完了した後に、再びこの関数を使って元のリダイレクト状態へと安全に復元することができます。

なお、このようにリダイレクト状態を一時的に書き換えている間、システムは通常とは異なる不安定な状態にあります。そのため、この関数による強制解除の効力は極めて限定的かつ一時的なものです。この状態のまま、ファイルをオープン、クローズ、あるいはハンドルの複製といった「ファイルハンドル操作を行う任意の関数」を呼び出すと、システムは自動的にリダイレクト状態を本来の正しいマッピング状態へと上書きしてリセットします。したがって、このリダイレクト強制解除を維持したまま、通常のファイル操作を実行することは避けてください。
